# 备份与恢复

知了内置每日自动备份。本文说明备份了什么、放在哪里、以及出问题时如何恢复。

## 备份了什么

| 内容 | 形式 | 位置 |
| --- | --- | --- |
| SQLite 数据库（笔记、主题、标签、设置、对话） | 单文件快照 `app-YYYY-MM-DD.db` | 数据库同级的 `backups/` 目录 |
| 上传的图片（`uploads/` 全目录） | 明文目录 `uploads-YYYY-MM-DD/` | 同上 |

HEIC 图片的 JPEG 展示副本和 HEIC 原件都位于 `uploads/`，因此会一起进入图片快照。恢复时必须恢复整个目录，不能只复制笔记正文引用到的 JPEG。

- 应用启动 5 分钟后做第一次备份，之后每 24 小时一次；也可在 **设置 → 数据 → 立即备份** 手动触发（复用同一逻辑，覆盖当天快照）。
- 数据库快照与图片目录各保留 **最近 7 份**，更早的自动清理。
- 快照文件名中的日期为 **UTC 日期**：北京时间早上 8 点前完成的备份会落在"昨天"的文件名里，属正常现象（以文件修改时间为准）。
- 每日备份**成功后**会顺带执行清扫：彻底删除回收站中满 30 天的笔记，回收无引用的孤儿图片与失效的 AI 会话。先备份后清扫意味着被清掉的数据必然存在于当天快照中；备份失败当天不清扫。
- Docker 部署时备份位于容器内 `/data/db/backups/`；使用 `docker-compose.yml` 默认绑定挂载时，宿主机路径为 `./data/db/backups/`。

## 没备份什么（重要）

- **异地副本**。备份和原始数据在同一块磁盘上，磁盘损坏会一起丢。建议把 `backups/` 目录再同步到网盘或另一台机器（rsync、坚果云、Syncthing 均可）。
- 备份瞬间正在上传的图片可能漏掉当天快照，次日备份会补上。
- **彻底删除的数据只能再找回 7 天**：笔记在回收站保留 30 天，彻底删除（手动或自动清扫）后仅存在于既有备份中，随 7 份轮转陆续消失。想找回时按下文步骤恢复对应日期的快照即可。

## 恢复步骤（Docker 部署）

假设要恢复到 `2026-08-10` 的状态：

1. 停止容器：

   ```bash
   docker compose down
   ```

2. 恢复数据库快照。**关键：必须同时删除残留的 WAL 文件**，否则旧的 `-wal`/`-shm` 会污染恢复后的数据库：

   ```bash
   cd data/db
   rm -f app.db-wal app.db-shm
   cp backups/app-2026-08-10.db app.db
   ```

3. 恢复图片目录：

   ```bash
   rm -rf ../uploads/*
   cp -r backups/uploads-2026-08-10/. ../uploads/
   ```

4. 重新启动。启动时会自动执行数据库迁移与全文索引校验重建，无需额外操作：

   ```bash
   docker compose up -d
   ```

## 恢复步骤（Windows 命名卷）

Windows 上使用 `docker-compose.win.yml`（命名卷）时，数据不在宿主目录里，先用 `docker cp` 取出/放回：

```powershell
# 取出备份到当前目录
docker cp zhiliao:/data/db/backups .

# 恢复：先停容器，再放回文件（示例恢复数据库快照）
docker compose down
docker run --rm -v zhiliao_kb_db:/data/db -v ${PWD}/backups:/restore alpine `
  sh -c "rm -f /data/db/app.db-wal /data/db/app.db-shm && cp /restore/app-2026-08-10.db /data/db/app.db"
docker compose -f docker-compose.yml -f docker-compose.win.yml up -d
```

> 命名卷的实际名称以 `docker volume ls` 为准（前缀取决于项目目录名）。

## 本地开发（npm run dev）

数据默认在项目根的 `./data/` 下，恢复方法与 Docker 绑定挂载一致：停掉 dev 服务 → 删除 `data/db/app.db-wal`、`data/db/app.db-shm` → 用 `data/db/backups/` 里的快照覆盖 `data/db/app.db` → 恢复 `data/uploads/` → 重启。

## 手动触发一次备份

**设置 → 数据 → 立即备份**。与每日自动备份共用同一逻辑：同日多次备份覆盖当天快照，进行中的备份被重复点击时自动合并；完成后页面展示最近备份时间。手动备份不触发回收站清扫。

需要冷备时也可以直接复制 `data/` 整个目录（先停服务，保证 SQLite 文件一致性）。

## 导出与备份的区别

- “立即备份”用于灾难恢复，保存数据库快照及完整 `uploads/` 目录，包括未被导出的内部元数据和 HEIC 原件。
- “导出全部数据”用于迁移或阅读：笔记输出为 Markdown，展示图片位于 `assets/`，被正文引用的 HEIC 原件位于 `assets/originals/`。
