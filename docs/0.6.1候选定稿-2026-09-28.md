## 9 月 28 日输入核对（本机复算）

- 方法：对清单 276 条逐一计算 SHA-256，与当前工作树比对；再用提交差异确认这些输入未被后续提交改动。
- 结果：**275 项 0 处不符**，可由提交 `7d40ee8` 完整复现；该提交相对 `26bd61c` 只改 36 个文件，**没有一项属于候选输入**。
- 例外：`next-env.d.ts`（清单内 276 字节）被 [.gitignore](../.gitignore) 第 32 行排除，从未入库，因此只存在于工作树与构建副本。
  - 其当前内容含 `/// <reference path="./.next-r1-core/types/routes.d.ts" />`，指向本机 R1 隔离目录。
  - 影响范围：`.d.ts` 只参与类型检查、不进 `.next/` 运行时产物，**镜像内的运行时行为不受影响**；但该条输入**无法由提交复现**——干净克隆后由工具链重新生成，内容可能不同（R1 记录也观察到 Next 会改写该文件）。
  - 本轮不修改该文件：任何改动都会改变清单哈希，从而切断已验证的「清单 ↔ 镜像 ↔ run b / run c / run d / 升级回退」证据链。
  - 建议（属门禁 4，待你决定）：重建候选前清理该文件的陈旧 `.next-r1-core` 引用，与镜像一起重新生成清单身份，并重跑依赖旧身份的验收；或在文档中把生成文件明确排除出「可复现输入」。
