| 固定安装输入 | 从固定 RC 引用解析并核对索引 `D`，再按 `ghcr.io/b-tech-hub/zhiliao@sha256:...` 及平台拉取，记录耗时、RepoDigests、image ID 和平台。检查期首尾 RC 标签仍指向 `D`，不是本地刚构建镜像冒烟 |

基础镜像为浮动 `node:22-bookworm-slim`，记录每个平台实际材料，不强求不同架构的子 digest 相等；如同一轮上游版本发生漂移，停止作“统一输入”的结论，先评估影响，不自动改 Dockerfile 或重建。已有构建输出成功但所需证据缺失，同样不能关闭门禁 4。

## 5. 资源、时限与失败停止

以下预算是后续执行建议，尚未获得运行授权。只用标准 GitHub 托管 runner；不启用 larger runner、付费扩容、本机代跑、第三平台或第二次构建。每个平台构建和安装各一次，不新增本机完整门禁或 Docker smoke 重复矩阵。

| 阶段 | 已有硬限制 / 拟用监控边界 |
|---|---|
| F PR CI、M main CI | 各一轮；现有 CI 无显式 job timeout，人工上限各 60 分钟运行、30 分钟排队，不能写成自动硬限时 |
| Release validate | job 15 分钟 |
| build | 每平台 job 60 分钟，构建步骤 45 分钟；合计最多 120 job 分钟 |
| merge | job 15 分钟；imagetools create 子进程 120 秒 |
| install | 每平台 job 15 分钟；pull 300 秒，应用 probe 每次 180 秒，单 HTTP 5 秒；daemon 启动/停止各约 30 秒 |
| GitHub Release | 现有 job 无显式 timeout；拟人工上限 10 分钟，不把它写成已实现的硬限制 |
| 排队与总体 | 任一待调度阶段连续排队最多 30 分钟；R 从 run 创建计总墙钟上限 240 分钟，超限定向取消 |
| 安装资源 | 应用每容器 2 CPU、2 GiB、256 PID；日志 5 MiB × 1；卷/构建磁盘没有业务硬配额，由 runner 可用磁盘约束，不能声称已实现容量门禁 |
| 预算汇总 | R 已限时 jobs 总计 180 分钟，加 Release 人工 10 分钟为 190 runner-job 分钟预算；F/M 两轮额外最多 120 分钟，合计 310，不含排队和归档，计费方式以账户实际规则为准 |

开始前检查账户 Actions/存储额度、两种原生 runner 可用性和可接受成本，记录实际 runner 资源及可用磁盘；不足或无法确认则停止，不自动充值。artifact 保留 30 天，发布日志/构建 record 一并在到期前下载归档，不以 artifact 存在推断测试成功。

每 30–60 秒观察已确认的 run。失败、超时、身份/平台错误、非空匿名存储、鉴权失败、缓存导入、原生模块/持久化/MCP 不符、manifest 缺项、清理失败或证据缺失均停止后续步骤。必要时使用已获准的 `gh run cancel <本次实际run-id> --repo B-tech-hub/zhiliao`，再查询到终态；取消请求不等于已停止，也不保证强制取消时 always 清理/upload 成功。不能取消旧 run，不能自动 rerun、改依赖/源、放宽断言或用单架构通过。

失败可能留下平台 digest、RC 镜像标签、Git tag，甚至在观察延迟时已创建的预发布。逐项记录实际存在状态，不自动删除、覆盖或回滚；缺失 artifact/清理结果记未确认。后续补救、换 RC 编号或包权限变更须形成新范围。任何正式 tag、稳定镜像标签、普通入口切换、Story/Sprint/门禁 5–6 关闭均不由本单自动授权。
