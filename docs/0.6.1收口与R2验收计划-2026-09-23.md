5. **同步文档。** 更新候选表、`docs/releases/v0.6.1.md`、`CHANGELOG.md`、`docs/README.md`、[执行清单](产品规划/开源发布范围与执行清单-2026-09-13.md)；如恢复步骤有修订，同步 `docs/备份与恢复.md`。旧日期的失败记录保留，当前状态单列，避免“已完成”和“尚未开始”混在当前结论中。

预期不需要新增页面、API、表、依赖或迁移。发现会影响数据完整性的产品缺陷时，先给出证据和修复范围，再决定是否纳入候选，不顺手扩展本次实现。

## 4. R2 隔离设计与验收矩阵（待运行批准）

建议采用 Windows Docker Desktop 的本地 `linux/amd64` 候选。准备包完成后先固定源码，再选择或构建与该输入完全匹配的镜像，记录身份；历史 R1 镜像不能仅凭版本号相同直接复用。独立 Linux、arm64 和无缓存分发仍是后续发布验收。

使用三个互相独立的实例角色：合成数据源、ZIP 空库导入目标、完整快照恢复目标。每轮采用未占用的唯一 project 名，各自三份独立数据卷和独立凭据。建议界面端口为回环 3311/3312/3313，执行前检查占用；不套用主 Compose 的固定容器名和 `./data/notes` 挂载。恢复准备阶段无网络、不发布端口、源包只读；界面阶段另行确认网络配置。

只用合成笔记和可再分发图片，真实模型预算为 **0**，不复制宿主 `.env*` 或正式库。普通模式不设置 `DEMO_MODE`，避免备份/导入被 403 拒绝。关闭合成库的每周回顾等自动任务，确保五组模型配置没有外部凭据；会话内容使用标明来源的固定测试记录，仅验证持久化读取，不宣称真实回答效果。隔离恢复库启动仍会迁移和运行 worker，因此启动前后分别留证。

建议数据包含长短正文、中文与特殊字符标题、主题、标签、摘要、固定时间戳、锁字段、回收站笔记、已结束会话及来源、普通 PNG/JPEG、内嵌 `<img>` 属性和真实 HEIC/JPEG 配对。源库在手动备份期间保持无编辑、上传和后台写入。

| 通道 | 验收操作 | 通过标准 |
|---|---|---|
| 增量 Markdown | 新建、改标题/主题、改正文、回收站恢复后核对真实文件 | 正文和 frontmatter 符合现有导出规则，旧路径清理，异步完成可观察；新增/改动后有实际文件。现有实现只写 Markdown，不能宣称已复制完整图片或恢复时自动回填全库 |
| ZIP 往返 | 从源实例导出，导入空目标，再导同包一次 | 按契约核对 id、标题、主题名、标签、时间、摘要、正文；图片改名后的 URL 按映射比对，字节哈希一致；HEIC 原件成对保留。第二次新增笔记和图片均为 0，默认不触发 AI；回收站、会话和内部状态不属于 ZIP 还原范围 |
| 配对快照恢复 | 通过产品备份入口生成数据库及完整 uploads，固化包后只读复制到空目标 | SQLite `integrity_check` 通过，图片全清单及哈希一致；启动前核对数据库业务状态，启动后核对正文、主题/标签、图片、会话/来源可读和关键词搜索。只见 healthz 或最近备份时间不算通过 |
| 持久化与保护 | 目标中新建专用笔记，重启后核对；复核源包及资源 | 目标正文、图片、写权限和 Markdown 正常；源包哈希不变，正式实例资源未动。记录耗时、失败点；失败只停本轮实例，保留源包和目标，不自动删卷 |

快照来自哪个版本，就先用对应镜像恢复。0.6.0 → 0.6.1 的升级与升级失败回退仍需另一次隔离彩排，不能用“0.6.1 备份再恢复到 0.6.1”替代。

R2 运行前可复用 `tests/lib/{markdown-export,export,import,backup}.test.ts` 与 `tests/api/import.test.ts`。这些单元测试不是整库恢复证据；不修改其模块时，不为准备文档无条件重跑全部文件。若 R2 实测发现缺陷，再按修改范围补回归。

## 6. 风险、未知项与退出标准

- **候选身份尚未固定。** 当前 HEAD 加未提交改动才是待收口对象；最终提交和镜像 ID/digest 在准备完成、运行确认时填入实际值，不用占位值启动。
- **真实 HEIC 样本已补齐，容器实测仍待执行。** 生成了无用户内容的 96×64 几何图，原件、PNG、生成方法与哈希见[样本说明](验收证据/0.6.1-baseline-2026-09-23/r2/fixtures/README.md)。宿主现有解码器已转成 JPEG；这不替代容器上传转换与恢复。
- **备份不是原子联合快照。** `src/lib/backup.ts` 先备数据库再拷图片，缺 uploads 时仍可能成功。按手册静止源写入、逐项核对配对；缺图或不完整配对直接判失败，不通过补空目录掩盖。
- **ZIP 会跳过磁盘缺图。** `src/lib/export.ts` 过滤不存在的资源，HTTP 200 不能证明图片完整；验收必须以源引用清单对照包内清单。
- **规模结论有限。** 小规模功能恢复不证明 2,000/5,000 篇性能；若修复涉及批量路径，再安排对应规模验证。已知全目录扫描性能问题保留。
- **同盘隔离不是异地备份。** 本地验收只证明恢复链路；异地副本与实际目标环境不记为已通过。

准备阶段退出条件：候选范围和待提交文件清楚，B1 有实际审查与局部证据，R1 组合证据与最终差异关联，清理完成，R2 准备包有可审核的资源、样本、命令和判据。此时仅可称“候选收口、R2 待执行”；R2 通过必须另外取得上述实测证据，0.6.1 发布还需原门禁和发布操作。


准备阶段当前结论：候选输入已经固定，B1 和最终补丁局部证据补齐。2026-09-24 复核修正了操作单在 Windows PowerShell 5.1 下截获 `-d`/`-e`、缺少就绪等待的问题，并补上改正文、正式实例快照和构建前清单核对；桩函数干跑与准备脚本试跑通过，见[证据索引](验收证据/0.6.1-baseline-2026-09-23/README.md)。审查通过后已在本地分支 `candidate/0.6.1-baseline` 按六组提交，未推送、未打 tag；R2 运行与发布门禁待确认。前文调查表保留为当时发现。
