# 0011. 图像生成：只做同步接口，用张数封顶替代确认卡片

日期：2026-08-16
状态：已采纳

## 背景

v0.5 要给助手加画图能力（README Roadmap 已公开承诺）。这件事有三个各自独立的取舍：接哪种供应商接口、要不要在花钱前问一句、生成的图怎么进笔记。

图像生成与项目已有的全部工具都不同：**它不可撤销，且每次调用直接产生费用**。撤销机制（[0008](0008-assistant-tool-calling.md)）在这里失效——图片文件可以删，那次调用的钱撤不回来。

## 决策

**一、只做 OpenAI 兼容的同步接口。**
`POST {base}/images/generations`，`url` 与 `b64_json` 两种返回形态都当场取字节落盘。DashScope 那类「提交任务 → 轮询 task_id → 下载」的异步适配砍掉：手上没有可实测的 Key，而没真验过的适配器不该发。健康检查在四个版本里一直是 unhealthy（v0.3.1 才修）就是因为它从没被真正验证过一次。README Roadmap 原先写的「双适配」同步改掉，不留下已宣传未兑现的表述。

**二、不设确认卡片，改用每条用户消息最多 2 张。**
「仅删除需确认」是产品不变量（[0008](0008-assistant-tool-calling.md)）：确认弹得越多，用户越是闭眼点「允许」，真正危险的那次也一起放行了。生图不破坏任何数据，不该挤进这条窄门。防线改成硬额度：**每条用户消息最多 2 次 `generate_image`，失败也计数**。轮次上限（8 轮）与单轮调用数上限（20）都管不住跨轮累积——被提示注入策反的模型可以分八轮每轮画几张，用户看到的是一串卡片和一张账单。失败计数是关键：不计的话「画失败了再试一次」就是无限重试的绕过口。

**三、图片进笔记走双路：卡片按钮 + 模型自己调 `append_to_note`。**
生成卡片提供「插入当前笔记」（有笔记附件时）与「存为新笔记」；模型也可以自行调既有的追加工具，那条路自动获得操作卡片与撤销。落盘复用上传的 `saveImage` 入口与 `images` 表，不开第二条写入路径——孤儿图片清扫（[0007](0007-soft-delete-trash.md)）的判定与 24 小时宽限期因此原样适用。

**四、来源问答中禁用。**
与 `fetch_url` 同置于禁用名单：图是模型自有知识的产物，不可能出自来源集。执行层二次校验，模型硬调也会被拒。想在接地会话里画结构图，用本版新增的 mermaid（纯文本、可验证出自来源）。

## 备选方案与否决理由

1. **生图前弹确认卡片**：直觉上「花钱的操作该问一句」，但会稀释确认的信号强度，且用户此刻的意图本来就是「画图」——问的是他刚说过的话。
2. **给账户设总额度上限**：需要记账与配额 UI，且真实费用取决于供应商定价与分辨率，本地算不准。按消息封顶不精确但够用。
3. **只存图片 URL 不落盘**：省磁盘，但各家图床地址普遍一小时内失效，笔记里的图过一阵全变裂图。图片是笔记内容的一部分，必须自己持有。
4. **图片类型信任响应的 `Content-Type`**：实测中它并不总是准确。改为按魔数嗅探字节，与上传路径同一套判定。
5. **未配置图像模型时仍注册工具**：模型照调不误，收到「未配置」错误后还要多花一轮向用户道歉，而用户根本没提过画图。改为按配置门控注册。

## 后果

- **测试连接会真实计费一次。** 设置页的「测试连接」真生成一张最小尺寸图，按钮旁必须写明这一点——这是三组配置里唯一一个点了就花钱的按钮。
- **张数封顶是提示注入的直接防线，必须随提示注入重测一起验。** 「诱导连续生图」是烧钱型攻击，与数据破坏型攻击同等重要。
- **生成卡片没有撤销按钮。** 这是有意的：撤销意味着「当作没发生过」，而钱已经花了。未被引用的图由 24 小时宽限期后的孤儿清扫自然回收。
- **demo/mock 动线不受影响。** 体验模式不配图像模型，工具不注册，mock LLM 里补的生图分支只在显式配置后才走到。
- **只验过假端点的部分要在发版前补真实 Key 的端到端。** 本轮用仓库外的本地假端点（返回 `b64_json` PNG）验证了全链路，真实供应商调通留在发版前——这正是第一条决策要避免的那种「没真验过就发」。
