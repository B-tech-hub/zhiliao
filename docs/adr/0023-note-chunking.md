# ADR 0023：长笔记分块与 max-pooling 检索

状态：已接受（2026-08-27）

## 背景

ADR 0018 把分块列为「后续独立议题」，理由写在它自己的后果一节：长笔记的单一向量会稀释语义、末尾内容召回率偏低。除稀释外还有一层更硬的损失——`buildNoteEmbeddingText` 截断在 5000 字，超出部分**根本没有进过向量**。

## 决策

1. 新增 `note_chunks` 表，向量粒度从「一条笔记一个」改为「一条笔记多块」。**只有切出多块的笔记在此占行**，单块笔记继续走 `notes.embedding`——绝大多数笔记不产生额外行，也不推翻 T0 已实测通过的路径。
2. 切分优先按 Markdown 标题分节，超长节按空行段落再切，无结构可依时按字数硬切。上限 1000 字、下限 200 字、单笔记封顶 20 块。超出块数上限时**合并最短的相邻对而非丢弃尾部**——末尾内容进不了向量正是本 ADR 要解决的问题。
3. **笔记标题随每块重复注入，摘要不注入。** 标题提供「这块属于哪条笔记」的上下文；摘要是整篇概括，注入每块会让所有块彼此靠近、抹平块间差异，等于白分块。
4. 检索时同时扫两处，按 `note_id` 取该笔记所有块的**最高分**（max-pooling，不做平均——平均会让长笔记再次被稀释）。
5. `notes.embedding_chunk_count` 作为「向量落在哪一侧」的权威标记：NULL/0/1 表示单块、>=2 表示多块。不用「embedding 为空但 model 非空」这类隐式约定。
6. 写入时两侧严格互斥：转多块要清空 `notes.embedding`，转单块要删掉全部旧块。
7. `note_chunks.note_id` 外键 `ON DELETE CASCADE`，孤儿块由数据库兜底。
8. `chunk_count IS NULL` 一律计入待补算，触发一次全量回填。
9. 一条笔记的所有块合并成**一次** embedding 请求（`embedTexts` 批量上限 64，块数封顶 20）。
10. 陈旧判定沿用 ADR 0018 的模型名 + 维度双条件，但**按笔记计一次而非按块累加**。

## 取舍

第 5 条那一列是为了避免一类静默错误：笔记从长改短后若两侧都留有向量，同一条笔记会在 max-pooling 里拿两个分。显式一列的代价只是一个可空字段，换来的是写入互斥可被测试断言。

第 8 条容易被忽略但决定功能是否真正生效：升级后存量向量的模型名与正文版本都对得上，若不特殊处理，worker 的幂等检查会直接跳过，**存量长笔记将永远吃不到分块**，除非正文恰好被改过。代价是升级后设置页会一次性显示一批「过期」，故在补算入口旁增加了说明文案。

第 9 条推翻了计划中「请求量随块数倍增」的风险判断：批量能力早已存在，请求次数仍是每条笔记一次，增加的只有 token。

## 后果

分块把长笔记末尾内容的召回从「被截断掉」变成「独立成块可检索」。真实供应商实测（11 条笔记、Qwen3-Embedding-4B/2560 维，详见开发日志 T1 一节）：指向 5000 字截断线之后内容的两个查询，相似度由 0.3397/0.5702 升到 0.4439/0.6345；T0 的十条基准样本位次不退化，向量侧得分 6 升 4 降，降幅均在 0.015 以内。

**「标题是否随每块注入」由实测定案，而非推断。** 不注入时末尾召回得分更高（0.5528 vs 0.4469），但 T0 刻意埋设的干扰对上失手——「考研数学分值」被「六级分值」压过，Top1 由 10/10 掉到 9/10。块脱离标题后只剩「分值与时间分配」的共性内容，丢失了学科上下文。**跨笔记区分度比单块纯度更重要**，故采用注入。

一处必须记住的归因纠正：计划把「T0 第 8 条（长篇学习路线）从第 3 上升」列为分块有效性的直接判据，**这个归因是错的**。实测显示该条在纯向量侧一直是 Top1，分块后得分还涨了 0.0756，但它在混合检索里排第 3 是 BM25 经 RRF 融合拖下来的，与向量稀释无关。分块解决不了它。

由此得到一条方法论：**验收分块必须直接测 `vectorSearch`，不能测 `hybridSearchNoteIds`。** 混合检索里 BM25 索引全文、不受 5000 字截断影响，末尾查询它照样命中——首轮验收因此让对照组也拿到 2/2 Top1，测出的是「系统鲁棒」而非「分块有效」。

尚未验证的一项：本轮 11 条样本全部切出多块，因此「单块短笔记与多块长笔记同场竞争时是否吃亏」只有单元测试覆盖，没有真实数据佐证。
