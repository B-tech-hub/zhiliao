# 0016. 手写共享正文排版层，不装 typography 插件

日期：2026-08-18
状态：已采纳

## 背景

用户反馈「笔记界面太难看」「AI 回答的界面太小」。排查后发现两者是同一个根因，而且与配色、圆角、字体这些设计选择无关。

`globals.css` 第一行是 `@import "tailwindcss"`，Tailwind v4 默认带 Preflight，它会把 `p / h1-h6 / ul / ol / blockquote / figure` 的 margin **全部清零**。项目从未把它们补回来——既没装 `@tailwindcss/typography`，`globals.css` 里也没有 `@layer base` 重设间距。

而笔记编辑器里那串排版类（`markdown-editor.tsx` 的 `editorProps.attributes.class`）只写了字号、字重与列表符号：

```
[&_h1]:text-[28px] [&_h1]:font-semibold [&_h2]:text-[21px] …
[&_ul]:list-disc [&_ul]:pl-5 [&_ol]:list-decimal [&_ol]:pl-5 …
```

**一条 margin 都没有。** 结果是段落与段落零间距、标题只是「变大变粗的一行字」紧贴前一段、列表项挤成一列、`pre` 有底色却没有等宽字体。加上 `max-w-none` 与笔记详情页的 1440px 画布，正文行宽能拉到 900px 以上，一行 60 多个中文字。

助手回答更彻底：`whitespace-pre-wrap` 纯文本，连字号字重都没有，标题、列表、表格、代码块统统是裸字符，塞在 85% 宽的圆角气泡里。

所以「难看」不是设计语言选错了——`docs/DESIGN.md` 那套 Apple token 本身没问题——而是**从来没有过 rhythm 层**。

## 决策

**一、新增一个共享的 `.prose-note`，放在 `@layer components`。**

它是笔记编辑器与助手回答**唯一**的正文排版来源。此前编辑器有一套（残缺的）、聊天没有；各写一份的必然结局是漂移成两种排版。共用一个类，改一处四处齐动（编辑态、阅读态、笔记、助手）。

颜色、圆角、字体一律 `var(--color-*)` 取既有 token，不引入任何新的设计决策——因此暗色自动跟随，不需要第二套值（与 [0005](0005-dark-mode-class-next-themes.md) 的策略一致）。

**二、不装 `@tailwindcss/typography`。**

这是主要的备选方案，也是最容易的那个。否决理由：它自带一整套**完整的**字号、颜色、行高、间距体系（`--tw-prose-body`、`--tw-prose-headings` 等十几个变量），与 `docs/DESIGN.md` 的 Apple token 是两套独立的设计语言。要让它服从本项目的 token，需要覆写的变量比这里手写的规则还多，而且每次升级插件都可能被新的默认值反噬。本项目的排版需求就是「补回 Preflight 清掉的那部分」，不需要一整套预设审美。

其余被否决的：

- **在 `@layer base` 里全局重设 `p / h1` 的 margin**：会波及每一个页面——设置页的表单说明、会话列表、主题卡里的文字全都跟着变宽松，而那些地方要的恰恰是紧凑。排版应当作用于「正文块」，不是整个应用。
- **继续用行内 arbitrary variant**（`[&_p]:my-3` 这种）：能写，但一行长到不可读，且没法在两个组件间共享，正是当前问题的成因。

**三、行宽上限 `40em`，写在共享类里而非某个页面。**

40em 在 17px 下约 680px，中文约 40 字/行。写进共享类是安全的：助手面板本就窄于此，该值在那边自然不生效；只有宽屏笔记会被它约束。`em` 而非 `px` 意味着字号变了行宽跟着变，测量单位始终是「多少个字」。

## 后果

- **笔记详情页的编辑区不再占满卡片宽度**，右侧出现留白。这是有意的；点击留白仍会聚焦编辑器（外层 `onClick` 已有）。
- **助手回答需要一个 Markdown 渲染器**，项目此前没有（TipTap 是编辑器，不能当只读渲染器用）。新增 `react-markdown` + `remark-gfm` 两个依赖，是本次唯一的依赖变更。**不启用 `rehype-raw`**：模型输出是不可信内容，原始 HTML 一律当纯文本，杜绝注入。笔记里的内嵌 `<img>`（[0002](0002-image-attrs-inline-html.md)）走 TipTap，与这条路径无关。
- **引用溯源必须在解析前预处理。** `[^noteId]` 正是 GFM 的脚注语法，直接喂给 `remark-gfm` 会被当成脚注引用吞掉。改为先用既有的白名单判定把它转成标准 Markdown 链接 `[[n]](/notes/id)`，再交给渲染器；模型编造的 id 保持纯文本这条不变量不变。
- **补上排版后，笔记详情页一个既有的布局缺陷显形了**：编辑器外层 `<div className="min-w-0 flex-1">` 不是 flex 容器，`MarkdownEditor` 根节点的 `flex-1 min-h-0` 因此失效，高度长成内容高度。此前正文没间距、够短，撑不出来；间距补上后正文溢出卡片、压住底部标签行。一并修掉。
- 首屏体积增加约 40KB（gzip），只在加载助手面板时付出。
