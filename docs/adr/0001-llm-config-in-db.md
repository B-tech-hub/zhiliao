# 0001. LLM 配置存数据库，环境变量兜底

日期：2026-08-11
状态：已采纳

## 背景

LLM 配置（`LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`）原先只能通过环境变量设置，修改需要进入服务器编辑 `.env` 并重启服务。用户希望在应用设置页直接修改 key 和切换供应商。

## 决策

新增 `settings` 键值表存放 LLM 配置。读取时**数据库优先、环境变量兜底**（逐字段合并，而非整组覆盖）。`LLM_TIMEOUT_MS` 属冷门项，仍仅支持环境变量。每次 LLM 调用现读数据库、不做进程内缓存。

## 备选方案与否决理由

1. **保存时写回 `.env` 文件**：Docker / standalone 部署下 `.env` 可能不可写、容器重建即丢失，且修改后仍需重启进程才生效。否决。
2. **仅运行时内存覆盖**：实现最简单，但重启即丢失，每次都要重新填写。否决。

## 权衡

- API Key 明文存入 SQLite，与 `.env` 明文同一安全级别（单用户应用、数据目录受文件权限保护、修改接口受登录会话保护），可接受。
- 配置出现两个来源，通过设置页展示每个字段的来源徽标（数据库/环境变量）与"清除数据库配置回退环境变量"入口来消除歧义。

## 后果

- 设置页保存后立即生效，无需重启；AI worker 与 API 路由同进程共享连接，天然读到最新值。
- better-sqlite3 同步查询主键的开销为微秒级，相比数十秒级的 LLM 网络请求可忽略，因此不缓存。
- 数据库备份（每日自动）现在也包含 LLM 配置。
