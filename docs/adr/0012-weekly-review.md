# 0012. 每周回顾：产物是普通笔记，调度靠每小时对表

日期：2026-08-16
状态：已采纳

## 背景

知识库攒到几百条之后，单条笔记还在，脉络却没了：这周到底在想什么、哪条线索值得接着走，用户自己翻不出来。每周回顾就是补这一层——把上一自然周的笔记交给模型梳理成一篇。

两个非显然的问题：**产物放在哪里**，以及**在没有日历定时器的前提下怎么按周触发**。项目现有的调度基础设施只有「启动后每 24 小时跑一次」的 interval（每日备份），它对不齐「周一凌晨」这种日历时刻。

## 决策

**一、产物是一条普通笔记，归入自动创建的普通主题「每周回顾」。**
不新建实体、不做独立页面：回顾天然就是一篇笔记——可搜索、可编辑、可导出、可当作来源提问，全部能力白赚。主题 id 存在 settings 里而非按名字查：用户改名照用（id 不变），删掉才在下次生成时重建；若此时已存在同名主题（用户手建过）则直接沿用，避免撞唯一约束。建的是普通主题（`isSystem = 0`），用户不想要随时可删，与「未分类不可删」区分开。

产物笔记 `aiStatus = 'skipped'` 且 topic/title 双锁：它不该再被 AI 流水线整理一遍——标题与归属这里已经定好，而一旦用户编辑回顾正文触发重新入队，AI 会把它改名挪走。

**二、调度是「对表」，不是定时器。**
settings 记录**已安排生成的周**（上周一的本地日期，如 `2026-08-10`），每小时比对一次：算出当前的上一自然周，与记录不同就入队。这样重启安全、错过自动补——服务器周一停机、周三开机，开机后一小时内照样补出上周的回顾。

**入队即写这个 key，而不是等生成成功再写。** 失败重试交给 worker 已有的三次退避；如果按「成功才记」，一个必然失败的周（比如模型配置错了）会变成每小时入队一次的**真实付费死循环**。彻底失败后由设置页的「立即生成上周回顾」手动补。

**三、输入是标题 + 标签 + 摘要，不是全文。**
一周几十条笔记的全文轻松超出上下文，而 AI 流水线已经为每条长笔记写过摘要——回顾要的正是这种概览粒度。无摘要的短笔记取正文开头 120 字，单次上限 100 条。

**四、空周不产报告。** 一条「本周你什么都没记」的笔记只是垃圾。

## 备选方案与否决理由

1. **产物做成独立的「回顾」实体 + 专属页面**：多一张表、一套 UI 与生命周期问题，换来的能力笔记全都已经有了。
2. **主题按名字查而非存 id**：用户把「每周回顾」改成「周报」后就会凭空多出一个新主题，两边各存一半。
3. **用 cron 表达式库做真正的日历调度**：多一个依赖，且仍要解决「停机期间错过怎么办」——对表天然覆盖补偿，是更简单的解。
4. **生成成功后才记录已生成周**：见上，会制造按小时计费的失败循环。
5. **失败后自动降级为下周合并生成**：语义复杂（回顾区间会变成两周），用户也未必想要。手动按钮足够。
6. **UTC 分周**：容器默认 UTC，北京时间周一凌晨 8 点前的笔记会被算进上一周。改为服务器本地时间，容器需显式设 `TZ`（README 与部署手册已注明）。这是取舍不是完美解——跨时区旅行时周界会跟着服务器走。

## 后果

- **周界必须按任务的入队时刻算，不能在执行时现算。** 首次实测就踩到了：周日入队的任务因当时未配 LLM 一直延后，周一才跑起来，于是算出的「上一周」已经换了一周——原定那周（对表已记成「已安排」）永远补不回来，而新一周反倒生成了两篇。任务从入队到执行之间隔着停机、退避重试与「LLM 未配置」延后，跨周是常态而非例外。修法是 worker 传 `new Date(job.createdAt)`；这也意味着**任何「入队时确定、执行时才用」的参数都不能靠执行时现算**。
- **`aiJobs.type` 新增取值必须过一遍全部读点。** 本次同时给 worker 的任务分发加了**显式的未知类型分支**：此前未知 type 会被静默标成 done，新增类型忘了接线将永远查不出来。现在抛错走通用重试，三次后落 failed，在设置页「最近失败」里看得见。
- **`weekly_review` 任务没有 `noteId`。** 回收站清扫按 `noteId IN (...)` 删任务，对 null 天然不匹配，无需改动——但后续任何按 noteId 遍历任务的代码都要考虑这一类。
- **手动按钮无视已安排周，只防并发重复。** 连点两次会得到两篇同一周的回顾，这是可接受的：明确的手动动作不该被静默吞掉，多出来的一篇用户删掉即可。
- **产物笔记的双锁是「AI 不覆盖用户内容」这条规则的延伸**，但锁的对象是 AI 自己的产物。若将来放开「回顾可被重新整理」，双锁要一并重新评估。
- **时区依赖部署配置。** 容器不设 `TZ` 时按 UTC 分周，对中国用户意味着周界偏移 8 小时。这不影响功能正确性，但会让「上周」的边界与直觉不符。
