# ADR 0025：四项非核心功能默认关闭

状态：已接受（2026-08-28）

## 背景

2026-08-21 那轮意图梳理 §5 已经判定：AI 生图、Mermaid、手写摄取、深度思考在任何一个未来象限里都不改变胜负。一周过去，四项一个都没关，各自仍在默认界面上占着一个入口。

同一天定下的北极星指标是**真实笔记数**（见 README Roadmap 的冻结声明）。实测基线是正式库 7 条真实笔记、15 天 98 次提交——功能一直在长，用的人没有。新用户打开应用，第一屏要面对的东西越多，「随手记一条」这件唯一要紧的事就越不显眼。

这份 ADR 记录把四项从默认体验里挪出去的取舍。**这不是删除**：功能、数据与代码全部保留，只是不再默认出现。

## 决策

1. **默认关闭，不是删除。** 四项各有一个 `settings` 表里的开关，设置页可逐项开启，开启后立即可用。已经产生的转写、插图、Mermaid 代码块与思考过程照常显示、编辑与导出——用户为它们付出过的成本不因一次默认值调整而作废。

2. **读取语义只认 `"1"`，与 `isCorrectionLearningEnabled` 方向相反。** 「纠正即学习」判的是 `value !== "0"`，即**无记录时默认开启**；四项新开关判 `value === "1"`，无记录时默认关闭。同一张 `settings` 表里并存两种相反的默认语义是有风险的，照抄先例会让四项在空库上全部默认打开、与本 ADR 的目的正好相反。已用一条对照测试把这个坑钉死。

3. **新开关是「模型是否已配置」之上的一层，两者是「与」。** 生图与深度思考在本次改动之前就受各自模型配置的约束。合成写成 `isImageGenAvailable(db)` / `isReasoningAvailable(db)` 两个显式函数，而不是在每个调用点各写一遍 `configured && enabled`：两个 chat 路由加 layout 一共三处要问同一个问题，各写各的迟早漏一处。四种组合的真值表已固化为测试。

4. **关闭态是「入口不渲染」，不是「变灰」；但「已开启却没配模型」仍然变灰。** 这两种状态语义不同：前者是用户不想要，后者是用户想要但还没配好。深度思考此前只有后一种表现（显示「深度思考（未配置）」并禁用），那是修过的缺陷——按钮亮着却点了没反应，用户只会以为功能坏了。因此保留两种表现，`reasoningEnabled` 控制渲染，`reasoningAvailable` 控制可点。

5. **Mermaid 关闭时退回 StarterKit 自带的代码块。** 开启时用带 NodeView 的 `MermaidCodeBlock` 替换掉同名的内置扩展，关闭时反过来。两者 schema 与输入规则完全一致，所以已存在的 ```mermaid 块降级成普通代码块：照常显示源码、照常存回 Markdown，不出图，也不报错、不丢内容。

6. **界面藏了，服务端也必须拦。** 只改前端等于没关：
   - `/api/handwriting` 在关闭时返回 403，且这一判断排在「图片是否存在」之前。这条路径会先建一条笔记再排队转写，绕过界面直接打过来就会在库里留下一条只有原图的笔记，等一个永远不会跑的转写。
   - 关闭生图时不把 `generate_image` 下发给模型（沿用「没配图像模型就不下发」的既有理由：发了模型照调不误，用户会收到一张自己从没要求过的失败卡片）。
   - 关闭深度思考时服务端不启用推理模型，前端即使发来 `useReasoning: true` 也不生效。

7. **系统提示词按开关裁剪绘图指引。** Mermaid 关闭后，助手也不再被告知「可以用 mermaid 代码块画图」。留着的后果是：编辑器已经不渲染了，模型还往笔记里写图表源码——用户没开这个功能，却先收到了它的半成品。

8. **手写摄取的转写审核 UI 不隐藏。** 只隐藏产生新转写的上传入口。已经处于「待核对」状态的笔记仍然显示核对提示与「标记已核对」按钮，否则那些笔记会永久卡在中间状态，用户没有任何办法给它们收尾。同理，公式渲染（`math.ts`）属于转写的配套显示层，一并保留。

## 取舍

**最大的代价：新用户不打开设置页，就不知道这四项功能存在。** 这是「彻底隐藏」相对于「变灰并标注」主动接受的代价。选它是因为变灰几乎不降低第一屏的认知负担——一个灰着的按钮仍然要被看见、被读懂、被判断要不要点，而降噪正是本次改动的全部目的。README 的功能列表与设置页的区块说明是这条代价的缓解，不是抵消。

**「关闭态隐藏、未配置态变灰」意味着维护两种降级表现。** 第 4 条承认这份复杂度。合并成一种会牺牲掉一个真实区别，或者回退一个已经修过的缺陷。

**第 2 条的两种相反默认语义没有统一。** 更干净的做法是把「纠正即学习」也改成 `=== "1"` 并写一次迁移，但那会在升级时静默关掉一个用户已经在用的功能。宁可留着这处不一致，用注释与测试标注它。

**入口隐藏这件事在 UI 层的测试覆盖并不齐。** 手写摄取有组件测试（`quick-capture.test.tsx` 覆盖默认不出现、开启后出现），深度思考按钮的渲染条件没有——`chat-panel.tsx` 体量大、依赖多，为一行渲染条件搭一整套测试脚手架此刻不划算。服务端那半（不下发工具、不启用推理模型）有真值表测试托底，所以漏的是「按钮画没画」而不是「功能关没关」。**这是一笔明账。**

## 后果

全新数据库首次启动时，界面上只剩「记—找—用」三步。演示模式（`npm run demo`）的默认体验同步收窄，且不需要任何额外代码——`demo.ts` 不写 `settings`，四项自然为关。

四项功能从「默认成本」变成「按需成本」：不开的人不必理解它们，开了的人一切照旧。这也是新功能冻结期内唯一有真实代码量的改动——冻结冻的是「加东西」，把已经加过头的东西收回去不在其列。
