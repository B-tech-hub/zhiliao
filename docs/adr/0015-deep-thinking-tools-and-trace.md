# 0015. 深度思考：不缩水工具能力，思考过程落库但不回灌

日期：2026-08-18
状态：已采纳（推翻 [0014](0014-heic-original.md) 初稿中的深度思考部分）

## 背景

v0.5 之后加了「深度思考」——助手输入框上的消息级开关，本次消息改用独立配置的推理模型作答。初版实现（未发布）做了两个保守决定，都写进了[测试指南](../图片与深度思考测试指南.md)当作预期行为：

1. **推理请求不下发任何工具**，理由是「能力不确定，为安全起见」；
2. **不显示思维链**，「页面和会话记录中不出现模型内部思维链」。

实际用下来，两条都是错的。

第一条的后果尤其难以理解：用户配好了图像模型，开着深度思考说「画张图」，助手回答「我不能生图」。它没说谎——`generate_image` 确实没在它手上。但从用户视角看，这是「配了功能却用不了」，而且提示词里没有任何线索指向「深度思考」这个开关。同理，深度思考期间助手也检索不了笔记、改不了元数据，一个知识库助手退化成了一个不认识知识库的聊天机器人。

第二条更直接：思考过程恰恰是推理模型最有价值的产出。看不到它，用户没有任何办法判断这次多花的时间和钱换来了什么。而代码层面它甚至不是「没做 UI」——`parseSseStream` 的 `StreamDelta` 只声明了 `content` 与 `tool_calls`，供应商返回的 `reasoning_content` 在解析层就被丢弃了。

## 决策

**一、深度思考照常下发全部工具，能力由它自己那份探测结论决定。**

「深度思考」的语义是**换一个更强的模型**，不是**进入只读模式**。安全边界不该挂在模型选择上——真正的边界是既有的那几条：仅删除需确认（[0008](0008-assistant-tool-calling.md)）、来源问答禁用 `fetch_url` 与 `generate_image`（[0010](0010-grounded-source-chat.md)、[0011](0011-image-generation.md)）、生图每条消息最多 2 张（[0011](0011-image-generation.md)）。这些在深度思考下**原样生效**，没有一条被放宽。

被否决的折中是「只下发只读工具」：听起来稳妥，但理由站不住——危险的是写不是读，而用户抱怨的恰恰是生图这个写操作。它既没有真正降低风险，又没有解决问题。

**二、工具能力探测与文本模型分开记。**

新增 settings key `reasoning_supports_tools`，与既有的 `llm_supports_tools` 并列，由设置页「深度思考模型 → 测试连接」写入。**不能共用一份**：推理模型与文本模型常常不是同一家供应商，拿一边的结论去决定另一边要不要下发 `tools`，两个方向都可能判错——该发的不发（能力凭空缩水），不该发的发了（整个请求 400）。

探测复用 `probeToolSupport()`，只是多传一组端点，不另写一套。三态语义也沿用：`null`（从未探测）一律照发，只有明确探测出 `false` 才降级。超时放宽到 120 秒——推理模型连想「要不要调这个工具」都慢。

**三、思考过程落库，但绝不回灌。**

`messages` 增加 `reasoning` 列（迁移 `0009`）。落库而非只在流式期间显示，是因为「看完即弃」的思考过程价值很低——用户想回头核对模型当时的推演时，它已经没了。

**回灌是硬禁止**：DeepSeek 等供应商明确要求 `reasoning_content` 不得作为输入，带上会 400 拒绝整个请求。表现出来是「开了深度思考，聊第二句就报错」。`buildLlmMessages()` 因此不读这一列，`runToolLoop` 回灌 assistant 消息时也只带 `content`。这条有两个单测直接钉住（普通轮、纯工具轮各一），不是靠注释提醒。

**四、三种线格式都认，包括内联标签。**

`reasoning_content`（DeepSeek / 智谱 / Qwen / 硅基流动）、`reasoning`（OpenRouter），以及部分本地模型内联在正文里的 `<think>…</think>`。第三种需要一个跨 chunk 的状态机：标签会被切成 `"…<thi"` + `"nk>推演…"`，不留住尾部的半截标签，用户就会在答案里看到裸的 `<thi`，而后半段思考被当成正文吐出来。

## 后果

- **深度思考现在会花钱写库。** 它能建笔记、能画图，与普通对话一致。这是有意的——所有既有防线都还在，唯独「模型更强」这一点变了。
- **最坏耗时变长。** 300 秒超时 × 最多 8 轮工具循环，理论上很久。实践中推理集中在第一轮，后续轮次快得多；用户全程可见思考过程与工具卡片，也随时可以点「停止」。
- **思考过程会让会话表变大**，常常比答案长 3–5 倍。单用户本地 SQLite，可接受。
- **落库意味着它进导出与备份。** 这是合理的——它属于那次对话的一部分。但「存为新笔记」时不带上：笔记要的是结论。
- **未配置推理模型时开关置灰。** 原先它照常亮着，点了静默无效，用户只会以为功能坏了。
- **测试指南里那两条验收项已作废**，随本次改动改写。
