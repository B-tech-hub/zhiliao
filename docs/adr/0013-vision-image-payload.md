# 0013. 视觉请求使用内存压缩副本与字节预算

日期：2026-08-18  
状态：已接受

## 背景

笔记图片以原始文件保存。AI 看图原先直接把最多 4 张原图编码为 Base64 放入 Chat Completions JSON。4 张约 6.0 MiB 的 PNG 会膨胀成约 8.0 MiB 请求，超过部分 OpenAI 兼容代理或网站防火墙的限制；设置页使用极小测试图，因此无法暴露这个问题。

视觉模型通常不支持项目依赖的工具调用格式，所以看图模式不下发写库工具。用户需要把识别结果可靠地留进知识库，而不能依赖模型在同一轮调用 `create_note`。

## 决策

1. 视觉请求发送前，在服务端内存中将图片旋转校正、限制最长边并编码为高质量 WebP；不写回磁盘，不修改笔记原图。
2. 最多发送 6 张图片；压缩后单张不超过 700 KiB、合计不超过 2.5 MiB。超过限制时在调用模型前给出中文错误。
3. AI 的完整文字回答提供「存为新笔记」入口，保存仍走既有 `POST /api/notes`，复用统一的 FTS、入队和数据校验路径。
4. 上游若返回 HTML 防火墙页面，只展示状态码与页面标题，不把 HTML 原文暴露到聊天界面。

## 取舍

- 调高第三方代理限制不由本应用控制，且不能保护其他部署环境，因此不能作为唯一方案。
- 逐张调用模型会增加费用，也会丢失多图之间的上下文，不采用。
- 压缩可能轻微影响极小文字；采用较高 WebP 质量和 960 像素最低最长边，在代理兼容性与 OCR 清晰度之间取平衡。原图始终保留，后续可调整编码策略。
