## 6. 原确认稿的启动命令

以下保留提交确认时的命令和模板。执行时先生成运行标记、保护基线和经指纹核对的源码副本；将当前 `docker-compose.demo.yml` 复制为 `compose.base.yml`，将 `nginx/demo.conf` 复制到临时目录相同相对路径，保存下方覆盖文件为 `compose.r1.yml`。复制配置用于验收，不修改原文件。原模板入口失败与实际补充覆盖见第 11 节。

在清洁专用 PowerShell 子进程内，准备变量：

```powershell
$r1RunId = (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + [guid]::NewGuid().ToString('N').Substring(0, 8)
$r1Project = 'zhiliao-r1-061-' + $r1RunId
$r1Root = Join-Path ([IO.Path]::GetTempPath()) ('zhiliao-r1-install-061-' + $r1RunId)
$r1Source = Join-Path $r1Root 'source'
$r1ImageTag = 'zhiliao-r1:0.6.1-' + $r1RunId
```

准备完成后，从副本进行一次构建。`source-manifest.json` 是按相对路径排序的源码 SHA-256 清单，随证据保存；构建输入包含当前未提交内容。

```powershell
$r1SourceSha256 = (Get-FileHash -Algorithm SHA256 -LiteralPath (Join-Path $r1Root 'source-manifest.json')).Hash.ToLowerInvariant()
docker --context desktop-linux build --platform linux/amd64 --progress=plain `
  --label "io.zhiliao.r1.run=$r1RunId" `
  --label "io.zhiliao.r1.source-sha256=$r1SourceSha256" `
  --label 'io.zhiliao.r1.base-commit=f213761b795cc020be2122e27301fe4a7c5cf7a0' `
  --label 'io.zhiliao.r1.working-tree=true' `
  --iidfile (Join-Path $r1Root 'image-id.txt') --tag $r1ImageTag $r1Source
if ($LASTEXITCODE -ne 0) { throw '候选镜像构建失败，保留日志并停止验收。' }
$r1ImageId = (Get-Content -Raw -LiteralPath (Join-Path $r1Root 'image-id.txt')).Trim()
```

将 `R1_RUN_ID`、`R1_IMAGE`（实际 image ID）、`R1_PORT=3312` 与新生成的 `DEMO_PASSWORD`、`DEMO_SESSION_SECRET` 写入临时 `r1.env`。后两个变量仅为复用基础 Compose 的插值接口，app 的实际模式由下面的 `DEMO_MODE=0` 决定；基础文件插值发生在合并前，不能省略 `DEMO_SESSION_SECRET`。

覆盖模板如下。`!override` 要求 Compose 2.24.4+，当前版本满足。


第 5 步的容器重建命令，必须使用与启动相同的参数和环境文件：

```powershell

if ($LASTEXITCODE -ne 0) { throw '重建前停止失败。' }
```
