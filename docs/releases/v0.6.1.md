## 后续候选验证与部署

`package.json` 保持正式基础版本 `0.6.1`；例如 `v0.6.1-rc1` 的镜像为 `ghcr.io/b-tech-hub/zhiliao:0.6.1-rc1`，其 MCP 应用版本仍为 `0.6.1`。Compose 默认固定正式镜像；RC 验证通过明确的镜像覆盖选择同一 RC，不能仅改变 tag 名就运行正式镜像。

维护者可先在当前工作区预览，以下命令不启动容器：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/smoke-fresh-install.ps1 -PrintConfig
powershell -ExecutionPolicy Bypass -File scripts/smoke-fresh-install.ps1 -Image ghcr.io/b-tech-hub/zhiliao:0.6.1-rc1 -PrintConfig
```

镜像实际生成并获准验收后，再去掉 `-PrintConfig` 运行隔离安装冒烟。正式镜像发布前，普通安装仍按双语 README 和部署手册中的 **v0.6.0** 路径执行；不要用当前分支 Compose 推断 0.6.1 已可拉取。

从 0.6.0 升级前，保存原镜像 tag/digest、Compose、环境文件、project、实际挂载及数据库/完整图片的配对快照。目标版本发布后，在原部署目录对比配置，再将应用镜像固定为 0.6.1。失败时按[备份与恢复](../备份与恢复.md#isolated-restore)恢复到独立目标，不直接让旧镜像读取已经升级的库。

2026-09-27 [隔离升级与回退彩排](../验收证据/upgrade-060-061-20260927-a/README.md)（本机 linux/amd64、合成数据）通过：0.6.0 数据改用 0.6.1 候选镜像后，迁移记录不变，业务表、图片哈希与 HEIC 展示图读取一致，升级后写入重启保留；以 0.6.0 镜像恢复升级前快照后状态一致。**回退到 0.6.0 后 HEIC 展示图会因 0.6.0 的已知读取缺陷返回 400**，数据仍完整，重新升级即恢复显示。异地、独立 Linux、arm64 与 RC 仍未验收。
