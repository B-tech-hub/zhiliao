## 3. 获准后的执行顺序

以下命令是待执行方案。均在仓库根目录运行，每条失败立即停止；PowerShell 不会因原生命令非零退出自动终止，执行者须检查 `$LASTEXITCODE`。本轮尚未运行本节的暂存、提交或推送。

### V1：提交并锁定候选

1. 再查分支、工作树、暂存区及第 2 节路径。读取 Git hooks 配置；若 hook 会触发额外重验证或写外部系统，先明确其范围，不擅自跳过 hook。
2. 只暂存第 2 节 13 个路径，确认暂存内容与本单一致，再执行：

```powershell
git commit -m 'chore: 准备 R3 门禁 4 分发验收与候选 CI'
if ($LASTEXITCODE -ne 0) { throw '提交失败，停止' }
$candidateSha = (git rev-parse HEAD).Trim()
if ($LASTEXITCODE -ne 0 -or $candidateSha -notmatch '^[a-f0-9]{40}$') { throw '候选身份无效' }
git rev-parse 'HEAD^{tree}'
git ls-tree -r --full-tree $candidateSha
git status --porcelain=v1 -uall
```

要求工作树和暂存区干净。保存完整候选 SHA/tree、13 个路径的 SHA-256 以及全部 Git blob 清单；其中工作流、工具和测试必须匹配第 1 节的哈希。新提交的父提交须为本单本地 HEAD。该清单随运行证据保存，不为把自身清单写进自身提交而循环提交。

### V2：复核远端并进行一次普通推送

```powershell

gh pr view 12 --repo B-tech-hub/zhiliao --json state,isDraft,headRefName,headRefOid,baseRefName,baseRefOid,mergeable,statusCheckRollup
git merge-base --is-ancestor 40ac9d7b4ccb8e824e9dccabb19849c8c249cbb2 $candidateSha
```

远端候选、main 和 PR 目标必须仍与第 1 节一致，祖先检查必须退出 0。PR 关闭、冲突、远端移动或待推送内容变化都先停止；不自动 rebase、merge 或强推。

```powershell
git -c push.followTags=false push --no-follow-tags origin "${candidateSha}:refs/heads/candidate/0.6.1-baseline"
if ($LASTEXITCODE -ne 0) { throw '推送未确认成功，先只读核对远端，不盲目重试' }
```

这里只更新一个候选 ref，显式禁止附带 tag。推送返回后用 `ls-remote` 和 PR API 确认远端 head 等于 `$candidateSha`；若网络中断，先确认远端是否已收到提交及是否已有 CI，避免重复触发。

## 4. 验收、风险与停止条件

V 通过须同时满足：候选 ref 与批准内容一致；新 CI 的 head/base/checkout 身份可追溯；版本及四条门禁成功，未以跳过或取消代替成功；日志和输入身份归档完成。此时只勾选规格中的 V，不关闭门禁 4–6 或 Story/Sprint。

| 情况 | 处理 |
|---|---|
| 远端分支移动、PR 冲突、提交范围变化 | 推送前停止，呈交新差异；不强推或自动改写历史 |
| 没有匹配的新 run、Actions 待批准、存在多个匹配 run | 先只读辨认原因；不另建 workflow 或触发重复运行 |
| 安装、版本、设计、lint、测试、构建任一失败 | 保存首次失败与未执行步骤；区分代码、环境、既有问题，再提出最小修复与复验范围 |
| 队列或运行超出监控阈值 | 按本单取消当前 run，留证；取消未成功也如实记录，不称已停止 |
| SHA、tree、日志或步骤结论缺失 | 标为证据不足，V 未通过 |
| CI 通过 | 记录 Linux PR merge 验证通过；npm 缓存、单架构和 Next 构建不等于无缓存双架构镜像验收 |

影响范围为本轮候选提交、PR 检查和本地证据。风险集中在独立 Linux 依赖安装/原生模块、现有测试的平台差异、Actions 调度与身份取证；P 的静态检查不能预判它们一定通过。真实数据、已运行的本机服务及历史镜像不在执行范围。
