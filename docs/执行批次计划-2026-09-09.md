真实笔记达到 100 条前继续冻结新功能。文档、分发、部署、安全和缺陷修复可以推进；正式库、Demo 库、测试库必须保持数据、卷、网络和密钥隔离。

## 批次顺序

| 批次 | 对应 Epic | 预计投入 | 退出条件 |
|---|---|---:|---|
| A | GitHub 安装与首次使用教学 | 1～2 天 | 全新环境按文档安装成功，并完成首条笔记闭环 |
| B | 公网 Demo 安全化 | 1～2 天 | 服务端限制、隔离部署、资源保护、重置和 HTTPS 验收通过 |
| C | 可复现的“AI 不编造”演示 | 0.5～1 天 | 固定数据可复现，20～30 秒素材已同步 README |
| D | ADR 文档分发与效果观测 | 写作 1～2 天，观察 30 天 | 至少一篇文章发布，Traffic 快照按节点留存并完成复盘 |

## 依赖与人工闸门

```text
A 安装教学
    └──> B Demo 安全化 ───> C 可复现演示 ───> D ADR 分发与观测
```

- 维护者必须先确认主安装路径、Demo 最小演示能力、服务器/域名/HTTPS 和是否共机。
- DNS、服务器部署、GitHub Release、外部发帖和公开 Demo 链接均保留人工确认。
- `pilot-runbook.md` 的真实设备、授权、备份、交付和 7 日记录要求，不得由一次本地测试替代。
- Issue #4 的手机入口仍需连续 7 天每天至少一条真实笔记；恢复验收单独统计。

## 总体验收

1. 新用户能从 GitHub/v0.6.0 固定版本完成安装、登录和首条笔记闭环。
2. 公网 Demo 与正式数据、卷、环境文件和密钥隔离，服务端拒绝高风险设置与 Token 操作。
3. Demo 可自动/手动重置，演示数据和“AI 不编造”结论可复现。
4. 至少一篇 ADR 文章完成发布，流量和反馈按固定时间点留存。
5. 没有因文档或分发工作绕过 100 条真实笔记前的新功能冻结闸门。
