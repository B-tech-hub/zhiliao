## 问题定位

### 1. 助手在相关性排序之前截断候选

责任位置：[src/lib/search.ts](../src/lib/search.ts) 的 `searchNoteIds` 和 `hybridSearchNoteIds`。

修复前 `searchNoteIds` 的 FTS 查询在 SQL 中直接 `LIMIT`，取回后才按命中词数及 BM25 排序。搜索页面请求 50 条结果，内部取 150 条候选；助手默认请求 8 条，内部只取 50 条候选。因此同一问题在两个入口得到不同质量的结果，后导入的相关笔记可能根本没有进入排序阶段。

修复前对 BERT 问题做了只读对照：

| 对照 | 结果 |
|---|---|
| FTS 匹配总数 | 114 条，包含预期来源 |
| 未排序就取前 50 条 | 不包含预期来源 |
| 按 BM25 排序后取 50 条 | 包含预期来源 |
| 旧函数取 50 条候选后排序 | 预期来源未返回 |
| 旧函数取 150 条候选后排序 | 预期来源排第 1 |

这排除了“笔记未导入或没有建立索引”的解释。现已改为先过滤有效笔记和来源，再按 BM25 排序取候选，并完整统计已选候选的逐词命中数；LIKE 降级同样在截断前过滤来源。修复后 BERT 在 50/150 个候选下都排第 1。新增 205 条来源外匹配、失步索引和 55 条弱匹配的回归用例，确认修复不依赖把候选常量调大。

### 2. 自然问句中的常用词影响关键词排名

圆面积问题即使候选覆盖整批语料，预期来源仍排第 15；作为诊断补充，查询缩为“圆面积公式”或“圆的面积”时均排第 1。原问题分词包含“文档、给出、的、是、什么”等，当前排序先比较命中词数，再比较 BM25。

说明该差距不能全部归于候选截断。后续需要评估查询词权重或停用词处理，同时保留中文短词、课程编号、英文缩写及现有检索能力。补充关键词查询只用于定位原因，原始验收问题继续按失败记录；本轮未启用或批准 AI 查询改写。

### 3. 长文可被检索，但读取工具拿不到末尾证据

责任位置：[src/lib/ai/tools/read-note.ts](../src/lib/ai/tools/read-note.ts) 和来源超预算后的读取流程。

`13-计算机科学-自学规划.md` 导入后正文为 18902 字符，超过来源全文注入的 12000 字符预算，来源上下文进入 `digest` 模式。选取只出现一次的末尾原句“以上的课程规划难免带有强烈的个人偏好”作为证据，其零基偏移为 **18295**。

- 来源内检索可以找到该笔记。
- 修复前 `read_note` 返回成功及“正文过长已截断”标记，但只提供前 6000 字符，未包含目标证据。
- 旧工具没有偏移或分段读取参数，多次读取仍然拿到相同的开头。

现已通过可选 `offset` 和返回文本中的 `nextOffset` 补齐续读。偏移按 UTF-16 单位计数，默认从 0 开始，末尾为 `null`；每页正文最多 6000，完整工具结果不超过 8000。较长标题、主题、标签使用单行预览，代理对不会被拆开；每次读取重新检查来源和笔记存活状态。具体契约见 [ADR-0010](adr/0010-grounded-source-chat.md)。

本次验收从 0 开始跟随返回位置，没有直接跳到已知答案偏移：

| 请求 offset | 正文长度 | 完整结果长度 | nextOffset | 包含末尾证据 |
|---:|---:|---:|---:|---|
| 0 | 6000 | 6162 | 6000 | 否 |
| 6000 | 6000 | 6166 | 12000 | 否 |
| 12000 | 6000 | 6167 | 18000 | 否 |
| 18000 | 902 | 1068 | null | 是 |

四页拼接与 18902 字符全文逐字一致。单次结果与多轮结果预算仍为 8000 字符，最多 8 轮工具调用；工具可逐页读全不代表模型同时持有全部页面，旧页仍可能因预算被省略。普通与来源系统提示均要求未读完时说明无法确认。
