使用入口：[固定 v0.6.0 Release](https://github.com/B-tech-hub/zhiliao/releases/tag/v0.6.0)、[安装路径](../../README.md#部署docker)、[首次使用](../首次使用与故障排查.md)、[备份与恢复](../备份与恢复.md)。新版本未发布前只按现有发布能力描述；本页列出的文档缺口和候选能力不能当成 v0.6.0 已验证结果。

反馈可使用[现有 GitHub Issue](https://github.com/B-tech-hub/zhiliao/issues)，也可由维护者人工记录。请提供版本、平台、预期、实际、复现步骤和必要的脱敏日志；不要公开密码、Token、API Key、完整笔记或备份。身份、联系信息和敏感材料只保存在维护者的私有记录中。

| 字段 | 填写口径 |
|---|---|
| 试用代号、渠道、版本、平台、日期 | 同一人去重；首次安装与升级分开统计；没有发生就留空或写未尝试 |
| 安装与首次记录 | 尝试数/成功数、耗时、是否需协助、失败位置；沿用 PRD 的 5 分钟选路、安装后 15 分钟保存首条笔记目标 |
| 整理、搜索、来源问答 | 配置情况、具体任务、目标笔记是否打开、引用是否支撑回答、是否正确拒答；保留失败样本 |
| 出口与恢复 | Markdown、ZIP、导回、数据库恢复分别记录通过数/尝试数；未演练不能填通过 |
| 七日使用 | 真实新写、手机捕获和使用摩擦；历史导入单列，只记必要计数，不收正文 |
| 处置与投入 | 缺陷/文档编号、下一步、责任人、支持分钟和实际费用；无回复不等于满意 |

不要求每位试用者执行恢复；发布方先具备隔离恢复证据，用户自愿演练时明确独立目标和数据范围。发生数据损坏、泄露或恢复失败时停止受影响步骤并保护源数据。

免费反馈不自动计入 CAP-1 有效商业访谈，不算实际付款、套餐交付或商业成立，也不启动商业 D1。原商业访谈、资金、成本和停止结论保留，共用成本只记一次；重新收费前仍需明确批准与原合同条件。恢复通过不替代留存或 #4 七日验收，多个用户的库不能相加宣布维护者正式库解冻。
