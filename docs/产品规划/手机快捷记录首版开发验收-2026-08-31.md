# 手机快捷记录首版开发验收

日期：2026-08-31  
对应 Issue：#4 手机一键记录  
状态：首个可试用版本已完成；已补充 Server/Client 向量字段序列化修复，真实 iPhone 与连续 7 日行为验收待用户执行

## 当前理解

现有服务端已经具备 `capture:write` Token、外部捕获接口和吊销能力。本轮不新增页面、数据表、持久化状态或接口，目标是把隐藏在技术契约里的能力变成用户能配置、能验证、能排错的首版体验。

## 实施范围

- 将设置页 Token 区块从大型 `settings-panel.tsx` 拆为独立组件。
- 增加用途清晰的 Token 创建、一次性明文提示、复制反馈和吊销结果。
- 创建手机快捷记录 Token 后显示实例捕获地址和可复制请求信息。
- 增加真实写入自测，成功后可打开笔记，失败时保留输入。
- 增加 iOS 快捷指令逐步配置、错误码、安全和吊销文档。
- 增加面向用户的 HTML 产品说明。

## 非目标

- 不修改 `POST /api/external/capture` 契约。
- 不生成无法在 Windows 环境安全签名的 `.shortcut` 文件。
- 不宣称完成真实 iPhone、蜂窝网络或连续 7 日行为验证。
- 不增加 Android 平台模板，本轮只完成一个主平台。

## 风险与处理

| 风险 | 处理 |
|---|---|
| Token 被截图或误分享 | 文档和界面强调明文只显示一次，截图使用脱敏示例 |
| 用户用错 `knowledge:read` | 用途名称明确为“手机快捷记录（只写入）”，接口继续做权限校验 |
| 网络失败导致内容丢失 | 应用内自测保留输入；iOS 指南要求发送前复制到剪贴板 |
| `localhost` 在手机不可用 | 指南明确要求 HTTPS 和 Tailscale 地址 |
| 笔记已保存但 AI 未整理 | 成功文案区分“已保存”和“进入整理队列”，故障表给出检查入口 |

## 验收标准

- 用户能创建专用 `capture:write` Token。
- 用户能复制 Token、捕获地址和完整请求信息。
- 用户能在设置页真实写入一条笔记并打开结果。
- 401 和网络失败时输入不丢失，并给出下一步。
- Token 吊销后从列表移除，旧调用立即返回 401。
- 390px 手机视口无横向滚动，主要按钮不小于 44px。
- 浅色、深色、桌面和手机视口均完成截图检查。

## 后续缺陷修复记录（2026-09-03）

用户测试发现收件箱页出现 Next.js 错误：`Only plain objects can be passed to Client Components ... Uint8Array objects are not supported.` 根因是数据库 `notes.embedding` BLOB 被完整传入 `InboxClient`。

- 新增 `src/lib/client-note.ts`，通过 `toClientNote` 在服务端边界移除 `embedding`。
- 收件箱、主题笔记和笔记编辑页统一使用可序列化笔记对象；服务端检索仍继续使用数据库向量。
- 新增 `tests/lib/client-note.test.ts`，验证 helper 会去掉 BLOB。
- 2026-09-22 补上 `tests/components/client-note-pages.test.tsx`，锁定收件箱、主题笔记和笔记编辑页不再把 `embedding` 传给客户端。
- 实例验证：登录返回 `200`，`/inbox` 返回 `200`，响应不含 `Uint8Array` 或 `Console Error`。
- TypeScript、受影响文件 ESLint 和相关回归测试均通过。
