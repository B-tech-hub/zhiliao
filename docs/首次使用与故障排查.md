# 首次使用与故障排查

本教程面向已经按 **v0.6.0** 启动知了、并能打开登录页的用户。按“先完成一次，再理解配置，最后排错”的顺序阅读；不需要真实 API Key，也不会要求修改运行时或重建正式数据。

## 先选实例

- **Demo**：使用 `npm run demo` 或 `docker-compose.demo.yml`。Docker Demo 默认密码为 `demo`，可由 Compose 环境变量 `DEMO_PASSWORD` 覆盖；源码 Demo 会受当前进程传入的 `APP_PASSWORD`、`PORT` 等环境变量影响，始终以启动输出和实际环境为准，不要把 `demo` 当作固定秘密。源码 Demo 写入 `./data-demo/`，Docker Demo 写入独立的 `demo_db`/`demo_uploads` named volume。结束前先停止当前 Demo，再只删除 Demo 目录或 Demo project/volume 重置，不能清理正式数据。
- **正式实例**：使用 v0.6.0 的 Docker 镜像或源码路径。Linux/默认绑定挂载的数据在 `./data/db`、`./data/uploads`、`./data/notes`；Windows Docker Desktop 使用 `docker-compose.win.yml` 时，SQLite 数据库和上传文件在 `kb_db`、`kb_uploads` named volume 中，不要按 `./data/db` 或 `./data/uploads` 查找。正式实例使用自己的 `.env`、端口和 Docker 卷。
- **测试/冒烟实例**：使用隔离的 Compose project、临时密码和 named volume；不要复用正式 `.env`、`data/` 或卷。维护者可参考 README 的[全新环境安装冒烟](../README.md#全新环境安装冒烟)。

实例之间不要共用数据目录、Docker 卷或环境文件。遇到问题时，先确认当前浏览器地址、Compose project 和数据目录属于哪一个实例。

## 最短闭环：从登录到搜索

### 1. 登录

打开 `http://localhost:3000`（手机访问请使用 Tailscale 提供的 HTTPS 地址），输入当前实例的 `APP_PASSWORD`。

成功判据：进入首页，能看到主题列表或空状态，并能打开设置。

> Docker 主路径、Windows 命名卷例外和 HTTPS 前置条件见[部署手册](部署手册-tailscale.md)。不要把 `localhost` 地址发给手机使用。

### 2. 新建普通文本笔记

点击新建笔记，输入一段普通文本，例如“今晚羽毛球多球训练，杀球终于有点下压了”，然后点击保存或离开编辑器等待自动保存。

成功判据：笔记重新打开后正文仍在，并显示已保存或页面成功状态；不要用手机捕获 Token 或图片功能代替这一步。若保存失败，保留编辑内容，先排查网络/服务状态，不要刷新页面丢稿。

### 3. 等待并确认 AI 整理状态

保存后回到笔记详情，查看标题、标签、摘要和主题状态：

- 已配置文本模型：通常会从“待整理”进入整理中，再显示标题、标签、摘要和主题。
- 未配置文本模型：笔记仍已保存，状态保持“待整理”。到 **设置 → AI 服务** 配置模型后，旧笔记会自动补处理，也可在笔记页点击“重新处理”。

成功判据：正文没有被覆盖；AI 字段出现，或明确看到“待整理”而不是“保存失败”。

### 4. 打开主题

从笔记显示的主题名称进入主题页；如果 AI 置信度不足，笔记会留在“未分类”，这也是有效结果。

成功判据：主题页能看到刚才的笔记，正文和 AI 摘要可打开查看。

### 5. 完成一次搜索

在搜索框输入“羽毛球训练”或另一种说法（例如“杀球练习”），提交搜索；也可以先点主题再浏览该主题的笔记。

成功判据：结果中出现刚才的笔记。未配置 `EMBEDDING_*` 时搜索使用 BM25，仍应可用；配置后才会增加语义召回。

## AI 未配置或任务等待

### AI_NOT_CONFIGURED（教程内部标签）：一直“待整理”

1. 确认正文能重新打开，说明保存成功，不要删除或重建笔记。
2. 进入 **设置 → AI 服务**，填写接入点、模型和 API Key，点击“保存”与“测试连接”。API Key 只填在设置页或本机环境文件中，不写进文档、截图或日志。
3. 保存配置后等待队列补处理，最多先等 **5 分钟**；仍未变化时，查看任务状态并对单条笔记点击“重新处理”。

停止条件：没有模型账号、无法确认接入点或怀疑会触碰正式数据时先停在这里，保留笔记，联系维护者或查[部署手册 FAQ Q7](部署手册-tailscale.md#q7记了笔记ai一直不整理一直待整理或显示失败)。

### TASK_WAITING（教程内部标签）：用户可见“整理中”或“整理失败”

1. 在设置页检查 AI 服务配置和测试连接结果。
2. 检查任务状态；确认容器仍在运行，必要时在当前实例目录执行 `docker compose -f docker-compose.yml -f docker-compose.win.yml logs --tail 50`（Linux 可省略第二个文件）。
3. 修复配置或网络后，对该笔记执行“重新处理”，不要复制正文创建新笔记。

停止条件：等待超过 **5 分钟**、日志持续报同一错误，或无法判断哪个实例在运行时，停止重试并保留日志片段与笔记原文，按[部署手册 FAQ Q7](部署手册-tailscale.md#q7记了笔记ai一直不整理一直待整理或显示失败)处理。

## 按症状排查

| 症状 | 检查 | 修复/下一步 | 停止条件 |
|---|---|---|---|
| 端口冲突，提示 `port is already allocated` | `docker ps -a`，确认是否已有程序占用 3000 | 只对当前实例把 compose 映射改为 `"3001:3000"`，Windows 继续叠加 `-f docker-compose.win.yml`，再执行 `docker compose -f docker-compose.yml -f docker-compose.win.yml up -d`；Tailscale 同步执行 `tailscale serve --bg 3001`，访问 `http://localhost:3001` | 不确定占用者或可能是正式实例时不要停进程，先记录端口并求助 |
| 权限错误、Docker 起不来 | 打开 Docker Desktop，确认 Docker 已就绪；在当前实例目录执行 `docker compose logs --tail 50` | Windows 按部署手册使用 `docker-compose.win.yml` 命名卷覆盖；确认当前目录和 `.env` 属于目标实例 | 出现 SQLite/WAL 或卷归属不明时停止，不删除卷或 `data/` |
| `localhost:3000` 打不开 | `docker ps` 看容器状态；若 `Exited`，在当前实例目录执行 `docker compose -f docker-compose.yml -f docker-compose.win.yml logs --tail 50`（Linux 可省略第二个文件） | 按[部署手册 FAQ Q3](部署手册-tailscale.md#q3容器起不来--localhost3000打不开)修复配置、端口或 Docker | 日志无法判断原因时保留容器和日志，不反复重建正式卷 |
| HTTPS 不受信任、手机打不开 | 手机与电脑 Tailscale 是否同账号且在线；执行 `tailscale serve status`；确认管理台已启用 HTTPS Certificates | 按[部署手册第 6 章](部署手册-tailscale.md#第-6-章tailscale让手机在任何地方都能连回家)恢复转发，使用 `.ts.net` 域名而非 IP | 证书仍报错或设备不在线时停止，不把 HTTP 地址当作 PWA 入口 |
| 蜂窝网络不可达 | 手机 Tailscale 开关、电脑是否睡眠、服务是否运行；先在手机蜂窝网络打开 HTTPS 地址 | 保持电脑运行并使用 Tailscale 地址；手机快捷记录另见[手机快捷记录](手机快捷记录.md) | 无法确认网络归属或设备不在线时停止，不修改正式数据 |
| 升级后变成空应用 | 检查项目文件夹名、Compose project 和 Docker 卷是否改变 | 放回原文件夹名并按[部署手册 FAQ Q9](部署手册-tailscale.md#q9升级挪动文件夹之后打开变成了全新的空应用我的笔记呢)恢复原卷 | 不要初始化新库、删除旧卷或覆盖 `data/` |

## 安全边界与数据出口

- `APP_PASSWORD` 是登录密码；`SESSION_SECRET` 是会话签名密钥，二者只属于当前实例的 `.env`，不要写进截图、Issue 或共享模板。示例命令中的占位符不是可用密码。
- API Key、`capture:write` Token 和 `knowledge:read` Token 都是秘密。教程只说明入口，不要求真实 Key 才能完成首条普通文本笔记；手机捕获配置和吊销流程见[手机快捷记录](手机快捷记录.md)。
- Demo、正式和测试实例必须使用不同的数据目录、卷、端口与环境文件。停止服务后，清理只能针对当前 Demo project/volume；不要用 Demo 密码访问正式实例，也不要把正式备份导入测试环境后继续对外暴露。
- 备份用于灾难恢复，导出用于迁移与阅读；需要恢复时只按[备份与恢复](备份与恢复.md)操作，先停服务并确认快照日期。遇到不确定的卷或 WAL 文件，不要直接删除。

完成首次闭环后，再按需要阅读[部署手册](部署手册-tailscale.md)、[手机快捷记录](手机快捷记录.md)和[备份与恢复](备份与恢复.md)的专项章节。
