当前工作区目标为 **0.6.1 候选，尚未发布**。本教程的普通安装继续采用已发布 v0.6.0；当前分支的主/Demo Compose 已指向待发布 0.6.1，不能直接套用为旧版配置。当前候选的源码 Demo 接线已修复，已在 Windows 本机受控环境完成实际启动与浏览器验收，见 [R1 结果与边界](产品规划/开源发布范围与执行清单-2026-09-13.md#r1-source-demo)及[实测记录](R1源码Demo接线验收-2026-09-14.md)。该次使用临时副本和附加运行保护，不代表 Docker、安装、恢复或发布验收通过。

当前免费试用采用你自己设备上的自托管实例；公网 Demo 后移。软件按 MIT 免费使用，设备与自选模型费用按实际情况承担。完成主流程后，可继续阅读[数据出口与恢复](备份与恢复.md)，并按[免费反馈说明](产品规划/开源发布范围与执行清单-2026-09-13.md#free-feedback)记录安装、找回笔记、来源问答或恢复中的具体阻断。未配置模型时仍可保存、关键词搜索和导出；mock 演示只证明流程，不代表真实模型效果。

## 先选实例

若按 README 的固定命令获取旧版，v0.6.0 源码 Demo 允许宿主环境覆盖演示默认配置；旧启动器未设置 `NOTES_EXPORT_DIR`，Markdown 默认写入 `./data/notes`。必须使用[下方的隔离启动步骤](#v060-source-demo)，不要将以下“源码 Demo（当前候选）”的强制覆盖规则套用到旧 tag。

- **源码 Demo（当前候选）**：使用 `npm run demo`，启动器自动设置 `DEMO_RUNTIME=local`，连接固定本机 mock `http://127.0.0.1:8787/v1`。源码启动器固定 `APP_PASSWORD=demo`、演示专用 `SESSION_SECRET` 和 `./data-demo/` 下的数据库、上传及 Markdown 路径，覆盖宿主同名配置；`PORT` 等未固定变量仍可透传。上方版本说明和 README 的 v0.6.0 获取命令仍按历史版本解释。
- **Docker Demo（当前候选配置）**：使用 `npm run demo:compose -- up -d` 启动。包装脚本会先清理宿主 `DEMO_*`/`COMPOSE_*`，再执行内部等价命令 `docker compose --env-file demo.env -p zhiliao-demo -f docker-compose.demo.yml`，避免正式 `.env` 或宿主变量污染 Demo。默认连接固定容器 mock `http://mockllm:8787/v1`。默认密码为 `demo`，可在专用 `demo.env` 中通过 `DEMO_PASSWORD` 覆盖。必须设置独立的 `DEMO_SESSION_SECRET`，不要把密钥写入 Compose 文件。Docker Demo 写入独立的 `demo_db`/`demo_uploads`/`demo_notes` named volume，并使用 `zhiliao-demo` project；Nginx 入口发布 3210 端口并限制 200 MB 请求体，app/mockllm 仅加入 isolated 内网。结束体验：`npm run demo:compose -- down -v`。结束前先停止当前 Demo，再只删除 Demo project/volume 重置，不能清理正式数据。
- **正式实例**：按[固定版本安装步骤](部署手册-tailscale.md#第-2-章获取固定版本的部署文件)使用 v0.6.0；历史 tag 的 Compose 仍指向 `latest`，须先将 `image:` 改为 `ghcr.io/b-tech-hub/zhiliao:0.6.0` 并用 `config --images` 核对。Linux/默认绑定挂载的数据在 `./data/db`、`./data/uploads`、`./data/notes`；Windows Docker Desktop 使用 `docker-compose.win.yml` 时，SQLite 数据库和上传文件在 `kb_db`、`kb_uploads` named volume 中，不要按 `./data/db` 或 `./data/uploads` 查找；Markdown 仍在宿主机 `./data/notes`。实际卷名取决于原 Compose project，正式实例使用自己的 `.env`、端口和卷。
- **测试/冒烟实例**：使用隔离的 Compose project、临时密码和 named volume；不要复用正式 `.env`、`data/` 或卷。维护者可参考 README 的[全新环境安装冒烟](../README.md#全新环境安装冒烟)。

实例之间不要共用数据目录、Docker 卷或环境文件。遇到问题时，先确认当前浏览器地址、Compose project 和数据目录属于哪一个实例。

当前候选仅在 `DEMO_MODE=1` 时使用上述 mock 规则：只有 `DEMO_RUNTIME=local` 选择本机，缺省或非法标记均选择容器；`DEMO_LLM_BASE_URL`、`LLM_*` 和数据库中的外部模型配置不能改写目标，Embedding、视觉、生图和推理模型保持禁用。正式模式仍按数据库优先、环境变量兜底读取模型，运行标记不改变此规则。

当前 Docker Demo 已改为 Nginx 入口、app 和 mockllm 三容器拓扑。入口默认只绑定 `127.0.0.1:3210`，加入普通入口网络与 Demo 内网；app/mockllm 不直接发布端口，也不分配宿主机网关。入口与 app 共享 Demo 内网是反向代理所必需的，因此 app 可以访问 `ingress:8080`，但入口只固定转发到 app，不提供任意目标代理。

已发布 v0.6.0 应用镜像尚未包含本轮服务端防护；当前 Demo 配置已改为 0.6.1 候选，镜像发布与验收仍待完成。公网使用前须发布包含补丁的固定应用镜像。Nginx 已在 Next.js 前限制实际接收正文，目标主机仍须验证 isolated 网络兼容性并设置 Demo 卷配额。维护者见 [Story 2.2 验收记录](Demo部署隔离验收-2026-09-10.md)。

维护者复验候选镜像时，可按验收记录使用 `scripts/verify-demo-runtime.ps1`，宿主机需 Node.js 22+。默认使用随机 project 和本机 3322 端口；端口冲突可用 `-Port` 调整，`-IncludeSse` 增加流式检查，`-IncludeNetwork` 在同一实例上接着执行 20 项网络对照。两组选项可同时使用，默认检查后清理 Demo 和网络对照资源；网络、证据或清理失败均返回非零，不需要为了串接网络检查而添加 `-KeepResources`。单独工具的使用方式见 `node scripts/verify-demo-network.mjs --help` 和 `node scripts/verify-demo-proxy-timeouts.mjs --help`。

9 月 12 日 B2 已在 Windows Docker Desktop 完成本机 HTTP/SSE、20 项网络对照和清理，代理时限沿用此前 A2 四项成功证据。本阶段仅供本机体验，业务卷硬配额、实际正式服务隔离、公网 HTTPS 及补丁镜像发布仍待完成，详见 [最新验收记录](Demo部署隔离验收-2026-09-10.md#b2-local)。

## 已发布 v0.6.0 源码 Demo 的隔离启动

需要 Node.js 22+、全新独立目录和专用终端。不要复制正式 `.env*` 或已有 Demo 数据库；目录已存在时换一个新目录名重新执行，不能跳过 clone 失败。旧版中的 `DEMO_MODE`、`LLM_*`、`EMBEDDING_*`、`VISION_*`、`IMAGE_*`、`REASONING_*` 及已有 Demo 数据库中的模型配置都可能影响行为。清空宿主变量不能覆盖数据库已保存的模型，因此不能无条件承诺旧版不会发出外部请求。

旧版新建和修改笔记都会安排 Markdown 导出；其默认 `./data/notes` 不在 `data-demo` 下。以下两种命令显式设置 `NOTES_EXPORT_DIR=./data-demo/notes`，并清理宿主对演示默认值和附加模型的影响。不要在这个旧版体验实例中另行保存真实模型配置；当前候选的固定 mock 与附加模型禁用仍按上节说明。

### Bash

子 shell 会在结束后恢复外层终端的环境：

```bash
(
  set -e
  git clone --branch v0.6.0 --depth 1 https://github.com/B-tech-hub/zhiliao.git zhiliao-demo-v060
  cd zhiliao-demo-v060
  npm ci
  unset DEMO_MODE APP_PASSWORD SESSION_SECRET DATABASE_PATH UPLOAD_DIR
  for demo_prefix in LLM EMBEDDING VISION IMAGE REASONING; do
    unset "${demo_prefix}_BASE_URL" "${demo_prefix}_API_KEY" "${demo_prefix}_MODEL"
  done
  NOTES_EXPORT_DIR=./data-demo/notes PORT=3000 npm run demo
)
```

<a id="v060-source-demo-powershell"></a>

### PowerShell

在新开的专用 PowerShell 终端执行，结束体验后关闭该终端，不用它启动正式实例：

```powershell
git clone --branch v0.6.0 --depth 1 https://github.com/B-tech-hub/zhiliao.git zhiliao-demo-v060
if ($LASTEXITCODE -ne 0) { throw 'Demo 目录创建失败，请换一个新目录名。' }
Set-Location -LiteralPath zhiliao-demo-v060 -ErrorAction Stop
npm ci
if ($LASTEXITCODE -ne 0) { throw '依赖安装失败，请先排查错误。' }
$demoClearKeys = @('DEMO_MODE', 'APP_PASSWORD', 'SESSION_SECRET', 'DATABASE_PATH', 'UPLOAD_DIR')
foreach ($demoPrefix in @('LLM', 'EMBEDDING', 'VISION', 'IMAGE', 'REASONING')) {
  $demoClearKeys += "${demoPrefix}_BASE_URL", "${demoPrefix}_API_KEY", "${demoPrefix}_MODEL"
}
foreach ($demoKey in $demoClearKeys) {
  Remove-Item -LiteralPath "Env:$demoKey" -ErrorAction SilentlyContinue
}
$env:NOTES_EXPORT_DIR = './data-demo/notes'
$env:PORT = '3000'
npm run demo
```

按以上步骤首次启动时，数据库、上传与 Markdown 都在新 checkout 的 `./data-demo/` 中。先停止当前 Demo，再重置这个隔离目录；如果以前按旧命令运行过，先核对 `./data/notes` 的遗留导出，不能把只删除 `data-demo` 写成完整重置，更不能删除正式目录。上述命令本轮只做语法与文档检查，未实际克隆、安装或启动服务。

## 最短闭环：从登录到搜索

### 1. 登录

打开 `http://localhost:3000`（手机访问请使用 Tailscale 提供的 HTTPS 地址），输入当前实例的 `APP_PASSWORD`。

成功判据：进入首页，能看到主题列表或空状态，并能打开设置。

> Docker 主路径、Windows 命名卷例外和 HTTPS 前置条件见[部署手册](部署手册-tailscale.md)。不要把 `localhost` 地址发给手机使用。

### 2. 新建普通文本笔记

点击新建笔记，输入一段普通文本，例如“今晚羽毛球多球训练，杀球终于有点下压了”，然后点击保存或离开编辑器等待自动保存。

成功判据：笔记重新打开后正文仍在，并显示已保存或页面成功状态；不要用手机捕获 Token 或图片功能代替这一步。若保存失败，保留编辑内容，先排查网络/服务状态，不要刷新页面丢稿。

### 3. 等待并确认 AI 整理状态

保存后回到笔记详情，查看标题、标签、摘要和主题状态：

- 已配置文本模型：通常会从“待整理”进入整理中，再显示标题、标签、摘要和主题。
- 未配置文本模型：笔记仍已保存，状态保持“待整理”。到 **设置 → AI 服务** 配置模型后，旧笔记会自动补处理，也可在笔记页点击“重新处理”。

成功判据：正文没有被覆盖；AI 字段出现，或明确看到“待整理”而不是“保存失败”。

### 4. 打开主题

从笔记显示的主题名称进入主题页；如果 AI 置信度不足，笔记会留在“未分类”，这也是有效结果。

成功判据：主题页能看到刚才的笔记，正文和 AI 摘要可打开查看。

### 5. 完成一次搜索

在搜索框输入“羽毛球训练”或另一种说法（例如“杀球练习”），提交搜索；也可以先点主题再浏览该主题的笔记。

成功判据：结果中出现刚才的笔记。未配置 `EMBEDDING_*` 时搜索使用 BM25，仍应可用；配置后才会增加语义召回。

## AI 未配置或任务等待

### AI_NOT_CONFIGURED（教程内部标签）：一直“待整理”

1. 确认正文能重新打开，说明保存成功，不要删除或重建笔记。
2. 进入 **设置 → AI 服务**，填写接入点、模型和 API Key，点击“保存”与“测试连接”。API Key 只填在设置页或本机环境文件中，不写进文档、截图或日志。
3. 保存配置后等待队列补处理，最多先等 **5 分钟**；仍未变化时，查看任务状态并对单条笔记点击“重新处理”。

停止条件：没有模型账号、无法确认接入点或怀疑会触碰正式数据时先停在这里，保留笔记，联系维护者或查[部署手册 FAQ Q7](部署手册-tailscale.md#q7记了笔记ai一直不整理一直待整理或显示失败)。

### TASK_WAITING（教程内部标签）：用户可见“整理中”或“整理失败”

1. 在设置页检查 AI 服务配置和测试连接结果。
2. 检查任务状态；确认容器仍在运行，必要时在当前实例目录执行 `docker compose -f docker-compose.yml -f docker-compose.win.yml logs --tail 50`（Linux 可省略第二个文件）。
3. 修复配置或网络后，对该笔记执行“重新处理”，不要复制正文创建新笔记。

停止条件：等待超过 **5 分钟**、日志持续报同一错误，或无法判断哪个实例在运行时，停止重试并保留日志片段与笔记原文，按[部署手册 FAQ Q7](部署手册-tailscale.md#q7记了笔记ai一直不整理一直待整理或显示失败)处理。

## 安全边界与数据出口

- 正式实例的 `APP_PASSWORD` 是登录密码，`SESSION_SECRET` 是会话签名密钥，二者只属于当前实例的 `.env`；源码/Docker Demo 按上方对应版本和启动方式设置。不要将正式凭据写进截图、Issue 或共享模板，示例命令中的占位符不是可用密码。
- API Key、`capture:write` Token 和 `knowledge:read` Token 都是秘密。教程只说明入口，不要求真实 Key 才能完成首条普通文本笔记；手机捕获配置和吊销流程见[手机快捷记录](手机快捷记录.md)。
- Demo、正式和测试实例必须使用不同的数据目录、卷、端口与环境文件。停止服务后，清理只能针对当前 Demo project/volume；不要用 Demo 密码访问正式实例，也不要把正式备份导入测试环境后继续对外暴露。
- 备份用于灾难恢复，导出用于迁移与阅读；按[备份与恢复](备份与恢复.md#isolated-restore)核对同次数据库与完整图片快照，在独立目标先离线恢复。数据库会带回模型配置与任务，联网核验前先确认发送范围；健康检查、图片和 Markdown/ZIP 分别验收。遇到不确定的卷或 WAL 文件，不要直接删除。

完成首次闭环后，再按需要阅读[部署手册](部署手册-tailscale.md)、[手机快捷记录](手机快捷记录.md)和[备份与恢复](备份与恢复.md)的专项章节。
