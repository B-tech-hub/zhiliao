日期：2026-09-19。状态更新至 2026-09-28：core 回补及图片往返修复的 49 项局部回归保留；新候选已构建，run b 已执行浏览器矩阵本机通过，GFM 初始输入和全部请求日志仍有缺口，发布未完成。接续[9 月 18 日分诊与补丁](依赖告警分诊-2026-09-18.md)，保持单 Agent。

## 1. 结论与证据边界

**当前 `@tiptap/core 2.27.2` 的 helper 缺陷真实存在；静态追踪未发现知了现有入口满足该公告的完整利用前提。官方 v2 `2.27.3` 已包含对应回补，建议仅升级 core，补实际编辑器的定向回归。**

这不是全站 XSS 安全证明，也不是对现有 32 项告警的风险接受。当前源码与本机依赖仍未修复。实际编辑器、浏览器剪贴板和导入后重开尚无本次专项运行证据。

复用 9 月 18 日全量/生产审计的 **32 moderate、0 high、0 critical**，以及旧 helper/标准图片 schema 探针；不重跑审计或既有 65 项测试。当前包文件哈希与补丁记录一致：

## 2. 实际可达性

公告链为：不可信对象的**自有** `__proto__` 键 → `mergeAttributes` 普通赋值触发 setter → 返回对象继承攻击者属性 → ProseMirror `DOMSerializer` 用 `for...in` 枚举并设置 DOM 属性。它改变单个对象原型，旧探针没有修改全局 `Object.prototype`。

| 路径 | 实际数据边界与过滤位置 | 本轮判断 |
|---|---|---|
| 创建、更新、追加笔记；外部捕获；AI 新建/追加 | Route/工具 schema 接收 `content` 或 `text` 字符串；详情页把正文传给 `MarkdownEditor.value`，没有把请求对象作为扩展配置或属性包传入 | 未找到外部对象直达 helper 的通路；正文仍是不可信文本 |
| ZIP 导入与恢复后的笔记 | `import.ts:62` 分离 front-matter 与正文；约 `:295` 显式取元数据字段；`:356` 只将正文字符串及图片路径改写结果写入笔记。恢复后的正文也走详情页相同渲染入口 | YAML 对象不作为 TipTap 属性包；此判断不替代 ZIP/恢复运行验收 |
| 初次打开、外部正文同步 | `markdown-editor.tsx:420/:461`：字符串经公式占位转换、`tiptap-markdown` 的 Markdown → HTML，再交固定 ProseMirror schema | 任意 JSON 文本不会自动变成 TipTap JSON；`html: true` 不等于任意属性均保留 |
| Markdown 文本粘贴 | `handlePaste` 只接管图片文件；其他文本由 `MarkdownClipboard.clipboardTextParser` 解析，再经 `DOMParser.fromSchema(...).parseSlice` | 未找到任意属性包透传；尚未做真实组件粘贴专项 |
| HTML 粘贴、拖放 | 默认 ProseMirror 剪贴板/拖放解析仍经 schema。`data-pm-slice` **确实包含 JSON.parse 路径**，但其上下文通过 `type.create` 与 `computeAttrs` 按已声明属性名重建 | 不能声称“整个粘贴链没有 JSON”；当前 schema 仍过滤未知键，实际剪贴板需回归 |
| MathNode | 只声明 `latex/display`；`renderHTML` 自建 `data-math/data-latex/data-display/class` 对象 | 自定义扩展存在，但没有动态属性名或属性包展开 |
| RichImage | 继承 `src/alt/title`，增加 `width/align`；宽度映射固定键，align 只产生固定 style 字符串 | 不复制全部 HTML attributes；任意 `__proto__` 不进入渲染属性集合 |
| Link、表格、StarterKit | Link 仅声明 `href/target/rel/class`，其 URI 有独立校验；单元格仅 `colspan/rowspan/colwidth`；core `getRenderedAttributes` 仅合并已登记属性 | 未找到动态 schema；Link 配置常量不代表所有链接属性值恒定 |
| Mermaid 开关两态 | 开启时只替换 CodeBlock NodeView，保留 schema；`language` 不直接作为 HTML 属性包，图表使用 strict 模式 | 未找到本公告所需对象输入；不据此推断 Mermaid 自身所有风险已验证 |

关键实现：`node_modules/@tiptap/core/src/helpers/getRenderedAttributes.ts`、`injectExtensionAttributesToParseRule.ts`，以及 `node_modules/prosemirror-model/src/schema.ts:27`。后者仅遍历 schema 属性并创建无原型属性对象。`node_modules/prosemirror-view/src/clipboard.ts:261` 的 JSON 上下文路径已专门核对。

**单用户、登录和 Demo 限制不是本结论的安全依据。** 外来文档、剪贴板和模型正文仍可包含恶意内容；结论依赖当前固定 schema 和没有动态属性对象透传。一旦新增 JSON 文档导入、动态扩展或任意 `HTMLAttributes`，必须重新评估。

## 3. 新发现：官方 v2 已回补，但公告范围尚未反映

9 月 18 日记录“未获得 2.x 修复版证据”是当时取证边界。本次官方 registry 的 `v2-latest` 为 `2.27.3`，发布时间为 `2026-09-04T09:53:41.264Z`；进一步检查了精确版本的实际 npm tarball，而非只依据 tag 或版本号。

- [官方版本元数据](https://registry.npmjs.org/@tiptap/core/2.27.3)的 `gitHead` 为 `0ed4a30a6cda23799a01881f67d01ad218a2ac6d`。
- tarball 的 SHA-512 integrity 和 SHA-1 shasum 均与 registry 匹配；SHA-256 为 `a0ec99121a9f7e1dd8d476926596bb79423bff64860d3b6a230e6ed682398a7c`。
- `src/utilities/mergeAttributes.ts`、`dist/index.js`、`dist/index.cjs` 均含 `__proto__` 专门分支：在读取/普通赋值前，用 `Object.defineProperty` 定义自有数据属性并返回。
- helper 源码相对已安装 `2.27.2` 只增加这一保护分支；不据此声称整个 npm 包只有这一处变化。
- 实现与公告引用的[上游修复提交](https://github.com/ueberdosis/tiptap/commit/01d7af8c983ee5954c63734f4fa46cb23ae3246d)一致。修复允许结果保留自有 `__proto__` 数据键，验收应断言原型未改变、没有继承 DOM 属性，不能错误地要求该键必须消失。
- 锁文件中 31 条 core 消费约束为 `^2.7.0`、`^2.27.2` 或 `^2.0.3`，均接受 `2.27.3`；新 core 的 peer `@tiptap/pm ^2.7.0` 接受现有 `2.27.2`。这是元数据兼容，尚未做锁解析或运行验证。

针对单个候选版本 `2.27.3` 的 npm Advisory Bulk 查询仍返回 `GHSA-cp6q-959q-f8rh`，范围为 `>=2.0.0-alpha.0 <3.30.4`。因此安装回补后，版本扫描可能继续报告 TipTap 链。应保留原始审计与补丁行为证据，注明公告范围与发布产物不一致；不能宣称告警已清零，也不在修复前把当前 `2.27.2` 标为误报。该单包查询不是新一轮工作区全量审计。

原始元数据、补丁提交、产物片段、哈希和单包公告响应见[本次证据](验收证据/tiptap-investigation-20260919/README.md)。没有安装或执行下载包。

## 4. 推荐处置与影响范围

方案待确认，具体任务见[实施草稿](../_bmad-output/implementation-artifacts/spec-r1-tiptap-residual-risk.md)。

1. 在 `package.json` 增加精确 override：`"@tiptap/core": "2.27.3"`，通过临时包文件副本更新锁文件。审核只变动 core 及根元数据，再应用；若 npm 需要额外升级，先回报差异，不自动扩大。保持已有 PostCSS/Sharp override。
2. 使用官方包，安装禁用生命周期脚本。验证所有 core 实例均为 `2.27.3`，ESM/CJS 实际入口包含并执行保护逻辑。保留 TipTap 扩展、pm、`tiptap-markdown 0.8.10`、React、其他依赖和应用版本 `0.6.1`。
3. 新增 helper → DOMSerializer 和实际 `MarkdownEditor` 的定向回归；复用现有数学、Mermaid 测试。测试使用惰性标记、禁用外部网络、隔离数据；不复制一套“近似扩展”作为唯一安全证据。
4. 追加修补后证据，同步依赖分诊、文档索引、发布执行清单、Release Notes 和 CHANGELOG。当前调查只更新分诊链接与调查索引，不提前写“已修复”。

主要风险是编辑器渲染/Markdown 往返兼容、解析锁文件时带入范围外升级，以及公告继续命中的误判。此次不需要更改数据库、API 契约、正文格式、图片属性策略或关闭 HTML；v3 迁移及自行维护补丁没有当前必要性。

## 5. 拟议验收标准

- **Given** JSON 自有 `__proto__` 及普通 class/style 属性，**When** 经实际 ESM/CJS helper 与 DOMSerializer，**Then** 返回对象保持正常原型，无继承 canary/事件属性进入 DOM，正常合并行为保留；断言需能在旧 `2.27.2` 上检出问题。
- **Given** 真实编辑器及恶意属性样本，**When** 初次加载、setContent、文本/HTML 粘贴、带 `data-pm-slice` 上下文的粘贴和文本/HTML 拖放，**Then** 图片、公式、链接、表格及 Mermaid 两态均不产生继承攻击属性；成功解析并保留正常正文，不能以丢弃全部内容换取通过。
- **Given** 含宽度/对齐/说明的图片、公式、GFM/HTML 回退表格、链接及代码围栏，**When** 保存再重开、再次保存，**Then** 相关语义和源码保持，无新增静默丢失。复用导入解析后的正文作为输入；实际 ZIP/恢复闭环仍归 R2。
- **Given** 批准的包文件变化，**When** 核对锁文件、安装树、版本与目标 lint，**Then** 只升级 core，无未修复 core 副本、无 peer 冲突，应用仍为 `0.6.1`；全量/生产审计如仍命中同一公告，逐项关联回补证据，新增公告另行分诊。
- **Given** 旧运行证据，**When** 交付修补记录，**Then** 不将其改记为新依赖的运行证明。新候选、真实浏览器、R1/R2、完整门禁与发布仍须另行明确范围并确认。

本轮未运行产品测试、build、全量测试、Docker、真实浏览器、模型、恢复或发布；未实施补丁，未授予风险豁免。只进行了源码追踪、已有证据核对、官方只读查询与调查材料落盘。

## 6. 已批准实施与局部验证

用户确认原方案后，仅将 `@tiptap/core` 通过精确 override 固定为 `2.27.3`；在临时包文件副本中解析、核对再应用，安装禁用生命周期脚本。锁文件仅 1 个包条目变化，依赖包数保持 875；本机安装也只变更 core。31 条消费关系全部指向 `2.27.3`，无 peer 冲突；752 个已安装包版本核对仅 core 改变，SQLite/jieba 原生文件哈希保持。源码与 ESM/CJS 完整文件哈希均匹配本次调查校验过的官方 tarball。

升级前新增测试检出两类问题：helper 的 12 项回归中 8 项失败；实际组件的 20 项回归中 16 项通过、4 项失败，失败为 Mermaid 两态下的图片属性丢失及图片相邻表格损坏。这是现有图片序列化实现不符合 ADR-0002，并非 core 升级引入。用户另行批准将其纳入后，在 `RichImage` 增加最小 Markdown 序列化：宽度/对齐图片通过 schema 输出转义后的 HTML，普通图片沿用 Markdown，块级图片正确分隔。不添加依赖或数据迁移；已丢失的旧图片属性无法由此自动找回。

| 局部验证 | 结果 |
|---|---|
| ESM/CJS helper 与 DOMSerializer | 12/12 通过；旧版对照的 8 项失败已消除 |
| 实际 MarkdownEditor | 26/26 通过；包含原 20 项及普通图片、仅对齐/仅宽度转义在 Mermaid 两态下的 6 项；无跳过 |
| 既有数学 / Mermaid 回归 | 3/3、8/8 通过 |
| 目标 ESLint / 局部 TypeScript | 3 个变更源码/测试文件通过，lint 无警告；类型检查仅从这 3 个文件及其导入展开 |
| 版本校验 | 通过，应用仍为 `0.6.1` |
| 全量锁文件审计（02:57:01–02:57:08 UTC） | 32 moderate、0 high、0 critical |
| 生产锁文件审计（02:57:08–02:57:14 UTC） | 32 moderate、0 high、0 critical |

49 项测试使用单 worker，没有重跑前一轮无关的 65 项回归。ESM/CJS 使用各自实际包入口；组件测试挂载真实 `MarkdownEditor`，不替换扩展、schema、剪贴板解析或事务。jsdom 只固定拖放坐标，并将 Mermaid SVG 绘图器替换为固定结果；因此不代表真实浏览器剪贴板、布局、完整 Mermaid SVG 或生产渲染通过。测试在内存库/临时目录环境运行，组件显式禁止 fetch，没有执行事件载荷。

**处置结论：官方 v2 回补已应用，公告对应的继承属性缺陷在本机双模块入口验证通过。** 两次审计仍以退出码 1 返回有效 JSON，32 项全部归于同一公告的宽版本范围；不是 32 个已证实可利用路径，也没有将原始告警隐藏或宣称清零。若出现旧 core、额外公告、动态属性对象入口或新的 schema，再按实际证据分诊。

当前包文件 SHA-256：`package.json` 为 `8e0d7f1d8f8a80eec1faccffce59439ebf448b4e4e18599cfb8aa8abab69a4f8`；锁文件为 `ec395b6392eae245af76f37d75dd6e1dd5465915884f38c985e479928df49fd6`。命令、旧版失败、修补后报告、范围核对及单 Agent 自审见[实施证据](验收证据/tiptap-patch-20260919T024351Z/README.md)。

## 7. 真实浏览器已有结果与收尾核对（2026-09-28）

[run b](验收证据/tiptap-browser-061-20260928-b/README.md)复用 R2 的本机 linux/amd64 候选，在 Mermaid 关闭和开启时各执行一次，合计 14 项检查通过（含两次登录）。宽度 50% 并居中、仅宽度 75%、仅右对齐、普通 Markdown 图片、图片紧邻 HTML 表格后编辑导出为 GFM，以及所列危险属性的渲染均有已执行断言和截图。未处理页面错误、异常响应、额外写请求、模型请求和弹窗数组为空；刻意引用的非法图片名返回 400，单列为预期响应。

本次只核对已有证据：报告与正文摘录一致，12 张截图齐全，抽查居中、右对齐和表格可见；候选 276 文件匹配，资源前后快照一致，运行时工具与归档匹配，临时凭据值在归档中无命中。run a 的 404 预期错误与失败证据保留。

**该结果不关闭原浏览器规格。** 原规格指定 GFM 初始表格，实际种子是 HTML 表格；正常 GET/HEAD 与登录也未逐请求归档，不满足“所有浏览器请求都要记录”。因此规格保持 `in-progress`，后续按最小范围补验，详见[收尾核对](验收证据/tiptap-browser-061-20260928-b/closeout-review.md)。危险属性原文仍存于数据库，证明的是渲染过滤，不是存储清洗、剪贴板专项或全站 XSS 安全。

公告审计继续引用 9 月 19 日的 32 moderate、0 high/critical，本轮未重跑审计。R2 同版本恢复和升级回退已另有本机通过证据；独立 Linux、arm64、无缓存分发、RC 和完整发布门禁仍待完成，见[R3 清单](产品规划/开源发布范围与执行清单-2026-09-13.md#r3-remaining-gates)。
