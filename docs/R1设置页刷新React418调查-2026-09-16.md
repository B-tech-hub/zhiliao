## 2. 代码因果链与假设

1. `src/lib/backup.ts:34` 在启动五分钟后安排首次备份；`getLastBackupAt():40` 读取数据库备份文件的 mtime。
2. `src/app/(app)/settings/page.tsx:72` 把时间戳作为 `lastBackupAt` 传给客户端组件。
3. `settings-panel.tsx:290` 的 `DataSection` 用该值初始化 state；第 366 行在服务端预渲染和浏览器首次渲染时都直接调用 `formatTime(backedUpAt)`。`"use client"` 不会取消首次请求的服务端预渲染。
4. `src/components/note-card.tsx:12–20` 同时读取本地时区与 `new Date()`：当日显示时分、同年显示月日、跨年显示年月日。输入时间戳相同不足以保证首帧文字相同。

| 假设 | 判断 |
|---|---|
| 已有备份 + 服务端/浏览器时区不同 | 内存中已复现具体文本节点差异；原容器 UTC、备份先于刷新，与现场高度吻合。原浏览器实际时区仍缺证据 |
| 同一时区但 SSR 与水合跨午夜/跨年 | 跨午夜已复现；属于同一函数依赖当前日期的边界问题，原 02:24 事件没有跨午夜证据 |
| 外观或侧栏偏好导致文字不同 | 当前外观已有 mounted 守卫，侧栏初值固定、挂载后对齐；未发现比备份时间更直接的证据 |
| 静态资源 503 是 #418 的必要原因 | 内存对照没有网络请求仍产生文本水合错误，因此它不是该代码缺陷的必要条件 |

不要把修改服务器 TZ、扩散 `suppressHydrationWarning` 或关闭整页 SSR 当成修复。需要让服务端与浏览器首次渲染共享确定的文字。
