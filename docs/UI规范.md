# 知了 UI 规范

版本：v1.0  
日期：2026-08-30  
适用范围：知了 Web、PWA、桌面浏览器与移动浏览器界面  
状态：App UI 唯一执行规范

## 一、规范定位

本规范把产品视觉 PRD、现有源码 token、布局契约和交互经验整理为可直接实施和审查的 UI 标准。

规范职责分工：

- 产品定位、用户目标、路线与候选功能以 [知了产品视觉 PRD](产品规划/知了产品视觉PRD-v1.0.md) 为准。
- 工程流程、数据、安全与验证以 [开发规范](开发规范.md) 为准。
- 页面视觉、组件、状态、响应式、键盘与焦点以本文为准。
- [DESIGN.md](DESIGN.md) 是 Apple 视觉研究和历史实现记录，不再作为 App 页面模板。

源码与本文不一致时，不在无关任务中做全站重构。新增和被修改的界面必须遵守本文；历史差异登记为兼容债务并逐步收敛。

## 二、体验方向

知了是面向个人知识工作者的编辑器优先型工具，不是营销页、企业后台或彩色 AI 仪表盘。

界面应当表现为：

- 安静：内容比品牌装饰更突出。
- 工具化：常用动作位置稳定，支持重复操作和键盘使用。
- 高密度但可扫描：一屏能看到足够多的主题和笔记，不用大卡片稀释信息。
- 可信：保存、AI 状态、来源边界、错误和数据出口清楚可见。
- 克制：单一行动色、有限圆角、少量动效，不用渐变和装饰性视觉。

禁止把知了做成：

- 大幅摄影、超大 Hero、低密度整屏营销区块。
- AI 紫色渐变、发光边框、彩色数据看板。
- 一层层悬浮卡片和卡片内再套卡片。
- 以功能介绍代替可直接使用的第一屏。
- 类企业后台的多级侧栏、顶部指标和复杂筛选台。

## 三、产品级 UI 不变量

1. 默认界面只突出“记、找、用”。
2. 桌面端保留左侧导航、主内容、AI 助手第三栏。
3. 移动端保留底部导航，AI 助手使用全屏层，快速记录使用整页。
4. 未分类是唯一强视觉焦点，不与多个彩色模块竞争。
5. AI 失败不能阻止保存和编辑，状态必须可见且可恢复。
6. 普通会话与来源问答的边界必须持续可见。
7. 删除笔记进入回收站；危险操作使用明确文案和确认。
8. 页面行为变化必须同步产品视觉 PRD、本文和相关测试。

## 四、信息架构与布局

### 4.1 桌面结构

```text
┌──────────────┬──────────────────────────────┬──────────────────┐
│ 左侧导航     │ 主内容                       │ AI 助手第三栏    │
│ 256 / 56px   │ min-width: 0                 │ 420 至 900px     │
│ 一屏高度     │ 页面内容独立滚动             │ 默认 560px       │
└──────────────┴──────────────────────────────┴──────────────────┘
```

- 左侧栏展开宽度 256px，折叠宽度 56px。
- 主内容必须使用 `min-w-0 flex-1`，保证三栏同时打开时不产生横向滚动。
- 普通页面内容最大宽度 980px；笔记详情宽屏画布最大宽度 1440px。
- 正文排版使用 `.prose-note`，可读宽度上限 40em。
- AI 助手宽度范围 420 至 900px，默认 560px；打开时推窄主内容，不覆盖主内容。
- 左侧栏和助手栏使用一屏高度并独立滚动，不能被长正文拉高。

### 4.2 移动结构

```text
┌──────────────────────────────┐
│ 页面标题与主内容             │
│                              │
│                    快速记录  │
├──────────────────────────────┤
│ 主题   搜索   未分类   设置  │
└──────────────────────────────┘
```

- `md` 以下进入移动结构，不保留桌面侧栏和第三栏。
- 底部导航固定，页面底部必须预留安全区域和内容间距。
- AI 助手、命令面板和来源选择器使用全屏或适合小屏的覆盖层。
- 快速记录跳转 `/notes/new` 整页，不在软键盘上方塞入半屏编辑器。
- 所有页面禁止横向滚动；表格、代码和公式在自身容器内横向滚动。

### 4.3 布局稳定性

- 固定格式控件使用明确尺寸、网格轨道或 `aspect-ratio`，状态变化不得推动周围布局。
- 加载骨架匹配最终布局，避免标题、列表和输入区跳动。
- 响应式优先用 CSS 断点，不用客户端宽度判断决定首帧结构。
- 服务端无法读取的本地偏好，应在首帧前写入根元素属性，避免水合后跳动。
- 设置页“最近备份”已有时间戳时，服务端与浏览器首帧统一显示时间占位 `—`，挂载后按浏览器本地时间显示；仅时间文字延后，其余内容和操作保留。没有备份时显示“从未备份”，不能用这句话代替已有备份的占位。跨时区与桌面/手机视口证据见 [R1 专项验收](R1安装验收-2026-09-15.md#settings-hydration-browser)。
- 页面区块保持无框或使用分隔线，不把每个区块包成浮动卡片。

## 五、设计 token

### 5.1 颜色

颜色定义在 `src/app/globals.css`，组件只使用语义类，不直接写十六进制颜色。

| Token | 亮色 | 暗色 | 用途 |
|---|---|---|---|
| `action` | `#0066cc` | `#2997ff` | 链接、选中、焦点和明确行动 |
| `action-focus` | `#0071e3` | `#409cff` | 聚焦反馈 |
| `cta` | `#1d1d1f` | `#f5f5f7` | 默认主行动底色 |
| `cta-ink` | `#ffffff` | `#1d1d1f` | 主行动文字 |
| `ink` | `#1d1d1f` | `#f5f5f7` | 主文字 |
| `ink-80` | `#333333` | `#d1d1d6` | 次级文字 |
| `ink-48` | `#7a7a7a` | `#98989d` | 辅助说明和元信息 |
| `parchment` | `#f5f5f7` | `#000000` | 页面底色 |
| `surface` | `#ffffff` | `#1c1c1e` | 内容面、编辑器、弹层 |
| `fill` | `#f5f5f7` | `#2c2c2e` | chip、代码块、输入内填充 |
| `hairline` | `#e0e0e0` | `#38383a` | 边框 |
| `divider` | `#f0f0f0` | `#2c2c2e` | 分隔线 |
| `danger` | `#ff3b30` | `#ff453a` | 删除和错误 |
| `danger-tint` | `#fff2f1` | 半透明危险红 | 危险浅底 |
| `chrome` | `#1d1d1f` | 同值 | 左侧栏、主题不变暗面 |
| `tile` / `tile-2` | `#272729` / `#2a2a2c` | 同值 | 内容区唯一暗色焦点 |
| `sky` | `#2997ff` | 同值 | 暗面链接 |

硬规则：

- 不新增第二套强调色。
- 不使用 AI 紫色、渐变、彩色仪表盘或装饰性色块。
- 内容区禁止裸 `bg-white`、低透明度 `bg-black` 和硬编码语义色。
- `text-white` 和透明白只允许在主题不变暗面、行动按钮和遮罩等明确场景。
- 状态不得只靠颜色表达，必须同时使用文字、图标或结构变化。

### 5.2 字体与字阶

| Token | 大小 | 字体 | 用途 |
|---|---:|---|---|
| `text-display` | 34px | serif | 页面级大标题 |
| `text-title` | 22px | sans | 区块标题、重要弹层标题 |
| `text-body` | 17px | sans | 正文与主要输入 |
| `text-ui` | 15px | sans | 列表标题、按钮、表单 |
| `text-meta` | 13px | sans/mono | 摘要、时间、辅助说明 |
| `text-micro` | 11px | mono | 标签、角标和紧凑元信息 |

字体栈：

- 正文与 UI：Inter Variable、Noto Sans SC Variable、系统无衬线。
- 页面大标题：Instrument Serif、Noto Serif SC Variable，仅用于不小于 24px 的页面标题。
- 元信息、数字、代码和键帽：JetBrains Mono Variable、系统等宽字体。

规则：

- 新增或修改的界面只使用六级字阶，不新增 `text-[Npx]`。
- 正文使用 400，强调和标题使用 600；不依赖大量字重制造层级。
- `letter-spacing` 统一为 0，不新增负字距或营销式宽字距。
- 当前源码中的负字距和任意字号是历史兼容债务；本次规范不触发全站重写，但被修改组件应在不扩大范围的前提下收敛。
- 不按视口宽度连续缩放字号；响应式只在固定断点切换既定层级。

### 5.3 圆角

| Token / 类 | 值 | 用途 |
|---|---:|---|
| `rounded-card` | 12px | 弹层、卡片和大容器 |
| `rounded-utility` | 8px | 按钮、输入框和小容器 |
| `rounded-chip` | 4px | 标签、筛选、内联代码和键帽 |

- `rounded-full` 只用于真实圆形 FAB、圆形图标按钮和计数角标。
- 禁止新增 `rounded-[Npx]`。
- 卡片不嵌套卡片；页面分区优先无框、留白和分隔线。
- 12px 是现有设计系统对卡片和弹层的明确例外，普通控件不得使用更大圆角。

### 5.4 间距与尺寸

- 以 4px 为基础单位，优先使用 4、8、12、16、24、32、48px 节奏。
- 控件内部间距保持紧凑，页面和区块间距可以更大，但不得用大面积空白模拟营销页。
- 任意尺寸只允许用于稳定布局契约，例如 980px 内容宽度、40em 正文宽度、助手栏范围和 `min()` 计算。
- 按钮、图标按钮、列表行和移动点击目标最小 44 × 44px；紧凑桌面工具项必须仍有清晰焦点和足够可点区域。
- 文本必须在容器内换行、截断或使用明确最大宽度，不得与按钮、图标和相邻内容重叠。

### 5.5 边框与阴影

- 内容层级优先用底色、分隔线和留白表达。
- 普通卡片、列表和按钮不使用装饰阴影。
- 阴影只允许用于需要脱离页面层级的弹层或浮层，并保持克制。
- 当前个别 `shadow-2xl` 是历史实现，新代码不得复制；被修改弹层应优先使用边框、遮罩和较轻阴影。

## 六、组件规范

### 6.1 按钮

| 类型 | 样式 | 用途 |
|---|---|---|
| 主按钮 | `bg-cta text-cta-ink rounded-utility` | 页面唯一主要提交动作 |
| 暗面主按钮 | `bg-action` 配合合适文字色 | 主题不变暗面上的行动 |
| 次按钮 | `bg-fill text-ink-80 rounded-utility` | 取消、次要操作 |
| 危险按钮 | `bg-danger` 或危险文字 | 删除、彻底清除 |
| 图标按钮 | 固定方形、明确 `aria-label` | 关闭、折叠、撤销等熟悉动作 |

- 每个局部区域只保留一个明显主操作。
- 保存、删除、下载等熟悉命令优先使用图标或图标加文本，不使用含糊的胶囊文本按钮。
- 未熟悉图标提供 tooltip 和可访问名称。
- 不在业务组件继续散落新的手写 SVG。现有图标优先集中复用；批准引入图标库时使用 `lucide-react`。
- 按压反馈可使用 `active:scale-95`，不得改变控件布局尺寸。
- 禁用态必须同时禁止事件并呈现明确视觉状态。

### 6.2 输入、选择和设置控件

- 文本输入使用 `rounded-utility`、语义底色和可见焦点。
- 布尔设置使用开关或复选框，不使用两个文字按钮模拟开关。
- 模式切换使用分段控制；互斥选项使用单选或选择器。
- 数值使用输入、步进器或滑杆，不使用多个自由文本字段拼接。
- 可选主题、模型和权限范围使用选择器或菜单。
- 密钥默认隐藏，明文只在必要时短暂显示；不得放进 placeholder 示例。
- `outline-none` 必须配套可见的 `focus-visible` 样式，不能删除焦点后不补替代。

### 6.3 标签和状态

- 标签使用 `rounded-chip`，字号使用 `text-micro` 或 `text-meta`。
- 标签用于分类和状态，不把所有辅助文字都做成 chip。
- 状态文案使用稳定口径，例如“待整理”“AI 整理中”“整理失败”“已跳过”。
- 危险、失败和未分类计数可以使用危险色，但不能让整页变红。

### 6.4 卡片、列表和页面分区

- 卡片只用于独立重复项、弹层和确实需要边界的工具。
- 页面区块不包成浮动卡片；设置页采用页面内分区和分隔线。
- 笔记列表优先标题、摘录、主题、标签和时间的扫描效率。
- 未分类暗色瓷砖是首页唯一强焦点，普通主题保持安静高密度。
- 卡片内部禁止再嵌套视觉卡片；操作区用分隔线、底色或留白处理。

### 6.5 弹层与覆盖层

- 桌面端命令面板和确认弹窗可居中；移动端确认弹窗可底部弹出。
- AI 助手桌面端不是模态，不使用遮罩和点外关闭。
- 覆盖层使用 `role="dialog"`、`aria-modal="true"` 和可访问名称。
- 打开后把焦点交给第一个主要输入或操作；关闭后归还唤起元素。
- 焦点已被新层接管时，旧层不得抢回焦点。
- 遮罩点击关闭必须保留用户输入；进行中的危险操作不得因误点关闭。
- 使用 Portal 前先判断祖先 transform 是否会改变 `fixed` 定位，不机械套用。

### 6.6 正文排版

笔记编辑器和助手回答共用 `.prose-note`：

- 中文正文可读宽度约 40 字。
- 标题上间距大于下间距，表达标题属于后续内容。
- 段落、列表、引用、表格、代码和图片保持一致节奏。
- 表格、代码、公式和 Mermaid 失败时保留源码或显示原因。
- 助手回答不套聊天气泡式正文容器；用户消息可使用受控气泡。
- 引用链接必须可打开真实笔记，不渲染伪造 ID。正式标记是 `[^笔记id]`；模型若写成 `[^noteId:真实id]`，只要 id 在白名单内，也渲染成同一条链接。

## 七、状态、错误与文案

### 7.1 状态层级

所有异步流程至少考虑：

- 初始。
- 加载或处理中。
- 成功。
- 空数据。
- 可恢复失败。
- 权限或配置受限。
- 降级运行。

加载状态尽量匹配最终布局；不可用功能说明原因和下一步，不只置灰。

### 7.2 错误文案

错误文案结构：

```text
发生了什么 + 用户当前数据是否保留 + 下一步动作
```

推荐：`保存失败，正文仍保留在当前页面，请检查网络后重试。`  
不推荐：`Error`、`操作失败`、`未知错误`。

- 网络失败保留输入。
- 模型未配置时仍允许保存，显示“待整理”及配置入口。
- 来源不足是正常回答状态，使用“来源笔记中没有相关内容”。服务端保证最终回答里出现这句，不依赖模型是否原样照抄。
- 不宣称“AI 绝不出错”，应表达“来源边界可见、引用可核验、资料不足时拒答”。

### 7.3 空态

- 只放一句解释和一个主操作。
- 不使用大插画、功能列表或营销文案填充空白。
- 空搜索不建议开启无关 AI 功能。
- 空库优先引导创建第一条真实笔记。

### 7.4 产品文案

- 使用普通用户语言，不要求先理解 Docker、Embedding、RRF、WAL 等术语。
- 技术术语出现时同步给出用户影响和成功标志。
- 按钮使用明确动作，例如“保存”“重新处理”“移入回收站”。
- 页面内不展示设计说明、快捷键清单或功能营销；快捷键通过 tooltip、菜单或帮助文档按需提供。
- PWA 只描述为“添加到主屏幕，当 App 使用”，不称完全离线或原生客户端。

## 八、键盘、焦点与层级

### 8.1 基础快捷键

| 快捷键 | 行为 |
|---|---|
| `Cmd/Ctrl + K` | 打开命令面板 |
| `Cmd/Ctrl + \` | 折叠或展开侧栏 |
| `Cmd/Ctrl + J` | 打开或关闭 AI 助手 |
| `Cmd/Ctrl + S` | 强制保存当前笔记 |
| `Cmd/Ctrl + Enter` | 在助手输入框发送 |
| `Esc` | 关闭当前最上层可关闭界面 |

- 编辑器和输入框中的普通按键不得被全局监听抢占。
- `Esc` 一次只关闭一层，不能同时关闭浮层和助手。
- 多层监听必须使用明确的捕获、冒泡和让路规则。

### 8.2 焦点契约

- 打开命令面板后焦点立即进入搜索输入。
- 对话框使用焦点约束；关闭后归还唤起元素。
- 使用 Portal 的延迟挂载组件通过 callback ref 聚焦，不依赖节点尚未存在时的 effect。
- 新层已取得焦点时，旧层卸载不得把焦点抢回。
- 所有交互元素支持键盘到达和激活，并使用可见 `focus-visible`。

### 8.3 层级建议

| 层级 | 用途 |
|---|---|
| 页面 | 普通内容 |
| `z-10` | 移动底部导航 |
| `z-20` | 快速记录和助手入口 |
| `z-30` | 手机 AI 助手全屏层 |
| `z-40` | 快速记录浮层 |
| `z-50` | 命令面板、确认弹窗和最高层对话框 |

新增层级前先核对现有栈，不使用任意极大 z-index 解决局部问题。

## 九、无障碍

- 使用语义 HTML；链接用于导航，按钮用于动作。
- 图标按钮提供 `aria-label`，装饰图标使用 `aria-hidden`。
- 异步保存、AI 状态和错误使用适当的 `aria-live`。
- 对话框提供角色、名称和焦点管理。
- 文字和背景满足 WCAG AA 对比度；状态不只依赖颜色。
- 触控目标原则上不小于 44 × 44px。
- 折叠导航的图标必须保留可访问名称；有意不可达的内容同时从视觉和无障碍树隐藏。
- 尊重浏览器缩放和系统字体设置，200% 缩放下不得遮挡主要操作。
- 图片编辑和预览提供有意义的替代文本或上下文说明。

## 十、响应式规则

### 10.1 断点策略

- 使用 Tailwind 既有断点，主要结构切换发生在 `md`。
- 断点是离散布局选择，不用 `vw` 连续缩放字体。
- 桌面、窄桌面和手机都必须保证主输入、保存、返回和错误恢复可用。

### 10.2 桌面

- 左栏、正文和助手三栏可同时存在。
- 正文使用 `min-w-0`；助手栏调整宽度时不覆盖输入区或 FAB。
- 宽屏笔记页可以显示目录和相关笔记，但正文宽度不被无限拉长。

### 10.3 移动

- 底部导航不遮挡内容和按钮。
- 软键盘出现时，主要输入与发送/保存动作仍可见或可自然滚动到。
- 表格、代码、公式在局部滚动，不扩大页面宽度。
- 不把桌面三栏压缩成三个窄栏。
- 文本、按钮和标签在 320px 宽度仍不重叠。

## 十一、动效

- 动效只服务于状态反馈、打开关闭和页面切换。
- 页面进入可使用现有约 240ms 淡入上移；控件按压可使用轻微缩放。
- 不使用持续漂浮、视差、滚动堆叠、装饰粒子和大面积过渡。
- 动效不得改变固定工具栏、输入区、计数器和列表行的稳定尺寸。
- 使用 `motion-reduce` 或媒体查询尊重 `prefers-reduced-motion`。
- 加载状态避免无限旋转成为唯一反馈，长任务同时显示当前阶段或可取消动作。

## 十二、页面级验收

| 页面 | 必须保持 | 重点检查 |
|---|---|---|
| 登录 | 私有实例、单密码入口 | 错误、限流、demo 说明，不出现注册 |
| 主题首页 | 未分类置顶、普通主题高密度 | 空库主操作、无营销指标 |
| 快速记录 | 正文第一焦点、主题可选 | 草稿保留、保存反馈、移动整页 |
| 主题详情 | 标题、数量、笔记列表、来源提问 | 删除说明、列表扫描效率 |
| 笔记编辑器 | 自动保存、正文、AI 状态 | 宽屏可读性、失败隔离、回收站 |
| 搜索 | 输入、主题筛选、结果摘录 | 300ms 防抖、降级原因、无结果空态 |
| 未分类 | 选择、批量移动、主题建议 | 分析失败不清空、建议可排除 |
| AI 助手 | 第三栏/全屏、会话和输入 | 来源边界、引用、撤销、删除确认 |
| 设置 | 页面内分区 | 不增加后台侧栏、危险操作清楚 |
| 回收站 | 恢复、彻底删除 | 保留期说明、危险确认 |

## 十三、设计门禁与验证

### 13.1 自动门禁

运行：

```bash
npm run check:design
```

当前门禁检查：

- 内容区裸色和硬编码语义色。
- `ink` 被错误用作背景。
- 任意圆角。
- `rounded-full` 非法扩散。
- 平台静态颜色和冻结 Mermaid 行的精确例外。

门禁尚未自动覆盖字号、字距、焦点、对比度、嵌套卡片和响应式。这些仍需代码审查、组件测试和截图验收。

### 13.2 最小截图矩阵

涉及 UI 的改动至少检查：

| 视口 | 主题 | 用途 |
|---|---|---|
| 1440 × 900 | 浅色 | 桌面主布局与内容密度 |
| 1440 × 900 | 深色 | token、层级与对比度 |
| 1024 × 768 | 任一 | 窄桌面三栏与文本适配 |
| 390 × 844 | 浅色 | 移动导航、输入和软键盘路径 |
| 390 × 844 | 深色 | 移动暗色与覆盖层 |

按改动范围补充 320px 宽度、浏览器 200% 缩放、长标题、长标签、空数据和错误状态。

### 13.3 交互验收

- 鼠标、键盘和触摸均可完成核心动作。
- `Tab` 顺序合理，焦点清晰。
- `Esc` 一次只退出一层。
- 网络失败后输入仍在。
- 助手打开不遮挡正文，移动端不出现横向滚动。
- 浅色和深色下文字、边框、填充和危险状态均可辨识。

## 十四、历史兼容与增量治理

当前源码存在以下历史差异：

- `text-[Npx]`、`tracking-[负值]` 和任意行高。
- 个别弹层使用较重阴影。
- 图标以分散的手写 SVG 为主。
- Mermaid NodeView 有一条精确圆角例外。
- 部分组件缺少统一 `focus-visible` 表现。

处理规则：

1. 不在纯文档或无关修复中发起全站视觉重写。
2. 新代码不得复制历史差异。
3. 修改某个组件时，只在该组件范围内收敛可安全处理的差异。
4. 高风险编辑器、Mermaid 和焦点链路需独立任务、复现和回归。
5. 扩大设计门禁前先清理现有命中，不能直接加入宽泛白名单。

## 十五、UI 完成定义

UI 改动完成时必须满足：

1. 服务于已批准需求，没有借视觉优化增加新功能。
2. 保留桌面三栏、移动底栏和核心信息架构。
3. 使用语义颜色、六级字阶、三级圆角和稳定间距。
4. 没有新增渐变、重阴影、嵌套卡片和装饰动画。
5. 加载、空态、成功、错误、权限和降级状态完整。
6. 键盘、焦点、点击目标、对比度和 `aria` 满足要求。
7. 关键桌面/移动、浅色/深色视口完成截图检查。
8. 相关组件测试、产品视觉 PRD、本文和设计门禁同步。
9. 未执行的浏览器或真机验证已明确说明。
