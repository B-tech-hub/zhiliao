- (technique) started Laddering
- (insight) 阶梯 1：不同人群（码农 vs 考研学生）需要的 agent 提示词不同，用户应能按自己的需要调整 agent
- (idea) 一个人的知识库横跨多个领域，可用同一个大模型调配出多个 agent，分别更好地控制知识库的不同部分
- (insight) 阶梯 2（考研学生场景）：模糊地问一道记过的数学题型时，调过的 agent 比默认助手更懂他当下要什么；并能以数学老师的身份、更专业的思路和知识框架作答并梳理知识
- (insight) 阶梯 3：底层收益是对自己记录内容的理解更深——花少量时间调一次，后续取用更省力；默认助手只能给千篇一律的回答
- (insight) 习惯差异的具体例子：遇到难题时，有人喜欢被引导着解，有人喜欢让 agent 直接给答案
- (insight) 阶梯封顶（真正的需求）：用户需要的是「一个专业的、适合他的人」——句子里已不含 agent / 提示词，提示词编辑只是抵达它的一种手段
- (idea) 顶层发想 1：知识关联功能——用户自主把知识点关联起来
- (idea) 顶层发想 2：来源问答（注：知了已有来源问答/严格接地，待用户说明设想版本与现状的差异）
- (insight) 好老师的三个特点：对知识和做题方法有一套完整理论；一步一步教、内容详细；用他的知识框架带着我一步步攻克难题
- (direction) 用户判断：这三个特点应该都能用提示词做到
- (idea) 知识框架的来源可以有四处：由用户的笔记倒逼生成提示词；用户脑子里的方法；用户记在笔记里的方法；网上流行的教学方法。具体形态未定，也可交给用户自己设计
- (technique) started SCAMPER
- (direction) 2026-09-18 恢复会话：用户要求继续 2026-09-16 的自定义提示词与知识库 Agent 讨论，从 SCAMPER 接续；沿用原 facilitator 引导模式。
- (idea) SCAMPER 替代：设计一个“制造老师”的 skill，引导用户回答一些问题，再根据回答创作出这个“老师”的提示词，以问答替代用户直接编写提示词。
- (direction) “制造老师” skill 的具体问答方式尚待设计，用户目前还没有想好。
- (technique) started SCAMPER — Combine（组合）
- (idea) SCAMPER 组合：用户手动链接两个笔记或两个知识点，并将关联告诉专业老师；后续提问涉及其中一项时，老师反馈与之关联的其他内容或知识点。
- (idea) SCAMPER 组合的泰勒展开场景：专业老师解答一道泰勒展开题时，同时给出其他常见函数的泰勒展开，扩展相关知识。
- (idea) 专业老师从用户笔记中查找同类型例题；如果笔记没有记录此类题，可以上网找到例题，提供两道题作类比，持续帮助用户直到真正掌握。
- (insight) 本轮设想涉及从网上补充例题，与现有严格来源问答只依据来源集、资料不足时拒答的边界不同；现有 fetch_url 也仅抓取用户提供的网址。暂保留为普通专业老师模式的候选需求，具体模式归属与联网方式待讨论，不改动现有产品边界。
- (insight) 掌握的判据：用户在没有提示的情况下，按指定标准（例如考研标准）完整做出类似例题，并能解释完整思路。
- (direction) 上述教学与掌握判据可扩展到其他领域；不同领域的具体标准存在差别，应根据用户的具体需求确定。
- (technique) started SCAMPER — Adapt（借用）
- (insight) SCAMPER 借用：面向学生时，老师的指导应明确、简单、可直接执行；过程不能过于繁琐，也不能过多跳步，需要一步一步推进。
- (insight) 用户判断（待验证）：如果第一步足够简单明确，学生应能执行；学生卡住极大可能是老师尚未理解学生的真正意图。
- (idea) SCAMPER 借用：参考 grill-me skill，以“拷问”式的深入追问了解学生的真实想法和意图，为后续指导提供依据。
- (insight) grill-me 参考事实：一次只问一个问题，沿分支逐一厘清决策依赖，直到双方形成共同理解；原 skill 还要求每问给出推荐答案。本轮将其作为教学方式的参考，继续原 facilitator 发想模式。
- (insight) 教练补充：步骤简单明确并不能保证学生一定会做，前置知识缺口也可能导致卡住；不能将“未理解学生意图”当成所有卡点的既定原因。
- (insight) 开始指导前需要通过追问了解两项信息：学生已有的前置知识，以及学生希望在本次对话中完成的明确目标。
- (technique) started SCAMPER — Modify（改变尺度）
- (idea) SCAMPER 改变尺度：在持续交往中，专业老师逐步了解学生的学习习惯，并实时更新对学生知识基础的认识。
- (direction) 专业老师自身的教学方式、说话习惯和做事风格应一以贯之，体现其作为用户创造出来的“真正老师”的稳定个性。
- (idea) SCAMPER 改变尺度：当学生表示不适应老师的讲法时，让学生明确指出具体问题和不习惯的做法，再由学生说出可以立即改变、简单直白的解决办法。
- (idea) SCAMPER 改变尺度：当学生说得出不适应之处，却想不出解决办法时，老师可以主动引导，提出具体、详细的改变方案，让用户选择或调整。
- (technique) started SCAMPER — Put to other uses（另作他用）
- (idea) SCAMPER 另作他用：用户创建的 Agent 可以担任知识库管理专业人员，各自有负责的范围，帮助用户搜索资料。
- (insight) 用户期望这些 Agent 比用户本人更熟悉各自负责范围内的笔记；用户需要创作时，Agent 帮助其了解和取用此前记录的相关内容。
- (idea) SCAMPER 另作他用的写作场景：用户准备写一本小书，素材库中已有许多人物形象和剧情构思，希望通过 Agent 直接检索出来用于创作。
- (technique) started SCAMPER — Eliminate（删减）
- (idea) SCAMPER 删减：省去用户主动检索后，Agent 可以主动为作品创作和人物形象描写提出建议；它本身具备小说创作家的专业能力，并了解用户的创作习惯和笔吻。
- (direction) 用户澄清创作建议的触发边界：应由用户主动提出需求，Agent 再给建议，不需要擅自做主。此条更正上一条“主动为作品创作和人物描写提出建议”的表述，不能把无需显式检索理解为无需用户发起请求。
- (technique) started SCAMPER — Reverse / Rearrange（反转与重排）
- (idea) SCAMPER 反转顺序：如果用户对心目中的理想 Agent 还很模糊，可以先用默认助手体验几次真实任务，逐步明确自己想要的老师形象，再塑造专属 Agent；这是适用于需求尚不清晰用户的可选路径。
- (technique) started Six Thinking Hats — White Hat（白帽：事实）
- (insight) 白帽下的用户自述体验（尚未提供具体对话样本）：默认助手回答枯燥、繁琐，不适合自己；用户希望问题得到解答，而不是由助手调用或呈现一大段已记录的笔记。
- (direction) 用户澄清：尚未使用知了 App，不知道其具体表现。因此上一条关于默认助手枯燥、繁琐及呈现大段笔记的描述，不能作为知了的真实使用反馈；保留为对理想回答方式的偏好，具体来源及实际表现尚未验证。
- (technique) started Six Thinking Hats — Red Hat（红帽：直觉与感受）
- (insight) 红帽下的用户期待：由一位专业并且懂自己的老师管理知识库，让学习更轻松、效率更高，也更有学习兴趣。此处记录预期感受与收益，不作为已验证的效果。
- (direction) 红帽场景下用户明确：当学生表示这部分太难、不想学了，老师应遵循用户当下的指令；不以提高学习兴趣或达成掌握目标为由强行推进。
- (technique) started Six Thinking Hats — Yellow Hat（黄帽：价值与收益）
- (insight) 黄帽下的核心预期价值是舒适的学习体验：老师了解用户的知识基础，有用户喜欢的性格，采用用户喜欢的教学方式，并在对应领域（例如考研数学）具备很强的专业能力。
- (technique) started Six Thinking Hats — Black Hat（黑帽：风险与局限）
- (insight) 黑帽下的用户顾虑：构建自定义 Agent 可能要求用户具备一些 AI 知识，而且构建过程本身较复杂。
- (insight) 黑帽下的另一项顾虑：Agent 构建完成后的持续管理也是问题；具体管理负担尚待展开。
- (insight) 黑帽下的持续管理两难：Agent 持续自主更新可能让提示词越来越繁琐；要求用户手动修改或整理提示词，又存在门槛高、耗时的问题。
- (technique) started Six Thinking Hats — Green Hat（绿帽：新办法）
- (idea by coach) 应用户请求提供一个绿帽建议：将稳定的老师设定与持续变化的用户学习档案分开。老师设定保存性格、教学方式和职责边界；学习档案保存知识基础与学习偏好，在用户发起任务时按需取用相关内容。档案按同一事项更新当前结论，合并重复、替换过时信息，不将所有对话持续追加到老师提示词中。涉及老师设定的长期改动，先给用户具体方案，由用户选择或确认；学习档案的更新规则仍待讨论。此建议尚未被用户采纳或验证。
- (decision) 用户以“可以”认可教练提出的候选方向：稳定的老师设定与可更新的学习档案分开管理，学习档案按需取用并合并、更新同一事项。此处为头脑风暴方案认可，不代表实现授权；用户尚未具体回答档案误判时如何纠正。
