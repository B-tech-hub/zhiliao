自定义提示词与知识库 Agent 2026.09.16 — 09.18

一个专业的，
适合我的人。

让用户长期拥有专业合拍、各有分工、维护省心，并由自己掌控的知识库 Agent。这是本轮讨论收敛出的方向。

这轮讨论的落点
“舒适的学习体验。”

老师了解我的基础，有我喜欢的性格，采用适合我的教法，也具备对应领域的专业能力。

本轮已收敛 四个核心已选定；当前为候选提案，体验与效果仍待验证。

01 / 最终选择

四个核心，构成同一份期待。

从六个归纳方向中，用户选定了 2、4、5、6。

用户选定的核心方向
02

专业合拍

懂专业，也懂我的起点。

了解知识基础与本次目标，性格和教法符合偏好。讲解明确、简单、能直接执行，步骤之间衔接清楚。

04

领域分工

各有专长，各自熟悉一部分笔记。

同一个大模型可承载不同领域的 Agent。考研老师与小说创作者，各自从负责的知识中帮助用户取用。

05

维护省心

持续了解我，维护过程保持简单。

将稳定的老师设定与变化的学习档案分开。按需读取相关记录，合并重复内容，更新过时判断。

06

用户掌控

由我发起，也由我决定停止。

用户提出需求，Agent 再响应。需要改变讲法时，说明具体调整，交由用户选择或修正。

配套候选仍保留：问答创建 Agent、手动关联知识。它们未被选为本轮核心，也未被否定。

02 / 想法如何走到这里

从一个手段，走向一种相处方式。

I

Laddering

不断追问“为什么”。
从提示词编辑，走到真正想获得的帮助。

  1. 最初的手段自己编辑提示词、设计 Agent
  2. 希望的变化不同领域，获得不同的专业帮助
  3. 个人的需要按我的基础与习惯，讲清楚问题
  4. 真正的期待一个专业的、适合我的人
II

SCAMPER

七次换一个角度。
展开字母，查看当时留下的想法与澄清。

S用问答“制造老师”Substitute · 替代
设计一个“制造老师”的 skill，引导用户回答问题，再将回答整理为老师提示词。具体问答方式尚待设计。
配套候选
C把知识点连起来用Combine · 组合
用户手动关联两条笔记或两个知识点；以后问到其中一项，老师可以带出相关内容。泰勒展开题由此延伸到常见展开式与同类例题。
配套候选
A借用逐个追问的教法Adapt · 借用
参考 grill-me，一次问一个问题，逐步了解学生的真实想法。开始指导前，问清已有的前置知识和这次对话要完成的明确目标；指导要简单、具体、可执行。
M把相处时间拉长Modify · 改变尺度
长期相处中，老师逐步了解学习习惯、更新知识基础判断，自己的教法与风格保持一贯。学生反馈不适应时，先说清具体问题；需要帮助时，由老师提出具体改法供学生选择或调整。
P让专业人员管理知识库Put to other uses · 另作他用
Agent 也可以帮助创作。用户写一本小书时，负责这部分素材的 Agent 检索已有的人物形象和剧情构思，让过去的积累进入当下创作。
E从找素材，延伸到给建议Eliminate · 删减
当用户需要创作帮助时，具备小说创作能力的 Agent 可结合用户的习惯与笔吻，为作品及人物描写提出建议。 最终澄清：“用户主动提出，Agent 不需要擅自主张。” 无需额外描述检索动作，不等于无需用户发起请求。
R先体验，再塑造Reverse · 反转顺序
如果用户还说不清心目中的理想 Agent，可以先用默认助手完成几次真实任务，从体验中逐步认识自己喜欢的老师形象。这是一条按需选择的路径。

III

六顶思考帽

将事实、感受、收益与顾虑分开看，再收束方向。

白

事实

用户尚未使用知了。“回答枯燥、搬运大段笔记”是偏好描述，不能记作知了的实测反馈。

红

感受

期待学习更轻松、更有兴趣。用户表示不想继续时，老师遵循当下指令。

黄

收益

舒适的学习体验：懂基础、性格合拍、教法合适、专业可靠。

黑

顾虑

创建过程可能复杂；自主更新可能使提示词膨胀，手工维护又费时、门槛高。

绿

新办法

将稳定老师设定与动态学习档案分开。该建议由教练提出，用户认可为候选方向。

蓝

取舍

选定专业合拍、领域分工、维护省心、用户掌控四个核心，结束本轮发散。

03 / 让构想落在具体事情上

一道数学题，一本小书。

讨论中的两个设想场景，用来说明期望的帮助方式。

场景 A / 学习

从泰勒展开题，走到掌握。

老师先了解学生的前置知识与这次目标，再按照适合的教法指导。

  1. 解答当前问题，带出相关的常见函数展开式。
  2. 从笔记里找到同类型例题，用两道题作类比。
  3. 按用户指定的标准，观察能否独立完成同类题，并解释完整思路。
边界待设计
笔记缺少例题时，用户提出可联网补题。它与现有严格来源问答的规则不同，具体模式与联网方式尚未确定。
场景 B / 创作

让旧素材进入正在写的小书。

熟悉这部分知识库的 Agent，检索用户此前积累的人物形象与剧情构思，供创作时取用。

素材 / 01人物形象
素材 / 02剧情构思
懂小说创作，也了解我的创作习惯与笔吻。
用户提出请求后，Agent 才给出作品或人物描写建议。学习与创作的节奏，都由用户决定。

04 / 把两种变化分开

风格保持一贯，了解持续更新。

已认可的候选方案 教练应请求提出，用户认可；具体更新和纠错规则仍待设计。
相对稳定 / 角色

老师设定

性格说话风格教学方式负责领域

承接用户喜欢的风格与专业职责，让这位老师在长期使用中保持可辨认的个性。

长期改动先形成具体方案，由用户选择或确认。

持续更新 / 对用户的了解

学习档案

知识基础学习表现明确的学习习惯

同一事项更新原记录，合并重复内容，替换过时判断，保留简短依据；回答时取用与当前任务有关的部分。

用户通过自然语言提出调整，具体纠错方式尚待确定。

这两部分共同服务于一件事：用户长期使用适合自己的 Agent，同时降低维护复杂提示词的负担。

05 / 留给下一次的页边

方向已选定，细节留待验证。

这些问题仍然开放；本轮收敛没有将它们视为已经解决。

创建怎样降低“制造老师”的门槛？
具体问答方式尚未设计，仍需弄清怎样让不熟悉 AI 的用户表达需求，并完成创建。先体验默认助手是已记录的可选路径。
分工怎样确定每个 Agent 负责的范围？
用户已选择按领域分工，但笔记与职责范围如何确定，尚未展开为具体方案。
维护学习档案怎样更新，误判怎样纠正？
分开管理已获认可。自动更新规则、需要用户确认的具体情形，以及误判知识水平后的便捷纠正方式，仍待设计。
来源联网补题如何保持清楚的来源边界？
现有来源问答严格限定在来源集内；已有抓取工具仅处理用户提供的网址。联网寻找新例题仍是候选需求，不能视为当前已具备的能力。
体验这些预期，能否在真实使用中成立？
用户尚未实际使用知了。对舒适感、专业能力、学习效率与兴趣的期待，均需后续验证；偏好描述不能作为当前产品的缺陷证据。

保留在书签里的三种技法

Worst Possible Idea（最糟糕的点子）、Build on What Works（沿着有效之处继续）、Scenario Cross（交叉场景）本轮未执行。它们保留为今后新会话的可选入口。
