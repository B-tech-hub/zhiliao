# 0.6.1 候选收口与 R2 准备：单 Agent 审查

日期：2026-09-24。方式：单 Agent 依次按盲审、边界路径、验证缺口三个视角逐项核对，并对照产品代码。用户要求保持单 Agent，没有启动子 Agent，不冒充独立多方审查。审查对象是[规格](spec-0-6-1-baseline-r2-preparation.md)自 `6ee6753` 起产生的文档与 R2 准备包；R1 产品补丁和 B1 已有各自的审查，本次不重审。

结论：没有需要回到规格重做的问题。7 项补丁已直接落地并复验，没有新增延后项。

| # | 问题 | 处理 |
|---|---|---|
| 1 | transcript 没有追加写，同一轮在新终端重跑定义块会覆盖记录 | `Start-Transcript -Append` |
| 2 | `Save-R2Text` 会覆盖同名证据 | 只新建不覆盖，与 `compare.py` 一致 |
| 3 | 构建段中断后停在 `Continue`，`build.log` 可能混写 | try/finally 恢复 `Stop`，先重置退出码，已有日志则拒绝 |
| 4 | 就绪等待不校验角色，注释里的时长不准 | 先校验角色；注释改为“最多 60 次” |
| 5 | 试跑脚本没有验证“启动后先等就绪”和各条失败路径 | 补顺序断言和 4 个反例；两处变异都被判失败 |
| 6 | 在记录 transcript 的终端里读取密码会被记下；证据入库范围没写明 | 换窗口读取；入库不复制 `*.env`，transcript 先检查 |
| 7 | `modelConfigured` 写死为 false，没有检查环境变量 | 断言五组模型环境变量都不存在 |

按代码核对、无需修改的部分：主题、上传、笔记、回收站、导入导出、备份、会话和搜索的接口形状；seal 写入的表结构；worker 在未配置模型时只推迟任务，不改笔记；导入会 `trim()` 正文，样本首尾没有空白；导出 frontmatter 使用 JSON 字符串和毫秒时间，导入端能解析。以上都要以 R2 实测为准。

复验结果见[证据索引](../../docs/验收证据/0.6.1-baseline-2026-09-23/README.md)第 4 节。
