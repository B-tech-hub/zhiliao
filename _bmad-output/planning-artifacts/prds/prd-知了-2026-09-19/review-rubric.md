# PRD Quality Review — 知了自定义知识库 Agent PRD

审查日期：2026-09-21。审查方式：主 Agent 按 `prd-validation-checklist.md` 七个维度顺序自审（用户确认不开子 Agent）。对象：`prd.md`、`addendum.md`。利害等级：单人自托管产品、冻结期规划稿、链首文档（后续接 UX、架构、Epic）。

## Overall verdict

这份 PRD 的决定都是决定，每一条都带着弃用项和理由，取舍表把「为什么不是另一种」写得比多数 PRD 的正文还清楚。风险在两处：第一，审查开始时「首轮完整功能组合尚未定稿」，Epic 拆不下去；第二，FR-1、FR-2 这两条最早写的需求缺少可验的后果，而 FR-16 一条长到失去可读性。三处均在本轮定稿中修复。

## Decision-readiness — strong

每个 Q 都以「采用 / 弃用与理由 / 代码依据」收口，addendum 三张取舍表把放弃的路径写明；FR-14 甚至写明「删除首轮不下发，不是永久决定」。开放问题是真的开放（Q-4、Q-8、Q-9 余项明确归属设计阶段），没有自问自答。

### Findings

- **high** 首轮功能组合未定稿（§首轮范围与非目标）— 原文「首轮完整功能组合尚未定稿」使 Epic 拆解无从下手。*Fix:* 写入用户确认的两部分组合与第二轮项。已修。

## Substance over theater — strong

没有人物画像、没有愿景套话；NFR 四条全部指向具体既有约束（正文不覆盖、来源集拒答、删除确认、UI 规范），不是模板搬运。「首次具体任务」一节用用户原句作为验收句，是实打实的用户旅程替身。

## Strategic coherence — adequate

论点清楚：四个核心，首轮只押其中能被导图任务检验的部分，并诚实写明「按领域分工」首轮验不到。反向指标已列。

### Findings

- **medium** 简报的四项主要风险在 PRD 中消失（§成功信号）— 风格无效、误判基础、分工漏检、维护抵消收益，是 SM-1 至 SM-4 存在的理由，却没有被点名。*Fix:* 在成功信号节开头列出并映射。已修。
- **medium** 缺少停止条件（§验证方案）— 简报补充材料写明「若现有助手已能满足主要任务，应重新评估必要性」，PRD 没有对应句，读者会以为基线期之后必然进入开发。*Fix:* 验证方案增「停止条件」。已修。

## Done-ness clarity — adequate

FR-3、FR-13、FR-14、FR-15、FR-16、FR-17 每条都有可判定的后果（越界零次、未分类禁入、每条回复最多 1 条、托盘 10 条、30 天）。FR-7 的「尽量保留」本身不可测，但验证方案用三档标注补上了判定方式。

### Findings

- **high** FR-1、FR-2 没有可验后果（§专业且合拍）— 「具体还需要追问什么，随任务明确」「专业质量与表达偏好分别验证」都是安排而不是标准。*Fix:* FR-1 补「已提供的信息不再重复询问、缺失时先问再教」并挂到 SM-3 的重复交代次数；FR-2 补三分法（专业错误 / 材料不足 / 风格不适合）与「未选择时不自行改变方式」。已修。
- **medium** FR-16 单段近四百字（§维护省心）— 六条规则挤在一段，下游拆 Story 时必须自己切分。*Fix:* 拆为呈现、触发与上限、暂存、否认、冲突、删除语义六个子项。已修。
- **low** SM-6「更新时限待定」与验证方案「不设」矛盾（§SM-6）— *Fix:* SM-6 改为引用验证方案。已修。

## Scope honesty — strong

非目标明确（联网补题、多用户、知识图谱、白板、接口与表设计）；第二轮项点名（FR-18、单 Agent 恢复）；唯一一处未经逐项确认的推断（删除 Agent 四项一并进出）已加 `[ASSUMPTION]` 并索引。开放项密度对冻结期规划稿而言合理。

## Downstream usability — adequate

术语表五条，FR、SM 之间引用全部可解析；addendum 的相对链接指向真实文件（本轮核对过 schema.ts、suggest-topics.ts、use-chat.ts、trash.ts、sources.ts、update-meta.ts、create-note.ts、tools/index.ts 与 ADR 0007/0008/0010/0012/0017/0020/0021/0024/0025）。

### Findings

- **medium** 缺交接节（全文）— 下一个 Agent 接手时找不到阅读顺序、启动条件与 Sprint 归属。*Fix:* 新增「交接与启动条件」。已修。
- **low** 「待决问题」标题名不副实（§待决问题）— 表内九行有七行已收敛，标题误导。*Fix:* 改名「问题收敛记录与剩余待决项」，表后列剩余项与归属。已修。

## Shape fit — strong

单人自托管、棕地、链首。没有硬套人物画像式用户旅程，用「首次具体任务」的真实句子代替，合适。棕地引用准确（见上）。

## Mechanical notes

- FR 编号按确认顺序分配，不按章节连续（FR-13 至 FR-15 在分工节，FR-16 在维护节，FR-17 在掌控节，FR-18 在创建节）。唯一且引用可解析，不改编号以免破坏日志追溯。
- 引号约定：用户原句与文件名用“ ”，界面标签与术语用「 」，全文一致。
- 假设索引：一条，与正文一致。
- 无 UJ，符合单操作者形态。
