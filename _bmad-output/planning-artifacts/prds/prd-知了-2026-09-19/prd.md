# 知了自定义知识库 Agent 产品需求文档

> 冻结期定稿，仅规划，不代表开发授权。需求范围、负责范围规则、学习档案生命周期、数据出口与验证方案均已由产品负责人确认；入口与异常流程等交互细节留给设计阶段。真实笔记达到 100 条前冻结新功能，达到后按[交接与启动条件](#交接与启动条件)重新评估，不自动立项。

## 产品目标与使用场景

让知了的个人用户长期使用专业且合拍、按领域分工、维护省心并受自己掌控的 Agent，将相关笔记用于当前任务。产品延续单用户、自托管 Web/PWA 形态。

用户已提出两个场景：考研数学学习，以及小说人物、剧情素材的取用。学习指导已提出“无提示完成同类题并解释完整思路”的掌握标准；创作场景的完成标准未定。

### 首次具体任务：知识导图图片入笔记与内容检索

用户已有一些考研数学内容的知识导图图片，希望 Agent 识别其中内容，尽量保留原图的节点、层级和连接。用户先预览导图，核对或修改后再加入笔记；在预览和笔记内直接修改图上的文字、增删分支。之后在笔记库中输入“帮我检索有关极限求法的知识”，应能找到导图里已有的相关内容。

已确认的任务顺序是“已有导图图片 → 识别并生成导图 → 预览核对或修改 → 加入笔记 → 后续直接编辑与自然语言检索”。本次成功结果是材料可用、可编辑、可检索，学习指导的掌握标准不直接套用于图片整理任务。

材料类型、目标、结构处理、直接编辑方式和先核对后加入的顺序已明确，具体图片尚未核对，也未执行识别或搜索验证。图片如何交给 Agent、加入现有还是新建笔记、公式处理和搜索结果的呈现细节仍待补充；不据此扩展为批量导入或完整导图编辑器。

原讨论中用户尚未实际使用知了；本轮确认已有图片材料，尚未确认这些图片已存入知了。舒适感、效率和兴趣提升属于预期，不能视为已验证收益，也不能据此认定现有助手存在缺陷。

## 术语

- **知识库 Agent**：用户可长期使用的专业角色，具有适合自己的风格与领域职责；不表示启用多个开发 Agent 或已确定角色间自动协作。
- **角色设定**：相对稳定的性格、教学或表达方式、职责边界。
- **学习档案**：每个 Agent 独立维护的知识基础与学习偏好判断，与角色设定分开管理。Agent 提出更新建议，用户确认后再保存；用户也可查看并直接修改或删除单条记录。用户拒绝的建议以「否认」记录保存在档案中，见 FR-16。是否扩展到创作习惯尚未确认。
- **负责范围**：用户自主为 Agent 添加和划定的笔记范围，可选择整个主题，也可单独选择笔记。主题是活引用，未分类不能作为成员；同一主题或笔记可以同时属于多个 Agent。范围内找不到所需知识时告知用户。成员与变更规则见 FR-13，允许的写操作见 FR-14。
- **来源集、来源问答、严格接地**：沿用 [CONTEXT.md](../../../../CONTEXT.md)；来源集属于会话，不自动等同于负责范围。

## 已确认方向对应的需求

以下 FR 的方向来自用户已确认结论，验收细节仍需结合真实任务补齐；列入本文不代表已批准实现。

### 专业且合拍

- **FR-1 理解任务与基础**：Agent 在指导前了解本次目标和必要的前置知识。用户已经提供的信息应被利用，不再重复询问；缺失时先问再教。具体还需要追问什么，随任务明确。验收看 SM-1 与 SM-3 的记录：重复交代背景的次数，以及卡住的原因属于意图未被理解还是前置知识缺口。
- **FR-2 适合用户的帮助方式**：Agent 根据角色设定提供专业帮助。学习指导具体、能执行、步骤衔接清楚；用户反馈不适应时，可说明具体问题，由 Agent 提出调整方案供选择，未选择时不自行改变方式。验收时把问题分为专业错误、材料不足和风格不适合三类分别记录，专业质量与表达偏好分别验证。

### 按领域分工

- **FR-3 管理与取用负责范围内的笔记**：用户自主添加和划定各 Agent 的负责范围，支持选择整个主题和单独选择笔记。Agent 的检索与读取限定在该范围内，找不到所需知识时如实告诉用户，告知后的回答边界见 FR-15；该决定不授权自动扩大检索范围或联网补充，也不允许 Agent 借修改笔记主题把范围外笔记纳入自己的范围。检验时区分正确取用、漏检和越界。成员与变更规则见 FR-13，允许的管理动作见 FR-14。
- **FR-13 负责范围的成员与变更规则**：主题作为范围成员时是活引用，之后归入该主题的笔记自动进入范围。「未分类」不能作为范围成员，避免后台整理和删主题回落使范围反复变动。范围增删从下一条消息起生效，已产生的回答不追溯重算。回收站中的笔记保留在范围内但不参与回答，恢复后自动重新生效。范围内的主题被删除后，范围中须标示该主题已删除并提醒用户，不静默收缩。同一主题或笔记可以同时属于多个 Agent 的范围，读取不冲突，写操作按 FR-14 约束。单独勾选的笔记按 id 始终留在范围内，之后被移到其他主题也不受影响；范围页须标示这类笔记「不随主题走」。
- **FR-14 范围内允许的管理动作**：首轮只向 Agent 下发新建笔记和追加内容两个写工具，追加只能作用于范围内的笔记，两者均沿用操作卡片与撤销。Agent 新建的笔记必须落在其范围内的某个主题：范围内只有一个主题时默认该主题，有多个时询问用户，没有主题时不下发新建工具。修改元数据首轮不下发；无论何时都不允许 Agent 改动笔记的主题。删除笔记首轮不下发，不是永久决定，既有删除确认卡片不变量继续有效。生成图片不下发。抓取网页首轮不下发，与不联网补题的非目标一致。
- **FR-15 老师模式的回答边界**：Agent 的会话是普通专业帮助，不是来源问答。模型可以用自身知识讲解，范围内的笔记用于找例题与类比；范围内找不到时先如实告知，之后仍可继续讲解。沿用既有引用溯源规则，只有真实取到的笔记才渲染为引用，不得把模型自身知识说成出自笔记。需要严格接地时仍使用来源问答，Agent 不改变其规则。

### 维护省心

- **FR-4 分离角色设定与学习档案**：持续了解用户不应自动改变角色设定。每个 Agent 独立维护自己的学习档案，按任务需要取用；对同一事项提出合并重复或更新过时判断的建议，按 FR-5 确认后保存，不把全部对话持续追加到角色设定中。
- **FR-5 处理长期调整**：角色设定的长期变更先形成具体方案，由用户选择或确认。Agent 对学习档案的更新同样先提出建议，用户确认后再保存；未确认建议不替换已生效档案。两类内容继续分开管理。建议的触发、上限、暂存、否认与冲突规则见 FR-16。
- **FR-12 用户管理学习档案**：用户可以查看各 Agent 的学习档案，并直接修改或删除其中的单条记录。用户手工更正无需先让 Agent 生成修正建议；不连带修改其他 Agent 的独立档案。手工改动与待确认建议的冲突、删除已生效记录的语义按 FR-16 处理。
- **FR-16 学习档案建议的生命周期**：
  - 呈现：Agent 在会话中提出的档案更新建议是一次需要用户确认的操作，沿用既有操作卡片的确认与撤销方式呈现，确认前不写入已生效档案。
  - 触发与上限：建议由 Agent 主动提出，应在完成当次帮助之后提出，不在讲解中途插入；每条回复最多提出 1 条。每个 Agent 的待确认建议最多保留 10 条，达到上限后 Agent 不能再提出新建议，托盘提示用户先处理。
  - 暂存：待确认建议持久保存，重开会话后仍可见，不因产生新建议而自动作废；Agent 的档案页汇总该 Agent 全部待确认建议（托盘），供用户集中处理。
  - 否认：用户拒绝一条建议时，档案中保存一条「否认」记录，可查看、可删除。否认记录存在期间，同一判断不得再次保存为档案，Agent 也应避免重复提出；用户删除否认记录即允许再次提出，不承诺永久不再提。
  - 冲突：用户确认建议时校验目标记录是否仍与提出时一致，目标记录已被用户修改则建议失效并标示原因，已被删除则建议作废；用户改动档案时不扫描待确认建议，也不自动重新生成建议。
  - 删除语义：用户删除一条已生效的档案记录表示忘掉该判断，Agent 之后可以基于新的观察再次提出；否认记录只由拒绝建议产生，删除时不额外询问。

### 用户掌控

- **FR-6 依用户请求行动与停止**：Agent 在用户提出需求后响应；用户明确要求停止时停止，不以学习目标、兴趣提升或创作建议为由强行继续。无需用户单独描述检索动作，不等于允许擅自发起任务。
- **FR-17 角色设定与学习档案的保存、删除与恢复**：角色设定与学习档案首轮不进入 Markdown 目录和 ZIP 导出，随整库备份保存与恢复。删除 Agent 时，其角色设定、学习档案、负责范围引用和会话历史整体移入回收站，30 天内可恢复，恢复后一并回到删除前的状态；到期后随每日清扫彻底删除，沿用既有保留期，不另设配置项。[ASSUMPTION: 用户以「30 天可恢复」一句作答，四项一并进出按整体理解记录，未逐项确认。] 需要能单独恢复某一个 Agent 的角色设定与学习档案而不改动其他数据，列入第二轮；首轮没有单独的导出文件，恢复来源只能是既有备份快照，如何从快照中取出单个 Agent 在架构阶段明确。

### 角色创建

- **FR-11 问答引导生成角色设定**：通过问答了解用户希望的性格、教学方式和职责，生成具体角色设定，由用户确认后采用。负责的主题和笔记仍由用户自主选择，不能以职责描述自动扩大范围或授予工具权限。首次引导的问题、草稿修改和角色选用流程待设计。
- **FR-18 继承已有 Agent（第二轮）**：新建 Agent 时，用户可以选择继承某个已有 Agent 的角色设定或学习档案。继承是创建时复制一份，之后两个 Agent 各自独立维护、互不影响，与 FR-4 一致；学习档案按整份复制，包含其中的否认记录。负责范围不继承，仍由用户按 FR-3 自主划定。继承与问答引导如何组合在交互设计时明确。

### 考研数学导图材料整理与检索

- **FR-7 识别导图并保留结构**：识别用户提供的知识导图图片，生成尽量保留原图节点、层级和连接的导图，供核对后加入笔记。未授权 AI 自行重新组织知识关系。具体样图、数学表达和可接受的识别偏差待定；看不清的内容按既有转写约束提示不确定，不得编造。
- **FR-8 用自然语言检索导图内容**：导图加入笔记后，用户在笔记库搜索“帮我检索有关极限求法的知识”，应能找到导图里已有的相关内容。不能仅以笔记标题或图片文件名命中作为验收证据。是否展示命中节点、定位分支或提供解释待定；没有确认直接输入公式检索的需求。
- **FR-9 直接修改导图文字与分支**：用户在图上修改文字、增加或删除分支，预览核对和加入笔记后的编辑都需要支持这一方式。不能将要求用户编辑源码或文字大纲作为完成该需求的唯一途径；拖拽、自由画布、实时协作等交互尚未纳入范围。
- **FR-10 先核对再加入笔记**：识别完成后先展示导图预览，用户核对或修改后再加入笔记。确认前不自动将识别结果追加为正式笔记内容；原图保留与正文不被覆盖沿用既有约束。预览是否暂存、取消及失败恢复的处理在后续设计中明确。

## 跨功能约束

- **NFR-1 产品与数据边界**：保持单用户、自托管、主题导向；AI 不覆盖用户正文，保留 Markdown、图片、备份与恢复的数据出口。角色设定与学习档案的保存、删除与恢复规则见 FR-17。
- **NFR-2 来源可信**：来源问答仅依据来源集回答，资料不足时明确拒答。自定义设定不得放宽来源边界；学习档案不能充当来源中不存在的知识证据。
- **NFR-3 操作可控**：保留既有删除确认、操作卡片与撤销规则。自定义角色不自动改变工具权限；现有网页抓取不等于自主联网搜索。
- **NFR-4 沿用现有体验规范**：后续界面遵循 [UI 规范](../../../../docs/UI规范.md)，本轮不新增页面或一级导航，不以规划稿改动现有产品行为。

## 首轮范围与非目标

四个核心作为范围评估依据。首轮功能组合于 2026-09-21 确认为两部分：

- **导图入库**：FR-7 至 FR-10 的识别、预览核对、直接编辑与自然语言检索，是首次具体任务。
- **单个数学 Agent 的最小闭环**：问答引导创建（FR-11）、负责范围与老师模式（FR-3、FR-13、FR-14、FR-15）、学习档案与建议生命周期（FR-4、FR-5、FR-12、FR-16）、删除进回收站（FR-17 的回收站部分）。

推到第二轮：继承已有 Agent（FR-18）与从备份快照单独恢复某个 Agent（FR-17 的单独恢复部分），首轮只有一个 Agent，两者都用不上。首轮只有一个 Agent 也意味着「按领域分工」这一核心首轮验不到，见验证方案。

保留但不进首轮的候选：先体验默认助手、手动知识关联、知识框架来源（笔记归纳、用户自己的方法或网上教学方法）；联网补题见下段。原始动机见[简报补充材料](../../briefs/brief-知了-2026-09-19/addendum.md)。

**已确认的首轮非目标：联网补充练习题。** 在负责范围内找不到所需知识时仍告知用户，不自动联网找题。联网补题保留为后续重新评估的候选；本决定不移除既有网页抓取能力，也不改变来源问答的严格接地约束。

不建设注册、多用户、RBAC、SaaS、工作流画布、知识图谱或白板。自带 Key、现有检索与来源问答不重复包装成新增能力。本轮不写开发任务、排期、接口契约或数据表设计。

## 成功信号与反向指标

简报列出的四项主要风险与观察它们的信号：风格变化未带来专业质量提升（SM-1）、错误判断知识基础（SM-4）、分工造成漏检（SM-2）、维护负担抵消收益（SM-3）。以下验证建议均尚未执行，各条不再重复说明：

- **SM-1 任务效果**：按用户指定的标准检验任务完成情况；学习任务同时检验无提示迁移与完整思路。每次任务保留目标、相关笔记、回答、追问原因和主观评价，记录用户为何觉得教法合适，以及卡住的原因属于意图未被理解还是前置知识缺口。验证 FR-1、FR-2。
- **SM-2 知识取用**：按用户选择的主题和单篇笔记检查相关知识是否找到并用于任务，记录漏检、误用和越界，引用须能回到真实笔记；设计范围内有答案、答案只在范围外及范围内无相关材料的对照，检查未找到时是否明确告知，验证 FR-3。范围外对照不应泄露未被取用的笔记内容。另检查 Agent 新建的笔记是否落在范围内主题、是否出现改动主题或未下发工具的调用，验证 FR-13、FR-14。
- **SM-3 维护负担**：记录重复交代背景、调整设定和纠正档案的次数与耗时，与基线期比较；记录分两行，见验证方案。验证 FR-4、FR-5。
- **SM-4 用户掌控**：验证 FR-4、FR-5、FR-6、FR-11、FR-12、FR-16、FR-17、FR-18。
  - 停止与确认：明确的停止请求被遵守；问答生成的角色设定经确认后采用；档案更新确认后才保存，未确认或拒绝时不替换已生效档案，不以沉默或继续聊天代替确认。
  - 档案管理：用户能查看、更正、删除单条档案记录，且不影响其他 Agent 的档案；拒绝后生成否认记录，否认记录存在期间同一判断不被再次保存；目标记录被修改或删除后建议失效。
  - 删除与继承：删除 Agent 后 30 天内能整体恢复；单独恢复一个 Agent 时其他数据未变；继承后两个 Agent 的档案互不影响。
- **SM-5 导图入库与检索（验收建议，待样图确认）**：用用户提供、含极限求法内容的原图核对节点、层级和连接；检查确认前不自动加入、预览修改能被保留、确认后重新打开可见。保持标题和其他正文不包含目标知识点，用用户原句“帮我检索有关极限求法的知识”检查能否找到相关导图内容。数学表达、排名、节点定位和识别容错的具体标准待定。
- **SM-6 编辑与检索一致（验收建议）**：修改节点文字或分支后保存并重新打开，检查修改是否保留、导图是否一致，以及新增文字能否通过搜索找到。移除文字的对照样例需确保标题、其他正文和原图说明中也不存在该词，分别判断精确文本命中与语义相关结果，不把所有旧词查询结果都判为索引残留。更新时限按验证方案不设。
- **反向指标**：不能用更长对话或更多追问替代任务效果；不能用更少确认掩盖错误的档案更新；不能用更高笔记命中数掩盖越界或答非所问。

验证语料、Demo 数据与基线期记录笔记不能计入真实笔记解冻门槛。

### 验证方案（2026-09-21 确认）

- **基线期从现在开始**：用现有产品学习考研数学，不启用 Agent，同时积累真实笔记与基线记录；一次性导入的笔记不计入 100 条门槛。基线期记录与 SM-3 相同的两行耗时，见「维护成本记两行」；逐日记录写在知了内固定主题「基线期」下的一条笔记里，每天追加一行，该笔记不进任何来源集、不计入 100 条门槛；两行在基线期的对应定义、每日一行格式、隔离规则与月度小结见[基线期记录](基线期记录.md)。
- **开发前的可行性实验**：用现有手写转写路径对全部真实导图图片裸跑识别，观察节点与层级的还原程度；目标 20 张，少于 10 张不足以判断识别偏差。这是整份需求中唯一能在不写产品代码时证伪的假设：FR-7 不可行则 FR-8 至 FR-10 不立项。现有提示词不要求还原结构，结果只说明起点。执行前须另行批准模型预算与图片发送范围；本轮公开图 20 张各一次的预算与发送范围已于 2026-09-22 批准，真实图另批。
- **首轮样本只验数学**：导图图片全部使用；数学题 10 道，覆盖导图中的知识点，用于 SM-1 的无提示完成同类题。小说素材场景推迟到完成标准确定之后。「按领域分工」首轮验不到的说明见首轮范围。
- **阈值只硬一条**：SM-2 的越界次数为 0，Agent 读到范围外笔记一次即 FR-3 不成立。其余指标第一轮只记录不判定：每张导图标「可用、要修、不可用」，每道题标「做出、未做出」，检索与任务效果记录原始结果；第二轮依据第一轮记录设阈值。SM-6 的更新时限不设，避免承诺尚未设计的机制。
- **维护成本记两行**：SM-3 分为「调整角色设定与手工纠正档案」和「处理待确认建议」两行分别记录，基线期记同样两行。上限是相对的，不高于不用 Agent 时的同类耗时，不设绝对分钟数；上限压单行还是总和，第二轮依据数据决定。
- **场景过期风险**：考研时间为 2027 年 12 月左右，基线期从 2026 年 9 月开始，到考试有一年多，链条晚于考试的风险低但保留。若发生，首轮验证场景改为考后错题复盘或创作场景，四个核心不变。
- **样本来源**：真实导图目前只有三四张，是 FR-7 还原度的主判据；可行性实验用公开导图补足到 20 张，内容丰富、跨多个领域，用于观察识别的泛化程度。公开图片只用于本地实验，不进公开仓库、不写入正式笔记库、不计入 100 条门槛；来源与筛选条件见[样本来源清单](可行性实验样本来源.md)。
- **停止条件**：基线期若现有助手已能满足主要任务，依据真实记录重新评估新增角色设定与持久化档案的必要性，本文可整体搁置，不因已写成而立项。
