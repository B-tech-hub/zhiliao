# 设计补充材料

本文服务于 [PRD](prd.md) 的后续设计交接，记录代码现状与待验证点；未确定接口、存储格式或开发任务，不代表开发授权。

## 知识导图图片场景的现有基础

以下为 2026-09-20 的静态阅读结果，未运行模型、浏览器或搜索验收。

| 现有能力 | 依据与边界 |
|---|---|
| 图片语义转写 | [手写转写实现](../../../../src/lib/ai/handwriting.ts)调用视觉模型生成 Markdown 和告警，提示词覆盖段落、列表、表格和数学公式；未明确要求还原导图节点与连接。不能据此认定导图识别已满足需求。 |
| 保留原图、追加及冲突保护 | [ADR-0017](../../../../docs/adr/0017-handwriting-transcription-and-math.md)要求保留原图、不覆盖既有正文；转写期间正文变化时保存候选稿。新场景设计需沿用这些约束，具体核对流程待定。 |
| 图表显示 | [Mermaid 组件](../../../../src/components/mermaid-code-block.tsx)支持笔记代码块的渲染和源码编辑；用户需要的导图类型、数学表达与编辑体验尚未验证。Mermaid 仅为候选复用方案。 |
| 正文关键词检索 | [搜索实现](../../../../src/lib/search.ts)的 `refreshNoteFts` 对 `note.content` 分词建索引；正常转写追加后调用该函数。被保存在正文中的节点文字具备复用此路径的基础；图片像素本身不会由该索引函数识别。 |
| 语义检索与降级 | 现有搜索支持 BM25 与向量融合，未配置 Embedding 时使用 BM25，见 [ADR-0018](../../../../docs/adr/0018-hybrid-search.md)。导图结构序列化后的召回质量和公式搜索未验证。 |

## 设计时需解决的问题

- 用户已确认直接在导图上修改文字、增删分支，现有 Mermaid 源码编辑不能单独满足该体验。后续需评估笔记内节点操作与现有 Markdown 出口的兼容方式，尚未选定组件或存储格式。
- 用户要求尽量保留原图节点、层级和连接，并先预览、核对或修改后加入笔记。图片公式、模糊区域及允许的识别偏差需要真实样图；不承诺自动还原所有版式。
- 现有转写正常完成时会直接追加正文，新场景则要求先核对后加入。后续需设计明确的预览与提交边界，不能直接复用自动追加行为；是否暂存、取消及失败恢复尚未决定。
- 导图显示、可编辑内容和搜索所用文本如何保持一致，尤其是修改或删除节点后的索引更新；实现方案待定。
- 导图语法或公式无法渲染时，需遵循既有保留源码和显式告警约束，不能静默丢内容。
- 用户已给出自然语言查询“帮我检索有关极限求法的知识”，后续应保留原句验收，不能只用简化关键词代替。该例本身含有知识点名称，不能单凭它断言必须新增向量模型或查询改写。公式匹配、命中节点定位与自动讲解尚未确认。
- 这一任务可以检验图片材料的整理与取用价值，尚不能证明需要长期角色设定或学习档案；后续需分别判断。

## Agent 负责范围

用户已确认自主添加主题或单篇笔记以划定 Agent 负责范围；范围内找不到所需知识时告知用户。没有授权自动跨范围检索、联网或用模型知识冒充笔记中的内容。

负责范围与会话来源集仍是两个概念：来源集属于会话，负责范围属于 Agent。2026-09-21 的多视角讨论确认范围规则尽量复用 [ADR-0010](../../../../docs/adr/0010-grounded-source-chat.md) 的来源集机制，结论已写入 PRD 的 FR-13 与 FR-14；持久化方式、数据表与接口留待架构阶段，本节只记录取舍依据。

### 范围规则的取舍记录（2026-09-21）

| 议题 | 采用 | 弃用与理由 | 现有代码依据 |
|---|---|---|---|
| 主题动态纳入 | 活引用，之后归入主题的笔记自动进入范围 | 快照：需新增成员表，且制造「我加了笔记 Agent 为什么看不见」；ADR-0010 备选四已否决同一方案 | [sources.ts](../../../../src/lib/ai/sources.ts) 按主题 id 现查、按笔记 id 去重 |
| 未分类作为成员 | 禁止 | 未分类是系统主题，后台整理会把笔记搬走，删主题会把笔记搬回，范围随收件箱反复变动 | [CONTEXT.md](../../../../CONTEXT.md) 未分类与删除主题的回落规则 |
| 主题被删除 | 范围中标示已删除并提醒用户 | 静默收缩：删主题后笔记回落未分类，范围一夜清空而用户不知 | `describeSources` 已有 `missing` 标记，显示「（已删除的主题）」 |
| 变更生效与回收站 | 下一条消息生效、不追溯；回收站笔记保留引用不参与，恢复即生效 | 另立口径：与来源集两处不一致需要额外解释 | `sources.ts` 展开时排除回收站但保留引用 |
| 范围重叠 | 允许 | 互斥：需新增唯一约束并在每个读点校验，ADR-0010 记录过 `scope_type` 漏一个分支险些删光全部会话；学习场景本身需要多个 Agent 共享同一批笔记 | 冲突只发生在写操作，由 FR-14 约束 |
| 修改元数据 | 首轮不下发；任何时候不允许改主题 | 开放改主题：Agent 可把范围外笔记改进自己的主题，范围自行扩大，违反 FR-3。开放改标题或标签：改动即置锁，笔记永久退出自动整理，用户不撤销就是永久副作用 | [update-meta.ts](../../../../src/lib/ai/tools/update-meta.ts) 第 15 行注释 |
| 删除笔记 | 首轮不下发，非永久 | 开放：导图入库、检索、讲题均无删除需求；确认卡片防模型乱来，防不了用户误点允许 | 确认卡片不变量照旧存在，不为 Agent 另加机制 |
| 新建笔记落点 | 必须落范围内主题；一个默认、多个询问、无主题不下发 | 落未分类后按 id 钉入范围：零新机制，但未分类已被排除，Agent 看不见自己新建的笔记；未分类满 8 条触发主题建议；用户看到数学讲义躺在收件箱会困惑 | [create-note.ts](../../../../src/lib/ai/tools/create-note.ts) 省略 `topicId` 即进未分类 |

以下两项于 2026-09-21 由产品负责人按建议采纳，候选保留供审阅：

- **单独勾选的笔记在主题变动后的去留：采用「留」。** 按 id 保留，范围页标示「单独勾选，不随主题走」，沿用现有展开逻辑，代价是多一层说明。弃用「走」：被移到范围外主题时随之离开，需在笔记改主题的路径上增加清理范围引用的逻辑；对本来就从范围外主题单独勾选的笔记，这条规则的语义不明确。
- **老师还是图书管理员：采用「老师」。** 模型可用自身知识讲解，范围内笔记用于找例题与类比，找不到时如实告知后仍可讲解；抓取网页首轮不下发，与不联网补题一致。依据是简报中「联系其他常见函数的泰勒展开」「无提示完成同类题」都超出笔记内容。弃用「图书管理员」：等同于来源问答加持久化范围，`GROUNDED_BLOCKED_TOOLS`（[tools/index.ts](../../../../src/lib/ai/tools/index.ts)）可整套复用，但找不到即拒答与学习场景不符。严格接地仍由来源问答提供，Agent 不改变其规则。

范围选择不等于写工具授权，正文不被 AI 覆盖、既有删除确认与来源问答严格接地的约束持续有效。

## 学习档案更新

用户已确认每个 Agent 独立维护学习档案；Agent 先提出更新建议，用户确认后再保存，未确认建议不替换已生效档案。用户可以查看、直接修改或删除单条档案记录。稳定角色设定与动态学习档案仍分别管理，不能把档案更新顺带用于改写角色设定。

2026-09-21 的多视角讨论确定了建议的呈现、暂存、否认与冲突规则，结论已写入 PRD 的 FR-16，取舍依据见下表。触发方式、每轮上限、待确认建议上限和删除已生效记录的语义已于同日由产品负责人按建议采纳，见表后说明。档案中的掌握情况属于可能出错的判断，不作为来源问答中缺失知识的证据；待确认建议越多，错误判断的库存越大，这是设置上限的原因之一。独立档案不能默认为共享用户档案；跨 Agent 转移或复用尚未确认。

### 建议生命周期的取舍记录（2026-09-21）

| 议题 | 采用 | 弃用与理由 | 现有代码依据 |
|---|---|---|---|
| 建议的呈现与持久化 | Agent 在会话中以工具调用发起建议，前端渲染为操作卡片，沿用确认与撤销；卡片随消息持久化，重开会话重建 | 沿用主题建议的「单批待处理、新批作废旧批」：用户没看的建议会被下一批静默顶掉，与用户掌控不符 | [ADR-0008](../../../../docs/adr/0008-assistant-tool-calling.md) 操作卡片；[schema.ts](../../../../src/db/schema.ts) `messages.toolPayload` 重开会话重建卡片；[suggest-topics.ts](../../../../src/lib/ai/suggest-topics.ts) 第 131 行作废旧批的先例 |
| 待确认建议在哪里看 | 卡片加 Agent 档案页托盘；托盘是该 Agent 全部未处理建议卡的汇总视图 | 只有卡片：往下聊几十条后卡片滚出屏幕，等于丢了建议 | 托盘按建议卡状态查询，不需要新表 |
| 「对话结束时集中提」 | 不采用 | `conversations` 只有 `createdAt`/`updatedAt`，没有会话结束信号，关闭标签页服务端不知道，没有触发点 | [schema.ts](../../../../src/db/schema.ts) `conversations` 表 |
| 拒绝后不再提 | 拒绝写入一条「否认」档案记录，可见可删；保存时校验拒绝重复判断（硬约束），Agent 读档案时避免重提（软约束）；删除否认记录即允许再提 | 独立黑名单或「永久 / 有条件」开关：仓库没有逐条禁止的先例，主题建议 dismissed 只改状态，纠正即学习只能整体清空 | `topic_suggestions.status`；[ADR-0021](../../../../docs/adr/0021-correction-learning.md) |
| 手工更正与待确认建议撞车 | 确认时对比目标记录快照，被改则失效并标示原因，被删则作废；改动时不扫描，不自动重生成 | 以手工版本重新生成：每次改动触发一次模型调用，与 ADR-0012 记录的付费死循环同类。改动时弹冲突框：多一个打断 | [use-chat.ts](../../../../src/components/chat/use-chat.ts) 撤销的 409 口径；[ADR-0017](../../../../docs/adr/0017-handwriting-transcription-and-math.md) 转写不覆盖用户改动；[ADR-0012](../../../../docs/adr/0012-weekly-review.md) |
| 每轮建议上限 | 工具层限次，超出返回拒绝 | 不限次：模型一轮内可多次调用 | 数值见下方采纳项 |

以下三项于 2026-09-21 由产品负责人按建议采纳，候选保留供审阅：

- **触发方式与每轮上限：采用「Agent 主动提出，完成当次帮助后再提，每条回复最多 1 条」。** 弃用「仅应用户要求时提」：把维护工作推回用户，档案会长期空置，与维护省心相反。弃用「对话停顿处集中提」：没有可用的停顿信号。1 条的理由是每张卡都要用户做一个决定，多于 1 条一轮回复就成了表单。「答完后再提」是对模型的提示约束，工具层只能限次，不能判断讲解是否完成。
- **待确认建议上限：采用「每个 Agent 最多 10 条，满则工具拒绝新建议、托盘提示处理」。** 上限同时充当总闸，Agent 无法堆积；10 是没有数据依据的判断值，验证后可调。弃用按时间自动过期：用户没看的建议被时间静默作废，与「新批作废旧批」是同一个问题。
- **删除已生效记录的语义：采用「删除即忘掉」。** Agent 之后可基于新观察再次提出；否认记录只由拒绝建议卡产生；删除时不额外询问。若用户想让某条已生效判断不再出现，删掉后等它再被提出时拒绝一次即可。弃用删除时询问「忘掉还是否认」：多一个弹窗。弃用删除即否认：用户无法让 Agent 重新学习，除非再删否认记录，两步且反直觉。

设计阶段仍需解决：「同一判断」在保存校验时如何匹配（精确键还是语义相近）尚未定义；否认记录与普通档案记录在档案页的区分方式待交互设计。

## 角色设定与学习档案的数据出口

2026-09-21 产品负责人对 Q-6 四问的回答已写入 PRD 的 FR-17 与 FR-18。以下记录先例与设计时需要处理的差异。

| 议题 | 决定 | 现有先例 | 设计时的差异 |
|---|---|---|---|
| 导出 | 首轮不进 Markdown 目录与 ZIP，随整库备份走 | [ADR-0020](../../../../docs/adr/0020-incremental-markdown-export.md) 增量导出与「导出全部数据」只含笔记与图片；对话、设置、纠正样例同样只在整库备份中 | 无新出口；日后若要人能读的副本另行评估 |

| 单独恢复某个 Agent | 需要，不改动其他数据 | 整库备份保留 7 份、恢复是整库覆盖（[备份与恢复](../../../../docs/备份与恢复.md)）；[ADR-0024](../../../../docs/adr/0024-markdown-zip-import.md) ZIP 导入是唯一按 id 挑数据的路径，只吃笔记 | 首轮无单独导出，来源只能是备份快照；仓库没有从快照中挑出部分数据的先例，属新能力，成本待架构评估 |
| 继承 | 新建时可复制已有 Agent 的角色设定或学习档案，之后各自独立；范围不继承 | 无直接先例 | 复制时否认记录一并带走；与问答引导的组合待交互设计 |

用户对「删除 Agent」以一句「30 天可恢复」作答，本文按整体理解：角色设定、学习档案、负责范围引用与会话历史一并进回收站、一并恢复，未逐项区分。

## 验证方案的取舍记录（2026-09-21）

产品负责人采纳多视角讨论的结论，已写入 PRD「验证方案」小节。取舍如下：

| 议题 | 采用 | 弃用与理由 |
|---|---|---|
| 基线 | 从现在起用现有产品学数学、记两行耗时，与攒 100 条真实笔记同期 | 直接为 SM-3 定上限：简报第 24 行明确用户尚未使用知了，没有基线的上限没有参照物 |
| 可行性实验 | 开发前用现有手写转写路径裸跑全部真实导图，目标 20 张 | 等开发后再验识别：FR-7 是唯一能在不写代码时证伪的假设，晚验等于把最贵的风险放在最后 |
| 样本范围 | 只验数学；小说场景推迟 | 两场景同验：创作场景没有完成标准，验收结果无法解释 |
| 分工核心 | 首轮如实写明验不到 | 用一个 Agent 宣称验证了「按领域分工」 |
| 阈值 | 越界 0 为唯一硬指标，其余第一轮记录、第二轮设 | 第一轮全部定量：没有基线的数字是编的 |
| SM-6 更新时限 | 不设 | 定时限：关键词索引在保存路径同步刷新，向量路径尚未设计，时限等于承诺未设计的机制 |
| 维护成本 | 记两行，上限相对基线 | 绝对分钟数：无参照物。合并为一行：分不清是调设定贵还是审托盘贵，分开记的成本为零 |
| 处理托盘的归类 | 记录但单列，是否受上限约束第二轮定 | 立即定性为负担（用得越多越失败）或定性为非负担（时间确实花掉了）均未被采纳 |
| 场景过期 | 写入风险，届时改验考后错题复盘或创作场景 | 忽略考试日期：验证链条可能晚于考试而无人察觉 |

可行性实验会把导图图片发送给视觉模型，执行前须按既有约束另行批准预算与发送范围；本文只记录计划。用户真实导图只有三四张，补充样本的来源、筛选条件和使用约束见[样本来源清单](可行性实验样本来源.md)。公开图片来自知乎、CSDN 与模板社区，授权未标明，只能用于本地实验；软件直出的清晰图比用户拍摄条件宽松，清单要求至少三分之一做成拍照或压缩版本。

## 产品边界与启动条件

目前将“知识导图”理解为用户希望存放在笔记内的内容表示，已确认直接编辑文字和分支，入口与异常交互仍待设计。README 禁止建设知识图谱或白板；本场景不据此授权新增跨笔记关系系统、独立画布或一级导航。如后续交互需要扩大范围，应先记录差异并由用户决定。

手写摄取和 Mermaid 当前均默认关闭，见 [ADR-0025](../../../../docs/adr/0025-non-core-features-off-by-default.md)；规划不改变默认开关。新功能冻结规则继续有效，交给其他 Agent 时仍须明确具体范围与开发批准，不以本稿代替启动条件。首轮功能组合、第二轮项、开发启动条件与 Sprint 归属见 PRD 的「首轮范围与非目标」和「交接与启动条件」，本文不重复。
