# 产品简报补充材料

本文件保留用户在原头脑风暴中贡献的场景与配套候选，供后续 PRD 或设计参考。除明确标为已确认的方向外，均不代表范围批准；本轮不改变现有产品行为。

## 已有场景与细节

### 学习：以泰勒展开题为例

- 老师先了解学生已有的前置知识和本次要完成的目标，指导要明确、简单、能执行，步骤不繁琐也不过度跳跃。
- 用户可能偏好一步步被引导，也可能希望直接得到答案；应符合个人习惯，不把一种教法强加给所有人。
- 讲解当前题目时，可联系其他常见函数的泰勒展开，并从用户笔记中找同类例题作类比。
- 用户已提出的掌握标准是：在没有提示的情况下，按指定标准（例如考研标准）完整做出类似例题，并解释完整思路。具体题目和评分标准尚未给出。
- 用户说太难、不想学了时，应遵循当下停止指令；提高兴趣和完成目标不能成为强行继续的理由。
- 用户提出笔记没有例题时可联网补两道题。这是尚未解决模式归属与联网方式的候选，不属于现有严格来源问答能力。
- 学生卡住可能源于意图未被理解，也可能是前置知识缺口；原讨论没有验证哪一种更常见。

### 创作：人物与剧情素材取用

- 用户准备写一本小书，知识库中已积累许多人物形象和剧情构思，希望直接检索出来用于创作。
- Agent 应具备对应领域的专业能力，并理解用户的创作习惯与笔吻。
- 建议由用户请求触发；用户无需单独描述检索动作，不等于 Agent 可以擅自发起创作。
- “素材被采用”“保持用户笔吻”等仅可作为待讨论的成功信号，原讨论未确定创作验收标准。

## 已认可的维护方向

稳定角色设定保存性格、教学或表达方式与职责边界；动态学习档案保存知识基础和学习偏好。后者按任务需要取用，同一事项合并重复、更新过时判断，不把全部对话持续追加到角色提示词中。

用户已认可这种分离方向。涉及角色设定的长期改变，先给出具体方案供用户选择或调整；档案何时更新、误判后如何纠正仍待决定。将学习档案推广成覆盖创作习惯的通用用户档案，是后续需要确认的概念，不在本轮静默改名或扩大范围。

## 配套候选，保留但未纳入核心

| 候选 | 原始动机与未决部分 |
|---|---|
| 问答式创建 | 类似“制造老师”的 skill，通过引导问题形成角色提示词，降低 AI 知识和提示词编写门槛；问题与创建流程未设计。 |
| 先使用默认助手 | 适合暂时说不清理想角色的人，通过几次真实任务了解自己喜欢的帮助方式；属于可选路径。 |
| 手动知识关联 | 用户主动关联两条笔记或知识点，Agent 在相关提问中带出关联内容；不等同于批准知识图谱、白板或新增关联结构。 |
| 知识框架来源 | 可来自笔记归纳、用户脑中的方法、笔记中的方法或网上教学方法；具体形态、选择与可信度尚未确定。 |
| 联网补题 | 知识库缺少例题时补充练习；是否需要、怎样获取、怎样区分外部材料与来源内容均待验证。 |

| [ADR-0021](../../../../docs/adr/0021-correction-learning.md)：手工修正元数据形成有限 few-shot 样例 | 这不等于已经具备学习档案、知识水平判断或角色长期记忆。 |

“管理负责范围内的笔记”属于已确认的领域分工方向；首轮具体需要哪些管理动作仍待真实任务明确，不能默认为所有写工具自动开放。角色的创建、切换和范围呈现方式也未确认。

## 后续验证建议

先用现有知了完成真实学习或创作任务，保留任务目标、相关笔记、回答、追问原因和主观评价。由用户指定任务成功标准，区分专业错误、材料不足与风格不适合。记录重复交代背景和维护所花时间，避免仅凭“像一个老师”认定有价值。

以上是待确认的验证设计，不代表已经开展实验。若现有助手已能满足主要任务，应据真实证据重新评估新增配置与持久化状态的必要性。当前未核验真实笔记数量，继续执行冻结约束；达到 100 条后重新评估、排序并取得具体开发批准。

真实笔记以用户真实撰写、捕获或个人历史资料导入的有效笔记为依据。Demo、测试与临时验收语料不能证明达到解冻门槛；仓库已有 130 篇隔离测试语料的验收结果，也不等于 100 条真实笔记。
