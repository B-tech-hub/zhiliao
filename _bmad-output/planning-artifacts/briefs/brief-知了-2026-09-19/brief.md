# 知了自定义知识库 Agent

> 冻结期产品提案，仅用于规划与价值验证设计，不代表开发授权或发布承诺。

## 产品主张

让个人知识库的主人长期拥有专业且合拍、按领域分工、维护省心，并由自己掌控的 Agent，把过去的笔记积累用到当下的学习与创作中。

这是知了单用户、自托管 Web/PWA 的候选能力。自定义提示词是手段，持续获得适合自己的帮助才是价值。本轮明确方向与验证问题；当前交付仍以开源安装、核心“记、找、用”和数据出口为先。

## 用户、问题与证据

目标用户是希望按自身基础和习惯取用个人笔记的人。已提出考研数学学习、小说素材取用两个场景，首轮优先场景待确认。

用户期待减少重复解释背景、调整回答方式与维护提示词的负担。学习者需要讲清问题、衔接步骤并检验理解；创作者需要找到已有的人物与剧情素材，服务当下创作。

**证据边界：**用户在原讨论中明确尚未使用知了，回答偏好不能作为知了缺陷。舒适感、效率与兴趣提升，以及提示词能否支撑专业能力，均未验证；目前没有真实使用基线。

## 四个已确认的核心

| 核心 | 用户应获得的体验 |
|---|---|
| 专业且合拍 | 先理解用户已有基础和本次目标，以用户喜欢的性格、教法或表达方式提供具体帮助；专业质量需通过真实任务检验。 |
| 按领域分工 | 不同 Agent 各有职责，熟悉并帮助管理、取用负责范围内的笔记。职责如何绑定笔记、跨领域任务如何处理，仍待设计。 |
| 维护省心 | 稳定的角色设定与持续更新的学习档案分开；档案按需取用，同一事项合并、更新，避免把所有对话堆进提示词。 |
| 用户掌控 | 由用户提出需求后行动，用户决定停止；长期改变角色设定先提出具体方案，由用户选择或确认。 |

“稳定设定与动态档案分离”已获用户认可，档案更新权与误判纠正方式尚未确定。

## 候选体验与范围

用户提出任务，选用相应领域的 Agent；Agent 了解目标与背景、取用相关笔记，再给出适合用户的帮助。用户可调整方式、结束任务。能否跨会话保持认识并减少维护，是关键验证点。

首轮价值验证覆盖四个核心；主场景、职责边界与档案更新原则明确后，再收敛候选范围。本简报不锁定页面、数据表或排期。

问答式创建、先体验默认助手、手动知识关联与联网补题保留为配套候选。自带 API Key、检索与来源问答属于现有基础。详见[补充材料](addendum.md)。

## 不变量与主要风险

- 保持单用户、自托管、主题导向及现有数据出口，不建设多用户、SaaS、工作流画布、知识图谱或白板。
- AI 不覆盖用户正文；自定义设定不放宽工具与来源边界。来源问答限定来源集，资料不足时拒答；联网补题仍为候选。
- 领域职责不等于会话来源集，也未确认角色间自动协作。档案如何更新、更正、删除需另行设计，既有写操作确认规则保持。

主要风险：风格变化未带来专业质量提升、错误判断知识基础、分工造成漏检、维护负担抵消收益。

## 成功信号与推进条件

以下为验证设计建议，尚未执行，也不是已确认的量化门槛：

| 核心 | 后续可观察的信号 |
|---|---|
| 专业且合拍 | 学习场景中，用户按指定标准、无提示完成同类题并解释完整思路；同时记录用户为何觉得教法合适。创作场景另定评价标准。 |
| 按领域分工 | 真实任务能找到并用上预先确认相关的笔记；记录漏检、误用与越界，引用可回到真实材料。 |
| 维护省心 | 连续任务中记录重复交代背景、修改设定和纠正档案的次数与耗时，与使用现有助手的基线比较。 |
| 用户掌控 | 对明确的停止请求及时停止；角色长期调整经用户选择；档案误判能够按后续确定的规则纠正。 |

先用现有产品积累真实任务与基线。样本、周期、维护成本上限及达标阈值待定，本轮不执行试验。真实笔记达到 100 条前不开发本提案；达到后重新评估、排序，不自动立项。
