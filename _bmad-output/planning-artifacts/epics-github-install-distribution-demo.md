> 说明：当前未发现独立 RV findings 文件；本文件采用上述依据中可核对的缺口，不把未核实的外部环境信息写成事实。

2026-09-13：用户已批准[开源发布优先范围调整](sprint-change-proposal-2026-09-12-open-source-first.md)。当前按 [R0–R4 执行清单](../../docs/产品规划/开源发布范围与执行清单-2026-09-13.md) 收口安装、核心闭环、出口恢复、版本与免费反馈；公网 Demo 后移。本文同步交付依赖，不改变任何 Story/Sprint 完成状态。下文商业手册仅作后续实验基线，当前不按其招募或报价。

## Epic 1: GitHub 安装与首次使用教学

目标：让新用户从 GitHub 仓库或 v0.6.0 固定版本开始，在不依赖维护者口头说明的情况下完成安装、登录和第一条笔记闭环。

范围：README 双语入口、Docker 与源码安装路径、首次使用步骤、环境变量说明、常见故障和证据记录。

非目标：不新增安装器、不改变运行时架构、不承诺 serverless 部署。

### Story 1.1: 固化受支持的 GitHub 安装路径

关联：RV 文档可执行性缺口；Issue #6 已发布的 v0.6.0 基线。

交付：

- 选择并标注主路径（Docker 预构建镜像）与备用路径（源码安装）。
- 写清 Node.js、Docker、持久化目录、`APP_PASSWORD`、`SESSION_SECRET` 和端口前置条件。
- 所有命令固定到 v0.6.0 或明确的提交/tag，避免使用未验证的 `latest`。
- 记录 Windows Docker Desktop 的卷挂载例外和 Tailscale HTTPS 前置条件。

验收：新用户无需猜测变量名、端口或数据目录；README 中英文的主路径语义一致。

依赖：无。外部决策：维护者确认默认推荐路径和发布版本。

### Story 1.2: 完成全新环境安装冒烟与证据留存

关联：Issue #6 发布验收；`pilot-runbook.md` 的“已核实运行平台”约束。

交付：

- 在隔离目录按主路径执行安装、启动、登录和重启。
- 验证 SQLite、上传目录、Markdown 增量导出和健康检查落在预期位置。
- 记录操作系统、Docker/Node 版本、镜像 tag、端口、耗时和失败恢复步骤。
- 不使用正式数据、正式卷、正式环境文件或真实 API Key。

验收：全新环境可重复启动；重启后数据仍在；证据可链接到文档或开发日志。

依赖：Story 1.1。外部动作：无，使用隔离本地环境。

### Story 1.3: 编写首次使用与故障排查教程

关联：Issue #4/#5 的使用入口；`pilot-runbook.md` 的真实设备与验收边界。

交付：

- 给出“登录 → 新建普通文本笔记 → 等待 AI 整理 → 打开主题 → 搜索”的最短路径。
- 补充 AI 未配置、任务等待、端口冲突、权限错误、HTTPS 不受信任和蜂窝网络不可达的处理。
- 明确 Demo、正式实例、测试实例的数据隔离与密码/密钥禁忌。
- 链接手机快捷记录、备份恢复和文档索引，不把本地未发布能力写成承诺。

验收：首次用户只阅读该教程即可完成主流程；每个故障项都有可执行的下一步或明确停止条件。

依赖：Story 1.2；手机入口的完整验收仍由 Issue #4 的连续 7 日真实使用负责。

## Epic 2: 公网 Demo 安全化

目标：在公开访问前，把现有 Demo 从“播种数据和提示密码”提升为服务端强制的受限演示环境。

范围：服务端权限边界、独立部署拓扑、资源与请求限制、重置、健康检查和运维文档。

非目标：不把 Demo 变成通用多用户服务，不允许访问正式数据或真实外部模型。

### Story 2.1: 建立服务端 Demo 能力边界

关联：Issue #5；RV 对 `DEMO_MODE` 只做播种和密码提示的安全发现。

交付：

- Demo 永远使用容器内 mock LLM，拒绝保存或清除外部模型配置。
- 禁止创建或吊销外部 API Token、备份下载、数据导入、向量补算和高成本设置操作。
- 被禁止的 Route Handler/API 直接返回明确 `403`，前端隐藏只作为辅助。
- 保留新建普通文本笔记、AI 自动归档和主题建议采纳主路径。
- 增加 demo 模式测试，覆盖允许路径、禁止路径和未登录路径。

验收：直接请求被禁止 API 仍返回 `403`；访客无法获得写入/读取正式知识库的 Token；允许路径完整可用。

依赖：Story 1.1；需要维护者确认 Demo 保留的最小演示能力。

### Story 2.2: 隔离 Demo 部署并限制资源

关联：Issue #5；Issue 计划中的共享基础设施决策。

交付：

- 保留独立 compose project、卷、网络和环境文件；v0.6.0 为历史发布基线，公网使用另行发布、包含 Story 2.1/2.2 补丁的新固定版本和 digest。
- Demo 不挂载正式目录，不读取正式 `.env`，不与正式服务共享卷或网络。
- 反向代理仅转发 Demo；设置请求体、CPU、内存、磁盘和日志轮转上限。
- Demo 容器禁止访问云元数据地址和内网网段；可行时设置必要依赖的出站白名单。

验收：隔离检查能证明正式数据、正式卷、正式密钥不可达；资源限制和上传保护可被实际触发并记录。

依赖：Story 2.1。外部决策：服务器、域名、DNS、HTTPS、费用和是否共机由维护者确认。

### Story 2.3: 建立重置、健康检查与故障恢复手册

关联：Issue #5；`pilot-runbook.md` 的数据出口、备份和停止规则。

交付：

- 提供自动定时重置和人工重置命令，重置后重新播种固定数据。
- 重置后自动执行健康检查和三步主路径冒烟。
- 记录容器重启、磁盘、可用性、证书到期和重置失败等最小监控项。
- 新增公网 Demo 部署与运维文档，说明恢复失败时停止公开访问的步骤。

验收：自动与人工重置均可恢复标准数据；健康检查失败不会静默继续对外服务；文档可由维护者独立执行。

依赖：Story 2.2 全部原验收与审查通过；本机成果归档不解除依赖。公网后移期间保留自动/人工重置、故障停止服务与恢复验收要求。

## Epic 3: 可复现的“AI 不编造”演示

目标：以固定来源集和固定问题展示严格接地回答与无来源时的拒答，不用误导性剪辑替代产品证据。

范围：首期交付固定版本的演示数据、问题文本、完整对照输出、本地复现、GIF/短视频和 README 双语安装承接；公网重置一致性在 #5/Epic 2 公网上线时补验，由 Story 3.3 留存关联证据，不删除该待办。

非目标：不声称通用模型在所有问题上都不会编造，不使用真实个人笔记、Token 或 API Key。

### Story 3.1: 固化演示数据与对照问题

关联：Issue #8；Issue 计划中的可复现性要求。

交付：

- 固定演示数据版本、来源笔记列表、问题文本、对照模型名称和日期。
- 用文本搜索和人工核对证明对照问题不在来源笔记中。
- 记录“知了严格拒答”和对照助手回答的完整原始结果，不剪掉不利结果。
- 复用已有导入或播种路径，将固定数据、问题文本和复现步骤放入可审计位置；每次在隔离本地实例恢复同一版本数据。
- mock 只证明流程；真实模型使用已确认的发送范围和预算，记录完整输出及失败样本，不放开公共 Demo 的模型或上传权限。

验收：任何维护者按同一版本数据都能复现演示；问题、来源和结论之间的关系可追溯。

依赖：Story 1.2、Story 1.3 与明确的应用/数据版本。首期本地复现不依赖 Story 2.3；公网上线仍须在 2.3 后验证重置恢复同一套数据。

### Story 3.2: 产出 20～30 秒演示素材并同步 README

关联：Issue #8；`docs/演示GIF录制清单.md`。

交付：

- 按“来源集选择 → 同一问题对照 → 明确拒答 → 展示来源集 → 固定 Release 与本地复现入口”的顺序录制。
- 生成体积可控的 GIF 或短视频、静态封面和准确替代文本。
- README.md、README.en.md 和演示录制清单同步入口与复现说明。
- 素材不包含真实个人资料、Token、API Key、内网地址或未发布能力。

验收：静音播放 20～30 秒内能理解差异；README 常见宽度下文字可读；素材与所引用的已发布应用和固定数据版本一致。

依赖：Story 3.1；外部发布链接须人工确认。

### Story 3.3: 完成演示复现与失效处理

关联：Issue #8；Issue #10 冻结闸门。

交付：

- 首期在隔离本地实例恢复固定数据后连续两次复现，记录应用、数据和模型版本。
- 后续 #5/Epic 2 公网上线前补真实入口及自动/人工重置后的数据与结论联验，仍在本 Story 留存关联证据；未执行项不记通过。
- 素材失效时标记并停止分发旧链接。
- 将演示失败归因到数据、版本、模型或部署环境，不用重新剪辑掩盖失败。

验收：连续两次复现得到同一产品结论；失败有停止和修复记录；不会把一次演示当作真实笔记增长证据。

依赖：Story 3.2。

## Epic 4: ADR 文档分发与效果观测

目标：将可验证的架构决策和失败复盘发布到 GitHub/社区，并保留可比较的流量与转化证据。

范围：首篇 ADR 文章、双语发布材料、渠道承接、Traffic 快照和 30 天复盘。

非目标：不在 Epic 2 验收完成前发布公网 Demo 链接，不把流量或 Star 当作产品成功证明。文章可指向已核实的固定 Release、安装和恢复文档；包含演示时须有对应复现证据。

### Story 4.1: 撰写并校验首篇 ADR 文章

关联：Issue #9；Issue 计划建议的“配置静默覆盖导致模型未生效”主题。

交付：

- 以决策、证据、错误判断、修复和自我推翻为主线，不写泛化成功故事。
- 每个关键结论链接到 ADR、开发日志、提交或测试证据。
- 区分当时已知、事后发现和仍未知；同步中文正文与英文摘要。
- 文章不包含真实密钥、用户数据或未经验证的性能/商业结论。

验收：文章可由读者沿链接复核；正文与当前代码、ADR、Release 版本一致。

依赖：Epic 1 Story 1.2；可引用 Epic 3 但不阻塞本地文档审校。

### Story 4.2: 准备渠道发布包与 README 承接

关联：Issue #9；Issue #8 的 README 承接要求。

交付：

- 准备 GitHub Release/Discussion、中文社区和 Hacker News 的不同开头与摘要。
- 各渠道指向固定版本、安装/恢复文档和免费反馈入口；引用演示时附对应素材与复现步骤，公网 Demo 链接只在原上线条件全部满足后加入。
- 发布前人工检查链接、密码提示、版本号、素材替代文本和隐私脱敏。

验收：每个渠道都有明确入口和承接动作；未完成 Demo 安全化时不发布公网 Demo 链接。

依赖：Story 4.1、已发布固定版本及安装/恢复文档；引用演示时追加 Story 3.2、Story 3.3，引用公网 Demo 时追加完整 Epic 2 验收。只发布文章和安装入口无需等待视频或公网。外部动作：发布、发帖和公开评论必须人工确认。

### Story 4.3: 建立 Traffic 快照与 30 天复盘

关联：Issue #9；Issue #10 指标闸门。

交付：

- 发布前保存 Star、Watcher、Issue、Views、Unique visitors、Clones、Referrers 基线。
- 以实际对外发布时间为 T0，在 24 小时、7 天、14 天、30 天按固定字段保存 Markdown 或 CSV 快照；草稿完成不启动时钟。
- 记录仓库访问、可取得的 README 点击、实际安装尝试、免费反馈和失败，不只保存截图；未取得的数据写未知，公网未启动期间 Demo 使用写未启用。
- 30 天后按“无曝光、无转化、安装/README 承接失败、产品未形成使用意愿”分类复盘；公网上线后再纳入 Demo 承接，不因后移而填零或判失败。

验收：所有时间点都有可比较快照；复盘能给出继续、调整或停止的明确动作，不提前恢复冻结中的新功能。

依赖：Story 4.2；外部数据由维护者人工采集。
