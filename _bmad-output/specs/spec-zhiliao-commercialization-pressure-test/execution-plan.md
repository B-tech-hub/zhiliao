# 首轮执行安排与决策规则

> 适用范围更新（2026-09-13）：[开源发布优先提案](../../planning-artifacts/sprint-change-proposal-2026-09-12-open-source-first.md)已获批准，当前按[执行清单与免费反馈](../../../docs/产品规划/开源发布范围与执行清单-2026-09-13.md)推进。本文保留为后续商业实验基线，暂缓新增收费招募、报价、收款准备与预付；原价格、样本、交付、资金、成本和停止规则不变，已有成本与存量承诺不抹去。免费试用不自动计为商业访谈或付款交付，不启动商业 D1。

对应 CAP-1～CAP-7。负责人角色为维护者，姓名和日期在启动前填写；当前仅完成文档准备，不代表实验已启动。实际执行沿用 [Issue 计划](../../../docs/Issue执行计划-2026-08-29.md)，不改变其发布、外向操作和重验证门禁。

历史准备入口为 [首单执行入口](../../../docs/产品规划/首单执行入口-2026-09-12.md)：2026-09-12 确认的客户自有设备路线继续保留，渠道、邀请、筛选和报价草稿供后续商业重启使用。当前不按其新增招募或报价；真实服务结果和 D1 仍待记录，未因本次免费方案自动生效。

商业重启后再按 [详细执行手册](pilot-runbook.md) 核对首周日程、访谈、条款和交付步骤。本文保留完整的启动与决策规则；当前免费观察采用独立记录代号，共用费用只计一次，不删除原准备成本。

## 1. 启动前待办

| 事项 | 责任人 | 完成凭证 | 未完成时 |
|---|---|---|---|
| 每周投入与内部时薪 | 维护者 | 已确认 15 小时/周、¥15/小时，先试行再复盘 | 已落实；实际工作仍需记工时 |
| 诊断时长、抵扣、支持窗口与上限 | 维护者 | A-5 为预算建议，服务说明和报价表仍需填妥 | 不开放付费接单 |
| 收款主体、平台、发票/税务、取消退款规则 | 维护者 | 逐情形退款表、方式和期限 | 不收款 |
| 资料访问、保存/删除与退出规则 | 维护者与客户 | 每单授权与期限 | 不获取资料或操作客户环境 |
| D1、D90、报价有效期、5 个名额及报名截止日 | 维护者 | 台账首行、报价版本 | 不开始带截止承诺的招募 |
| A-1～A-6 操作化口径、预算与执行建议 | 维护者 | 启动前确认日期；对客建议采纳后填写本单条款 | 保持假设，不宣称商业门槛已通过 |
| 至少 10 名候选及可承接平台/规模 | 维护者 | 私有候选表、只读盘点方式 | 先筛选，不承诺通用迁移 |

维护者可先使用 [招募提纲](interview-guide.md) 和 [实验台账](experiment-ledger.md) 做自愿免费访谈与非敏感信息筛选。收费前填妥 [服务说明](service-offer.md) 与 [订单模板](order-template.md) 的对应条款；资料查看、客户环境操作和 [交付](delivery-checklist.md) 分别满足授权、备份及验收条件。材料中的建议不自动成为收费承诺。本次任务没有授权代理对外发送、开通收款、部署服务或接触客户数据。

### 每周 15 小时的分配建议

| 用途 | 小时/周 | 计时边界 |
|---|---:|---|
| 候选筛选与访谈 | 3 | 记录近期阻塞与价格反馈；订单只读盘点归入下行 |
| 服务准备、诊断、盘点、交付、支持与返工 | 8 | 包含本轮专用彩排、新旧订单、验收、交接及诊断结论，不重复计时 |
| 通用材料与周复盘 | 2 | 更新共用文档、计算成本与渠道；订单专属记录归入上一行 |
| 缓冲 | 2 | 为意外情况保留，不提前售卖；未使用不记实际成本 |
| 合计 | 15 | 用户已确认的周总投入上限 |

分配为 A-5 的试行建议。起步每周先 1 个套餐；评估新增订单前，先扣除当周已有交付、诊断和支持预留。不能把 5 个首轮名额理解为一周同时接 5 单。¥99/¥299/¥699 对应 1/4/8 小时的总预算建议及费用情景见 [实验台账](experiment-ledger.md)，必须先盘点能否达到四项验收。

每周复盘实际耗时与有效时薪；后续提高投入、时薪或价格时另记生效版本，原轮次与已成交承诺保留。支持时段、收款退款及启动日期仍待填，不因工时参数确定而自动开始收费。

## 2. 90 天安排

D1 为启动条件满足后的实际开始日，不自动使用文档日期。每周复盘；报名截止日须在首轮报价前固定，并给交付和 7 日观察留出时间。详细手册的首周不自动等于 D1～D7，准备阶段已有的有效访谈、服务付款、工时和费用仍纳入首轮累计及停止判断，不能重新起算补数。

| 窗口 | 主要动作 | 阶段交付与判断 |
|---|---|---|
| D1～D7（第 1 周） | 填完条款、建立私有台账与至少 10 人名单，准备手机记录与恢复演练材料；核查赞助平台可用性 | 服务可被清楚解释、报价可核算、数据与退款规则可执行 |
| D8～D21（第 2～3 周） | 累计至少 10 次有效访谈，逐步达到 15～20 次；最多 3 个免费或低价陪跑估工时，符合条件可直接进入有边界付费诊断/报价 | 形成 3 个完整案例及报价反馈；免费案例仅作交付学习，不能替代付款 |
| D22～D35（第 4～5 周） | 按既有 #5/#8/#9 准备安全 demo、来源拒答演示和真实故障文章；服务、赞助与数据出口入口待材料及安全检查完成后再发布 | 本地 demo 可按既有方式 5 分钟体验；公网未安全化前不提供公开链接、不阻塞一对一访谈 |
| D36～D56（第 6～8 周） | 开放本轮累计 5 个套餐名额，盘点后报价、核实实付，按清单交付；先前套餐占同一批名额 | 截止时至少 3 名套餐实付；完成交付另算，不能用预付意向补足 |
| D57～D84（第 9～12 周） | 完成验收与跟进、成本/支持核算；确认重复获客；沉淀清单与现有能力的运维文档 | 套餐实付且交付至少 3 人；至少 2 人有 7 日记录或恢复证据；不自动进入托管试点 |
| D85～D90（收尾） | 补齐 12 周之外的 6 天，核对未完成订单、退款、支持剩余承诺与所有门槛 | 形成继续/调整/停止结论和凭证索引；证据不足不宣称成功 |

免费陪跑也必须有访问授权、范围与成本记录。任何阶段触发硬停止都提前执行，不必等 D90。报价可以提前，但不能另起一批名额逃避首轮门槛。

## 3. 继续条件

以下条件同时满足才可继续当前服务；通过不是新功能授权：

| 条件 | 证据与口径 |
|---|---|
| 15～20 次有效访谈 | 同一人去重；具体事件、环境与数据盘点信息、报价反应齐全 |
| 至少 3 名实际付款并完成交付 | 暂按 A-1 统计套餐客户；诊断单列，付款和验收均有证据 |
| 其中至少 2 名完成 7 日真实记录或恢复验收 | 记录与恢复分别统计，按人取并集；恢复不替代 #4 行为验收 |
| 交付及支持成本占净服务收入 ≤50% | 工时换算成人民币，包含本人、返工和支持，保留失败/免费成本；收入剔除未结算预收；支持未结束时，成本加剩余承诺预算也须 ≤50%，预算未知不判通过 |
| 无数据事故 | 实际恢复、客户确认、临时数据退出和事故/投诉记录可查；“未报告”不等于已核实 |
| 至少一个可重复获客来源 | 暂按 A-3：同一可再次使用渠道在不同时间带来至少 2 名独立付款并交付客户 |

付款且交付未达 3 人，即使收到很多诊断费也不能通过；恢复客户足够而 7 日记录不足时，只能报告恢复价值证据，不能扩展为已证实长期使用。

## 4. 硬停止与处理

| 触发条件 | 判定时点 | 动作 |
|---|---|---|
| 20 次有效访谈无实际服务付款 | 第 20 次访谈完成后的核对；D/P 实付都记录，意向不算 | 停止当前服务验证，复盘客户与付费结果 |
| 5 个套餐名额不足 3 个付款 | 预先固定的报名截止日 | 停止该轮套餐试销；不追加名额、赠送或延长期限补数 |
| 成本持续超过收入 50% | 暂按 A-2：同一 SKU 连续两次周复盘超标；D90 仍超标也不继续 | 停止该 SKU 接新单；未触发硬停止前可调整未来报价/范围，不能减少已售承诺 |
| 支持边界无法一页写清 | 发出报价前或出现边界失控时 | 停止该 SKU，不以“后续再说”接单 |
| 数据泄露或实际恢复验收失败 | 发现即触发 | 立即停止受影响操作和接单，保护源数据、通知当事客户、处理恢复/退款；共性风险未排除时停止整轮 |
| 第三方依赖导致无法履约 | 确认无法履行已售范围时 | 停止相关 SKU，按已约定规则通知、退款或退出，不承诺临时开发替代平台 |

停止不等于放弃存量客户：清点未完成承诺、履行退款/退出、归还资料、撤销临时权限并记录损失。后续重启必须重新写出条件与报价，保留原失败结论，不用新增功能把失败包装成“继续开发”。

证据不足而未触发硬停止时，D90 可判“调整/暂缓新增承诺”，列出缺口与下一轮验证；不能判“继续已验证业务”。

## 5. 其他收入模型的保留边界

| 模型 | 保留价格锚点 | 可做什么 / 门槛 | 本轮排除 |
|---|---|---|---|
| 社区赞助 | ¥5/¥20/¥50 月度档 | 核查 GitHub Sponsors 或替代平台可用性，公开用途与月报；连续 2 个月无新增支持且无反馈可停止该赞助推广方式 | 不算稳定营收或服务付款；不绑定额外无限支持 |
| 年度维护 | ¥399～¥999/年 | 5 个服务客户中至少 2 个有实际重复购买证据后，才测试；一页写清响应时段、包含工时、额外费率、排除项和退出规则 | 续费/复购意向不足以启动，不默认承诺 SLA |
| 托管实例/远程备份 | ¥29～¥99/月 | 只做候补或有明确可退款条款的预付；至少 10 名候补且至少 3 名实际可退款预付只触发另行评估 | 不开发基础设施，不开展人工托管试点，不保证上线日期 |
| AI/Embedding 网关 | ¥9～¥29/月额度包 | 只记录需求、成本担忧、BYOK 偏好和可退款预付；先明确原文“三倍变量成本”的比较对象 | 不建网关、代管 Key、销售已可用额度或提供无限量调用 |
| 模板/集成市场/Pro 便利 | 待定 | 记录来自真实服务的重复需求；100 条真实笔记后重新评估 | 不锁核心数据能力，不靠竞品清单立项 |

可退款预付还需单独约定金额、收款主体、无上线承诺、退出方式和最迟退款日期；任何一项未定只收候补信息。预付只证明愿意暂付，不证明交付、复购或托管毛利。隐私/数据位置、备份、SLA 与变量成本未评估前不承接托管责任。

## 6. 与当前路线的衔接

- **#4 手机捕获：** 复用既有接口与指南，在真实手机完成链路和连续 7 天使用；已存在自动化验证不代替真机证据。
- **#5 公网 demo：** mock AI、独立数据卷、禁止真实配置与高成本操作、服务端限制、可重置与资源边界验收后才上线。现有本地 demo 不能直接当公网沙箱。
- **#8 来源拒答：** 固定数据、来源集、问题、模型和日期，展示可复核的拒答与引用，不宣称泛化正确率、不拼接误导性对照。
- **#9 ADR 内容分发：** 以真实故障和恢复证据写作，公开入口就绪后发布；按现有计划在发布前、24 小时、第 7、14、30 天人工留存快照，不等 Traffic 过期后补取。首篇发布 30 天后若 Star 仍低于 20 且 Issue 为 0，停止同形式批量发文并复盘承接环节；这与服务付费门槛分别判断。
- **#10 冻结：** 真实笔记单独统计，不用测试、自动周报或客户库汇总冲线；新功能只入候选列表。

公开资金用途限缺陷、文档、发布与基础设施等已声明范围。技术文章、入口和赞助页面本轮仅提供执行要求，不标为已发布；发布前按既有项目规则完成相应检查。

## 7. 原规划冲突裁决

| 原口径 | 本轮采用的口径与原因 |
|---|---|
| 会 Docker、重视隐私即可作为首发画像 | 收窄到近期真实阻塞及可盘点环境，避免偏好替代需求 |
| “30 分钟跑起来”与 ¥99 安装诊断的模糊结果 | 去掉无条件时长保证，¥99 只售限时诊断，套餐盘点后报价 |
| 默认可从 Obsidian/Memos/flomo 完整迁移 | 以现有 Markdown 能力及附件对账为界，专有适配不假装已完成 |
| 3 个付费客户或 3 个预付意向 | 改为至少 3 名实际付款并完成交付，其他证据分账 |
| 复购意向即可年度支持、候补后人工托管/BYOK 小测试 | 年度需实际复购与完整边界；托管/网关仍只候补或可退预付，不启动平台 |
| “支持工时超过收入 50%” | 先以内部时薪换算成本，再计算成本/净服务收入，避免量纲错误 |
| 仅第 9～12 周结束即称 90 天 | 增加 D85～D90 结算，不提前忽略支持、退款与观察 |

研究中的 Joplin/Obsidian/SiYuan 等只支持“免费核心、服务与便利可另行收费”的待验假设；Memos 的赞助路线不能证明稳定营收，AppFlowy/AFFiNE/Outline 等也不构成复制团队复杂度的理由。2026-09-08 的价格、Stars 与搜索摘要是历史背景，未在本轮重新核验，不作为真实付款或市场份额证据。原规划的竞品与搜索记录保留供追溯。
