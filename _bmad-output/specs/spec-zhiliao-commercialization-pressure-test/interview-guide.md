# 首轮招募与访谈提纲

对应 CAP-1、CAP-2。目标为 15～20 次有效访谈；免费咨询、泛泛赞同或看过 demo 不自动构成有效样本。

首次执行可直接使用 [详细手册](pilot-runbook.md) 中的候选查找方法、首次邀请/跟进文案和 30 分钟访谈时间表。免费访谈不以收款条款已定为前提；资料查看和具体收费分别等待相应条件确认。

## 招募文案底稿

> 最近在个人自托管笔记时，是否遇到安装卡住、资料搬不进来、备份不会恢复，或者手机记录不顺的问题？我在验证知了的人工部署、迁移和恢复服务，希望了解一次具体经历。访谈先了解你的问题，不需要提供密码、API Key 或完整笔记。若现有能力适合，会在只读盘点后给出明确报价；访谈本身不承诺免费代装或免费修复。联系：[维护者渠道]。

由维护者选择渠道并自行发布；本材料不代表已发出招募。候选名单先录入至少 10 人，按同一口径筛选。

## 筛选与有效样本

| 核查项 | 必须取得的信息 | 不满足时 |
|---|---|---|
| 个人自托管 | 中文沟通、本人使用、能控制或取得运行设备的授权 | 企业/团队/教育机构不接首轮 |
| 近期具体阻塞 | 发生日期、做了什么、卡在哪里、尚有何影响；优先仍未解决或反复出现的问题 | 仅设想需求进入候补，不计有效访谈 |
| 环境可盘点 | 系统、Docker/主机状态、网络与手机平台；愿意配合只读核查 | 信息未补齐标“待核实”，不报价 |
| 数据可盘点 | 来源工具、导出格式、笔记/附件数量或可统计方式；无存量资料也明确记录为 0 | 不要求先交出完整数据；无法确认范围时不报套餐价 |
| 结果明确 | 愿意讨论解决什么结果、已有替代及成本、对明确报价的反应 | 只讨论新按钮不算本轮服务需求 |

同一人多次访谈只计一个有效样本。客户即使最终拒绝付费，只要信息齐全仍是有效访谈；不得从分母中删除不愿付的人。“近期”保留实际日期和当前影响，不擅自宣称来源已规定某个天数窗口。

## 访谈顺序

1. 最近一次卡住是什么时候？当时准备完成什么，停在哪一步？
2. 已试过哪些方法，花了多少时间或钱？现在是否仍受影响？
3. 设备、系统、Docker、手机、网络和数据格式分别是什么？能否先做只读盘点？
4. 哪个可观察结果会让你觉得问题解决：实例能打开、数据对得上、手机能记，还是备份能恢复？
5. 不使用知了或不购买服务时，你会怎么做？免费文档、其他工具或朋友帮助是否已足够？
6. 数据或 Key 不能交给别人时，可否由你共享屏幕并自行输入？哪些数据可以用于模型测试？
7. 告知 ¥99 限时诊断的结果与时限；套餐只说明 ¥299～¥699 测试区间，盘点完成后再给确价。这个具体结果值得你付款吗，阻碍是什么？
8. 若愿意继续，约定下一次盘点及报价时间；若不愿意，原样记录理由，不转成“以后可能会付”。

先听事件再展示产品。受访者提出新功能时记录其背后的阻塞；本轮不承诺实现。只在条款齐全后发出付款请求，不用口头“愿意”填入实付栏。

## 追问拒绝与跟进

- 价格问题：拒绝的是 ¥99 诊断、套餐总价，还是愿意自行解决？记录具体服务与金额。
- 信任问题：顾虑在远程访问、资料处理、恢复证据还是维护者资质？不靠绝对安全承诺消除顾虑。
- 能力问题：当前格式、平台或依赖不支持，记录缺口并拒绝超范围接单。
- 不紧急或无需服务：如实计入无付款结果，不追加免费服务换取好评。

完成第 20 次有效访谈仍无实际服务付款时，按 [执行安排](execution-plan.md) 停止；不得把诊断意向、赞助或候补预付填成服务付款。
